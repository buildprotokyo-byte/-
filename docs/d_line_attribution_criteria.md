# 64周目の基準: **見積の行から「何が効いたか」を辿れるようにする**

**測る前にコミットする。結果を見てから基準は変えない。**

## 0. **仮の判断(原文を確認できていない)**

おーちゃんの優先順 1 は「**何が効いたかを行ごとに記録する仕組み**」である。
**その元になった指示の原文がこのスレッドの文脈に無い**ため、コーディネータに
原文を依頼したうえで、**5 分待って返事が無かったので推奨で進める**
(ループの決まり)。**これは仮の判断である。原文が届いたら突き合わせて直す。**

**推奨した読み方**:

> 見積の行 1 行を見ただけで、**その行を作ったのは何か**が分かること。
> すなわち **どの規則が当たったか・その数量を出したのはどの手法とどの軸か・
> 仲裁層の階層と処置は何だったか**を、行そのものが持っていること。

**そう読んだ理由**: いまその情報は**木の形でしか無い**
(`MappingResult` → `QuantityMapping.quantity` → `RuleOutcome.rule_id` → `MappedLine`)。
**行だけを取り出す経路**(`settled_lines()`、`MappedLine.as_dict()`)を通ると、
**規則も手法も軸も落ちる。**報告や見積に出るのはその形である。

## 1. 測るもの

合成の案件で行を作り、**行だけを取り出したときに何が辿れるか**を数える。

| 記号 | 何を数えるか | いま |
|---|---|---|
| M1 | `as_dict()` に**規則**が入っている行の割合 | **0**(欄が無い) |
| M2 | `as_dict()` に**手法**が入っている行の割合 | **0** |
| M3 | `as_dict()` に**軸**が入っている行の割合 | **0** |
| M4 | `as_dict()` に**階層と処置**が入っている行の割合 | **0** |

**この周で変えるのは 1 つだけ**(行に「何が効いたか」を持たせること)。
金額・規則の中身・判定のしかたには触らない。

## 2. 対照(これが通らなければ結論を出さない)

**C1: 欄を足したあと、`basis` の内訳が足す前と 1 件も変わらないこと。**
(`MappingResult.basis_counts_text()` の数が完全に一致する)
**辿れる欄を足すだけで、行の基づきが動いたら、それは別の変更が混ざっている。**

**C2: わざと欄を空にしたら M1〜M4 が 0 に戻ること。**
戻らなければ、**数え方が中身を見ていない**ということなので結論を出さない。

## 3. 判定の分岐(先に決める)

- **M1〜M4 がすべて 1.0 かつ C1・C2 通過**
  → **入れる。**判定のしかたを変えないので、全件テストと CI が通ればマージ可。
- **どれかが 1.0 未満**
  → **辿れない行が残る。**どの行がなぜ辿れないかを名指しし、入れる前に直す。
- **C1 が通らない**
  → **入れない。**基づきが動くのは、この周でやると言っていない変更である。

## 4. この測定で分からないこと

- **行が正しいかどうかは測らない。**辿れるかどうかだけである。
- **人が読んで分かるかは測らない。**欄があることと、伝わることは別である。
- 合成の案件だけで測る(取り決め④)。実案件での測定は Codex-A が行う。
