### **いちばん大きい発見: 国交省の官庁営繕の基準が、丸ごと読める**

`www.mlit.go.jp/gobuild/` に**技術基準と積算基準の PDF が並んでいる。**
1 つ落として確かめたところ、**文字が取り出せる**(`建築工事標準詳細図(1)`、7.4MB、
文字あり)。読めるものの例:

- **建築工事標準詳細図(1)〜(6)** … **「こう納める」の絵と寸法。**記号と納まりの出典になる
- **建築設計基準 / 建築構造設計基準 / 構内舗装・排水設計基準**(それぞれ資料編つき)
- **建築工事設計図書作成基準 / 建築設備工事設計図書作成基準** … **「図面をこう書く」の本文**
- **公共建築工事積算基準 / 公共建築工事標準単価積算基準 / 公共建築工事共通費積算基準**
- **公共建築工事内訳書標準書式**
- 新営一般庁舎面積算定基準、官庁施設の基本的性能基準 ほか

**「図面に現れない行 8 行が公開の積算基準に載っているか」(K-17 2 番)は、
この環境から自分で調べられる。**調査担当に回す前提だったが、出典が手元にある。

### 読めないものと、その意味

**JIS の本文は読めない。**`jisc.go.jp` にも日本規格協会にも届かない。
**建築基準法・消防法の本文も読めない**(e-Gov に届かない)。

**つまり「出典を 3 つ変える」を JIS と法令でやることはできない。**
変えられるのは **①国交省の官庁営繕の基準 ②手元の `docs/drafting_rules_reference.md`
(おーちゃんが送った製図の決まりの原文) ③モデルが前提として持っている知識**の 3 つである。
**この 3 つ目は出典ではない**(どこに書いてあるか指せない)ので、
**使ったら必ず「出典を指せない」と記録する。**

## 3. この棚卸しから、ループの設計に返すこと

1. **周2(10〜20 の知識を当てる)の「知識」は、出典のある 2 つと、出典を指せないものに
   分かれる。**混ぜて数えると、20 個当てたつもりで実は「同じ 1 つのモデルの中の
   言い換え」を 20 回数えることになる。**独立性の軸(大元のデータ源)は、ここにも効く。**
2. **OCR はまだ 1 つも入っていない。**2 件目の案件(図面の文字が画像)には OCR が要るので、
   **入れるなら `rapidocr-onnxruntime`(onnxruntime だけで動く)から試すのが軽い。**
3. **周1(まとまりで読む)に新しい導入は要らない。**`get_texttrace` と `get_drawings` と
   `shapely` だけで組める。**まず手元の道具で測る。**
