# 読み方の比較実験 — 採点の基準

> **この文書は実行の前に固定する。実行結果を見てから直さない。**
> 採点で迷いが出たら、迷った内容と、そのとき採った扱いを報告に残す。
> **基準そのものを書き換えて辻褄を合わせない。**

出力の形は [output_format.md](./output_format.md)。上位の決まりは
[開発全体の最上位の原則](../../principles/start_kit.md) と
[作業の取り決め](../../coordination/README.md)。

## 1. 採点する人が見てよいもの・いけないもの

見てよい: 採点する出力（`P-1`…, `Q-1`… の JSON）、正解データ、入力パッケージ。

**採点する人には、どちらが A でどちらが B かを渡さない。** `P` と `Q` としてのみ
扱う。読み方の作戦、実験の仮説、他の条件の結果も渡さない。

**実行する人には、正解データ・見積・他方の条件を渡さない。**
正解データには「どのページを見ればよいか」「手がかりになる語」まで
入っているので、渡すと実験が成立しない。

## 2. 手順の順序を固定する（ここが一番大事）

**この順にしか進めない。前の段に戻らない。**

1. **対応づけ**（3 節）。出力の行と正解の行を結びつける。
   **この段では数量を見ない。**
2. **数量の判定**（4 節）。1 の結果を動かさない。
3. **区分の判定**（5 節）。
4. **根拠の検証**（6 節）。出力が示したページと位置に、本当にその記載があるか。

数量を見てから対応づけを変えると、**数量が合う相手を探す採点**になってしまい、
どの条件でも点が上がる。**2 の結果が悪いことを理由に 1 をやり直さない。**

## 3. 対応づけ

正解の行と出力の行を、**「同じ工事が、同じ場所について書かれているか」**だけで
結びつける。

- **名前の一致は求めない。** 図面の言葉と見積の言葉は違う。言い換え・略語・
  表記ゆれは同じものとして扱ってよい。ただし**同じとみなした根拠を1行残す**
  （どの語とどの語を同じとみなしたか）。残した対応表は報告に付ける。
- **1 対 1 でのみ数える。**
- 出力の 1 行が正解の複数行をまとめている場合（例: 全室のクロス張替えを 1 行で
  書いた）は、**「まとめ行」として別に数え、言い当てた行数には入れない。**
  一覧には残す。1 行で複数の点を取れる数え方にしないため。
- 出力の複数行が正解の 1 行に当たる場合は、**そのうち 1 行だけを当たりとし、
  残りを「細かく割れた行」として別に数える。**正解に無い項目には数えない。
- どの正解行にも当たらない出力行は「正解に無い項目」（7 節）。
- どの出力行にも当たらない正解行は「落とした行」。

対応づけは **P と Q で同じ人が、同じ日に、同じ手順で**行う。
片方だけ後日やり直さない。

## 4. 数量の判定

正解の `unit` で、判定のしかたを分ける。**出力の単位が違っていても、
正解の単位に換算できるなら換算して判定する**（換算したことを記録する）。

| 正解の単位 | 判定 |
|---|---|
| 個数（箇所・枚・組・台・本 など、数えられるもの） | **±1 以内なら許容差内** |
| 連続量（㎡・m・m³・kg など） | **±5% 以内なら許容差内** |
| `式` / `一式` | **数量の判定をしない。別に数える。**（数量 1 に意味が無いため） |

**図面から数量が決まらない行（7-5）も、数量の判定からは外す。**
工事を言い当てたかどうかは別に数える（7-1）。

- 出力の数量が `null` の行は「数量を出さなかった行」として別に数える。
  **許容差から外れた行には入れない。**出さなかったことと間違えたことは別である。
- 正解の単位と出力の単位が換算できない組み合わせのときは「単位が合わない行」
  として別に数える。

## 5. 区分の判定

- 正解データが持つ**大分類**（`major_category`）だけで判定する。
  **中分類（`middle_category`）は正解データに値が入っていないので使わない。**
- 出力の `区分` が空の行は「区分を出さなかった行」として別に数える。
  間違いには数えない。
- 言い換えは 3 節と同じ扱い。同じとみなした根拠を残す。

## 6. 根拠の検証

出力が書いた `ページ` と `位置` を、入力パッケージで実際に引く。

- そのページのその近く（**位置から 40pt 以内**）に、`読んだ文字` と同じ文字が
  あれば **根拠あり**。
- 表から読んだと書いてある場合は、その表のその行にあれば **根拠あり**。
- 無ければ **根拠なし**。
- **18〜21 ページを根拠にしている行は、必ず「根拠なし」**（この 4 ページには
  文字データが無く、何も読めないため）。

## 7. 指標

すべて**件数と分母を両方書く**。割合だけを書かない。

### 7-0. この実験で「精度」と呼ぶもの

**この実験が測りたいのは、最初に工事内容の理解（目的の理解）があると
推論の精度が上がるか、である。**速さ・読んだ量・推論の回数は**補助**であって、
中心ではない。報告では、精度の指標を先に置き、補助の指標を後に置く。

**精度は 1 つの数字にならない。**次の 3 つを**必ず組にして**読む。

| 精度の面 | 指標 | 一言で |
|---|---|---|
| 取りこぼし | 7-1 の言い当てた行数（3 つの分母すべて） | 正解にあるものを、どれだけ見つけたか |
| 出しすぎ | 7-2 の正解に無い項目（根拠あり／根拠なし） | 正解に無いものを、どれだけ出したか |
| 値の近さ | 7-1 の数量が許容差内の行数 と 7-8 の誤差の大きさ | 見つけたものの数量が、どれだけ合っているか |

**「言い当てた割合が高い方が精度が高い」と書いてはいけない。**
片方が全部の条件をとにかく並べれば、言い当ては上がり、出しすぎも上がる。
**取りこぼしと出しすぎは必ず並べて書く。**あわせて、出力の行数そのもの
（`工事項目` の総数）も毎回書く。分母の違う指標を足し引きして 1 つの点数にしない。

**根拠なしの項目は、出しすぎの中でも重い。**図面に根拠があって正解に無いものは
正解の側が落としている可能性があるが、根拠が無いものは読み方の側の作り話である。
**この 2 つを混ぜて「余計な項目」と 1 つにまとめない。**

### 7-1. 言い当てたもの

**分母は 2 つある。取り違えないこと。**

- **工事の言い当ての分母＝正解の全行**（図面から数量が決まらない行も入れる）
- **数量の一致の分母＝数量を判定できた行だけ**（図面から決まらない行は外す）

**工事があること自体は、数量が図面から決まらなくても見つけられる**（仮設・諸経費・
人が決める分は、図面の工事の内容から「要るはずだ」と辿り着ける）。
そこは読み方の差が出るところなので、分母から外すと差が消えてしまう。
一方で、数量の当たり外れは図面から数量が決まる行でしか測れない。

| 指標 | 分子 | 分母 |
|---|---|---|
| 言い当てた行数 | 対応づいた正解の行数 | **正解の全行**（`standard_rule` / `operator_input` の行も含む） |
| 言い当てた行数（図面から決まる行だけ） | 同上のうち、図面から決まる行 | 図面から決まる行（7-5 で外した行を除いた数） |
| 言い当てた行数（図面から決まらない行だけ） | 同上のうち、図面から決まらない行 | 図面から決まらない行の数 |
| 言い当てた金額 | 対応づいた正解の行の `reference_mdt_budget` の合計 | 正解の全行の合計。**金額は正解の側にだけあり、出力には書かせない。**行の重みとして使うだけである |
| 数量が許容差内の行数 | 許容差内の行数 | **数量を判定できた行数**（図面から決まらない行・`式`・`null`・単位不一致を除いた数）。除いた数も内訳ごとに併記する |
| 区分の正答数 | 大分類が合った行数 | 対応づいた行数 |

**上 3 行は必ず 3 つとも出す。**1 つにまとめない。

### 7-2. 余計に出したもの

| 指標 | 定義 |
|---|---|
| 正解に無い項目（図面に根拠あり） | 6 節で根拠ありだった行の数 |
| 正解に無い項目（根拠なし） | 6 節で根拠なしだった行の数 |

**根拠なしの項目は、1 件ずつ全件を一覧にして報告する。**割合だけにしない。
図面に根拠があるのに正解に無いものは、**正解の側が落としている可能性**があるので、
「間違い」と決めつけずにそのまま並べる。

### 7-2-2. 出した行数そのもの

| 指標 | 定義 |
|---|---|
| 出した行数 | `工事項目` の総数 |
| 数量を入れた行数 / 数量を空にした行数 | `数量` が `null` でない行 / `null` の行 |

**7-1 と 7-2 を読むときに、必ずこの数を横に置く。**
出した行数が違えば、言い当ても出しすぎも一緒に動く。

### 7-3. 波及

| 指標 | 定義 |
|---|---|
| 波及で出た項目の数 | `出どころ` が `波及から出た` の行数 |
| そのうち正解にあった数 | 上のうち対応づいた行数 |

### 7-4. 手間

| 指標 | 定義 |
|---|---|
| 所要時間 | 出力の `所要時間_秒` |
| 読んだページ数 | 出力の `読んだページ` の個数 |
| 読んだ文字量 | 出力の `読んだ文字量` |
| 推論の数 / 計算の数 | 出力の値をそのまま |

これらは**自己申告である**ことを、報告に必ず書く。

### 7-5. 図面から決まらない行（別集計）

正解の `expected_source_type` が `standard_rule` または `operator_input` の行は、
**図面だけからは数量が決まらない。**扱いを 2 つに分ける。

- **工事の言い当て（7-1 の上 3 行）: 分母に入れる。** 図面から数量が決まらなくても、
  工事があること自体は見つけられる。**そこは読み方の差が出るところなので外さない。**
  そのうえで、図面から決まる行・決まらない行に分けた数字も別に出す。
- **数量の一致（4 節・7-1 の数量の行）: 分母から外す。** 数量が図面から決まらない行で
  数量の当たり外れを測っても、読み方の差にはならない。

外した行数と、そのうち言い当てた行数は、**必ず両方書く。**

## 7-6. 架空の案件を採点するとき（金額が無いので行数で）

架空の案件の正解ファイルには**金額の欄が無い。**そのため、

- **「言い当てた金額」は出さない。**無い数字を作らない。
- **行数だけで採点する**（7-1 の上 3 行と、数量・区分）。分母の決め方は
  7-1・7-5 と同じで、変えない。
- 正解の欄の名前が P011 と違う。読み替えは次のとおり。

| P011 の正解 | 架空の案件の正解 |
|---|---|
| `expected_source_type` が `standard_rule` / `operator_input` | `数量の出どころ` が `standard_rule` / `operator_input` |
| `major_category` | `区分` |
| `unit` / `quantity` | `単位` / `数量` |
| （相当するものが無い） | `工事上の区分`（既存のまま／撤去／新設／改修）|

- `単位` が空の行は、**最初から数量が出せない行**として正解の側が作っている。
  数量の判定からは外し、外した件数を書く（7-1 の数量の行と同じ扱い）。
- `工事上の区分`（既存のまま／撤去／新設／改修）は、**区分とは別に**
  合っていた件数を数える。分母は対応づいた行数。

### 7-7. 仕掛けと食い違いを 1 件ずつ採点する

正解ファイルには、作った側が**わざと入れた**ものが 2 つのリストで残っている。

| リスト | 欄 | 何を見るか |
|---|---|---|
| `意図的に入れた仕掛け` | `番号` `種類` `内容` `関係する工事項目の番号` | その仕掛けに**気づけたか** |
| `意図的な食い違い` | `番号` `場所` `片方` `もう片方` `どちらが正しいか` | その食い違いを**食い違いとして挙げたか** |

**1 件ずつ、次の 3 つのどれかを付ける。割合にまとめる前に、必ず一覧で出す。**

| 判定 | 条件 |
|---|---|
| **気づいた** | 仕掛けなら、`関係する工事項目の番号` に対応づく行を出しているか、`要確認` にその内容を挙げている。食い違いなら、`要確認` にその場所の食い違いを挙げている |
| **気づかなかった** | 出力のどこにも出てこない |
| **取り違えた** | 触れてはいるが、**食い違いを食い違いと扱っていない**（片方を選んで確定した）、または仕掛けを別のものとして扱っている |

- **食い違いで「どちらが正しいか」を当てたかは、別の欄に書くが、点にはしない。**
  決まりは「食い違いはどちらも選ばない」なので、当てにいくこと自体が決まりに反する。
  当てていた場合は「決まりから外れた」として記録する。
- **仕掛けの `種類` ごとに分けて集計する。**種類によって読み方の得意不得意が
  出るなら、そこがいちばん見たいところである。
- `関係する工事項目の番号` が空の仕掛け（案件全体の性質を指すもの）は、
  **対応づけでは採点せず、`要確認` に挙げられたかだけで見る。**

### 7-8. 数量の誤差の大きさ（許容差の内か外かだけにしない）

許容差の内か外かだけだと、**惜しかったのか、桁が違ったのかが消える。**
対応づいて数量を判定できた行について、**相対誤差**を出す。

    相対誤差 = |出力の数量 - 正解の数量| / |正解の数量|

- 行ごとの相対誤差を全部並べ、**中央値と最大値**を書く。平均だけにしない。
- **0.05 以内 / 0.05〜0.25 / 0.25〜1.0 / 1.0 超** の 4 つに分けて件数を書く。
- 正解の数量が 0 の行は割り算ができないので、**この指標から外し、外した数を書く。**
- 個数の行（許容差 ±1）も同じ式で出すが、**個数と連続量は分けて並べる。**

**この指標は許容差の判定を置き換えない。**7-1 の「許容差内の行数」はそのまま出す。
誤差の大きさは、その内訳を見るために足すものである。

## 8. 報告のしかた

1. 指標ごとに、**P と Q の各回の値・平均・最小・最大**を並べる。
2. **差が偶然かどうかを断定しない。**「有意」「効果があった」と書かない。
   書いてよいのは、**差の大きさ**（どれだけ違うか）と**一貫性**
   （3 回とも同じ向きか、向きが揃わないか）だけである。
   3 回は、偶然かどうかを言うには少なすぎる。
3. **案件ごとに分けて示す。**とくに次の 2 つは、まとめずに別に出す。
   - 要約資料（工事概要書・仕様書・仕上表）が**無い**案件
   - 要約資料と図面が**食い違う**案件
4. 根拠なしの項目は全件の一覧を付ける（7-2）。
   架空の案件では、仕掛けと食い違いの 1 件ずつの判定も全件の一覧で付ける（7-7）。
   軸ごとの比較の表は [comparison_axes.md](./comparison_axes.md) の形で作る。
5. 採点で迷った件を一覧にする。どう扱ったかも書く。

## 9. やってはいけないこと

- 結果を見てからこの文書を直すこと
- 数量が合う相手を探して対応づけを変えること
- 片方の条件だけ対応づけをやり直すこと
- 3 回の結果から「効果がある」と結論づけること
- 割合だけを書いて件数を書かないこと
- 工事の言い当てと数量の一致で、同じ分母を使うこと（7-1）
- 架空の案件で、金額が無いのに金額の指標を作ること（7-6）
- 仕掛けと食い違いを、1 件ずつ出さずに割合だけにすること（7-7）
- うまくいかなかった結果を書かないこと
- **言い当てた割合だけを見て「精度が高い」と書くこと**（7-0）
- **取りこぼしと出しすぎを、出した行数を横に置かずに比べること**（7-0、7-2-2）
- **図面に根拠がある余計な項目と、根拠なしの項目を 1 つにまとめること**（7-0）
- **速さや読んだ量の差を、精度の話として書くこと**（7-0。これらは補助である）
