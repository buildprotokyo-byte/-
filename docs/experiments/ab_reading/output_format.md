# 読み方の比較実験 — 出力の形

> この文書は**実行の前に固定する**ためのものである。
> **実行結果を見てから直さない。** 直す必要が出たときは、直した理由と
> 直した時刻を残し、直す前に出た結果は別の実験として扱う。

上位の決まりは [開発全体の最上位の原則](../../principles/start_kit.md) と
[作業の取り決め](../../coordination/README.md)。採点のしかたは
[scoring_rules.md](./scoring_rules.md)。

## 1. この実験が測るもの

同じ材料を、2 通りの読み方で読んだときに、**出てくる工事項目と数量が
どれだけ変わるか**を測る。読み取りの腕（文字が読めるかどうか）は測らない。
**図面の文字・数字・表はすべて読み取れているものとして、入力パッケージの形で
渡す。**

読み方の作戦は実行するスレッドごとに指示する。**この文書は作戦を書かない。**
作戦以外のすべて（出力の形、守る決まり、記録する数字）は、どの条件でも同じである。

## 2. どの条件にも共通で課す決まり（3 つ）

**この 3 つは読み方の作戦ではない。どの条件でも必ず守る。**
ここを条件ごとに変えると、測っているものが読み方の差ではなくなる。

1. **根拠の位置を必ず記録する。** 1 つの工事項目につき、どのページの
   どこを見てそう言えるのかを、ページ番号と位置（と、読んだ文字そのもの）で書く。
   **根拠が 1 つも書けない項目は出さない。**
2. **見つからないものを埋めない。** 数量が図面から出せないときは、
   数量を空にして「要確認」に入れる。一般的な値・よくある値・標準の値で
   埋めない。項目名が思い当たっても、図面に根拠が無ければ出さない。
3. **食い違いは要確認にする。** 同じ場所について違うことが書かれていたら、
   どちらかを選ばない。両方を根拠として書き、「要確認」に入れる。

## 3. 出力の形

JSON ファイル 1 つ。文字コードは UTF-8。ファイル名は `<実行ID>.json`。

```json
{
  "実行ID": "P-1",
  "使ったモデル": "（get_session で確認した値をそのまま）",
  "入力パッケージ": "ab_reading_input_P011",
  "開始時刻": "2026-09-22T10:00:00Z",
  "終了時刻": "2026-09-22T10:41:00Z",
  "作業記録": {
    "所要時間_秒": 2460,
    "読んだページ": [1, 2, 3, 7, 8],
    "読んだ文字量": 48210,
    "推論の数": 63,
    "計算の数": 25
  },
  "工事項目": [
    {
      "番号": 1,
      "工事項目": "ビニルクロス張替え",
      "区分": "内装仕上工事",
      "場所": "玄関ホール",
      "数量": 12.4,
      "単位": "㎡",
      "根拠": [
        {"ページ": 3, "位置": [34, 120], "表": "表1 の 4行目",
         "読んだ文字": "玄関／壁／既存／ビニルクロスＣ"}
      ],
      "確かさ": "たぶん",
      "出どころ": "直接読んだ",
      "波及の道筋": null,
      "備考": ""
    }
  ],
  "要確認": [
    {
      "番号": 1,
      "内容": "玄関ホールの壁面積が図面から出せない",
      "なぜ": "数量が出せない",
      "関係する根拠": [{"ページ": 3, "位置": [34, 120]}]
    }
  ]
}
```

### 3-1. 各欄の決まり

| 欄 | 決まり |
|---|---|
| `工事項目` | 何をする工事かを書く。**図面の言葉をそのまま使ってよい。**言い換えても採点では拾う |
| `区分` | 工事の大分類（例: 解体・撤去工事、木工・大工工事、電気設備工事）。**分からなければ空にする。**当て推量で入れない |
| `場所` | 室名・部位。図面に書かれている呼び名をそのまま使う |
| `数量` | 数。**出せないときは `null`。0 で埋めない。**範囲でしか言えないときは `null` にして要確認に書く |
| `単位` | 図面・仕様書に書かれている単位。**単位が書かれていないときは `null`**（勝手に mm や m と決めない） |
| `根拠` | 1 つ以上。`ページ` は入力パッケージのページ番号、`位置` は `[x, y]`（左上原点・ポイント）。表から読んだときは `表` に「表n の m行目」を書く。`読んだ文字` は**印字されたまま**（寄せない） |
| `確かさ` | `確か` / `たぶん` / `分からない` のどれか |
| `出どころ` | `直接読んだ`（図面にその工事が書いてある） / `波及から出た`（書かれていないが、他の工事から必要になると考えた） |
| `波及の道筋` | `出どころ` が `波及から出た` のときだけ、**どの根拠からどう辿ったか**を1〜2文で書く。空にしない |
| `備考` | 任意 |

### 3-2. 「要確認」に入れるもの

- 数量が図面から出せない
- 単位が書かれていない
- 同じ場所について違うことが書かれている（食い違い）
- 仕様書・仕上表には書いてあるが、図面で見つからない
- 図面で見つかるが、仕様書・仕上表に無い
- そのほか、人に聞かないと決められないこと

`なぜ` は上のどれかを短く書く。**「要確認」に入れたものも、工事項目として
出せるなら出す**（数量を `null` にして出す）。要確認に入れたことを理由に
項目ごと落とさない。

### 3-3. 作業記録の数え方（条件によって数え方を変えない）

| 欄 | 数え方 |
|---|---|
| `所要時間_秒` | 最初に入力パッケージを開いた時刻から、出力を書き終えた時刻まで |
| `読んだページ` | **中身を読んだページの番号**。目次で名前だけ見たページは入れない |
| `読んだ文字量` | 読んだページの `page_NN.md` の文字数の合計（一部だけ読んだ場合も、そのページ全体の文字数で数える） |
| `推論の数` | 「A だから B」と考えた回数。1 つの工事項目を出すのに 3 段考えたら 3 |
| `計算の数` | 足し算・掛け算など、数を作った回数 |

推論と計算の数は自己申告である。**正確さより、条件をまたいで同じ数え方を
することのほうが大事**なので、上の定義から外れない。

## 4. 出力しないもの

- **金額を書かない。**単価も合計も書かない。この実験は金額を当てる実験ではない。
- **見積の行の名前に寄せない。**図面の言葉のまま書く。
- 条件の名前（A・B）を書かない。採点は `P` / `Q` の名前で行う。
