## 1. なぜパソコン側で動かすか

2026-09-23 の汚染の調査(`/mnt/project-files/reports/K-03_回答.md`)で分かったこと:

- プロジェクトのスレッドには、**記憶の索引(MEMORY.md)が全文、毎回自動で入る。**
  スレッドごとに切れない。封印フォルダを消しても、この経路は残る。
- 索引とは別に、**指示文に合わせて記憶が自動で選ばれて渡る。**
  読み方の比較実験では、条件が違うと渡る記憶も 1 件違っていた(`../ab_reading/memory_asymmetry.md`)。
- 共有フォルダのファイル名の一覧も自動で入る(封印フォルダの名前が見える)。

**パソコン側の空のフォルダで動かせば、3 つとも入らない。**封印フォルダ
(`/mnt/project-files/.sealed/` の 3 つ)は消さず、触らずに済む(K-03 の 38 番)。

## 2. 用意するもの(始める日に、おーちゃんがパソコンに写す)

条件ごとに**新しい空のフォルダ**を作り、次の 3 つだけを入れる。

| 入れるもの | 元の置き場 | 注意 |
|---|---|---|
| 入力パッケージ | `/mnt/project-files/.sealed/ab_reading_input_P011/`(README.md・index.md・page_01〜34.md・package.json) | 読み方の比較と**同じもの**。実図面から作ったデータなので**リポジトリには入れない** |
| 出力の形 | `docs/experiments/ab_reading/output_format.md` | 読み方の比較と同じ |

**入れてはいけないもの**: このリポジトリの写し、正解ファイル、採点の決まり、
ほかの回の答案、この文書、`design.md`。

## 3. 条件ごとの指示文(伏せ名で渡す)

共通の本文は、**読み方の比較で採点した B の回に渡した指示文**を土台にする
(「当面は B を既定にする」が続いているため。R を B と同じ順番にそろえる)。
**変えるのは順番を書いた段落だけ。**各条件の段落の中身は `design.md` 2 節の表のとおり:

- **R**: 既定の順番(段階 0 → 10)
- **S**: 見積の行の型を先に置いてから読む
- **T**: 差分(工事内容)を先に確定させ、その後に数量を出す
- **U**: 検査を各段階に埋め込む

**書き上げた 4 本の指示文は、始める前におーちゃんに見せる。**
(読み方の比較の指示文そのものは封印フォルダの中にあり、この準備では開いていない。)

## 4. 回し方

1. 1 条件 3 回、計 12 回。**回ごとに新しい空のフォルダ・新しい会話**で動かす。
   前の回の答案を同じフォルダに残さない。
2. 順番は R・S・T・U を交互に(同じ条件を続けて回さない)。
   **最初の一言も固定する。実行 ID だけを変える。**(2026-09-23 おーちゃんの決まり、K-07 4 番)
   会話を始めるときに渡すのは指示文だけ。回の数え方・条件の名前・ほかの回の話を書き足さない。
3. 各回について、**始めた時刻・終えた時刻・開いたファイルの一覧**を記録する
   (パソコン側の記録の取り方で。自己申告だけにしない)。
4. **パソコン側でも、会話に自動で入るもの(記憶・過去の会話・設定ファイル)が
   あるかを最初に確かめて、あれば回ごとに名前を記録する**(K-04 1 番の決まり)。
   条件の間で食い違いがあれば、結果と一緒に報告する。
5. 答案は `<伏せ名><回>.json`(例: `R1.json`)として回収し、採点はプロジェクトの
   スレッドで、**読み方の比較と同じ採点の決まり**で行う。採点する側には伏せ名しか渡さない。

## 5. 比べ方

読み方の比較の 6 本とは**環境が違う**(プロジェクトのスレッドとパソコン)。
だから**トライアルC の数字は、同じ回の中の R とだけ比べる。**
読み方の比較の A・B の数字と横に並べて差を言わない。
