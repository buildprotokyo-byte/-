# トライアルC 段階の順番の入れ替え — 実行の前に固定する設計

作成 2026-09-23。**この文書は読む側を動かす前に固定する。結果を見てから変えない。**
変える必要が出たら、変更と理由とコミットを残す。

比較の軸・出力の形・採点の決まりは、読み方の比較実験のものを**そのまま使う**
(`docs/experiments/ab_reading/` と `/mnt/project-files/ab_reading_scoring/`)。
**新しい採点基準を作らない。** 作ると、読み方の比較の結果と並べられなくなる。

## 1. 何を変え、何を変えないか

**原則は変えない。順番だけ変える。** どの順番でも次は必ず守る。

- 読み取った値には位置を付ける(根拠なしの行を作らない)
- 単一の根拠で確定しない
- 申告が無い数量を既定値で埋めない
- 読めなかったものを「無い」と書かない

**入力は 4 条件とも同じ**(P011 の匿名化v2 から文字・数字・表を取り出した
入力パッケージ。図形は入っていない)。**出力の形も採点の決まりも同じ。**

## 2. 条件(伏せた名前で渡す)

採点する側には **R・S・T・U** としてしか渡さない。どれがどれかは採点後に開く。

| 伏せ名 | 順番 | 何を確かめたいか |
|---|---|---|
| **R** | 既定(段階 0 → 10 の順) | 比較の土台 |
| **S** | **見積の行の型を先に置く** … どんな行を埋めるのかを先に知ってから読む | 探すものが先にあると言い当てが増えるか。**増えるなら、図面を読む前の枠が効いているということ** |
| **T** | **差分(工事内容)を先に確定させ、その後に数量を出す** | 「工事内容とは現況と計画の差分」(原則1)を段階の順番にしたもの。区分の正答が増えるか |
| **U** | **検査を各段階に埋め込む** … 最後にまとめて検査せず、段階ごとに検査する | 作り話と要確認の質が変わるか。手間がどれだけ増えるか |

**6 通り全部はやらない。** 1 条件 3 回で 12 回になり、読み方の比較(6 回)の
倍である。残る 2 つ(「会社のルールを先に置く」「確認を早く回す」)は、
**中身が無いと動かない**(会社のルールは未定、キラークエスチョンは
読み取りが候補を出してから効く)ので、この周では回さない。
**回さない理由もこの文書に残す。**

## 3. 測るもの(読み方の比較と同じ指標)

- 言い当てた行数(分子と分母を必ず付ける)
- 数量が許容差内の行数
- 区分の正答数
- 正解に無い項目のうち**根拠なしのもの**(= 作り話)
- 要確認の件数と、その中身が本当に人でないと決められないものか
- 手間: 所要時間、開いたページ数、往復の回数

**加えて、この周だけの指標**:

- **落ちている 39 行の内訳が変わるか。** 記号を数える行・形から出す行・
  会社のルールの行は、**順番を変えても原理的に埋まらない**はずである
  (A-1・A-2 で、入力に図形が入っていないことと、会社のルールが無いことが
  原因だと分かっている)。**もし埋まったら、その診断のほうが間違っている。**
  これは順番の効果を測ると同時に、A-1・A-2 の診断の裏を取る対照になる。

## 4. 先に決めておく読み方(結果の解釈)

- 3 回では偶然かどうかを断定しない。**差の大きさと一貫性だけを書く。**
- **4 条件とも同じところで落ちているなら、それは順番の問題ではない。**
  その場合、C の結論は「順番は効かない」ではなく
  「順番より上流(入力に何が入っているか)で決まっている」である。
- 手間が増えて指標が変わらない順番は、**不採用として記録する**
  (同じことを繰り返さないため)。

## 5. 汚染を防ぐ決まり(5章の原文どおり)

- 読む側は、**プロジェクトのメモや記録が一切読み込まれない、まっさらな作業場所**で動かす
- 渡すのは入力パッケージ・出力の形・実行の指示だけ。
  **実験の狙い、他の条件、過去の知見、正解ファイルの名前や置き場所を渡さない**
- **実行の前に、捨てスレッドで「何が渡っているか」を確認し、報告する**
  (`benchmarks/ab_reading_isolation_check.py` を先に回す)
- 実行後、読む側が開いたファイルの一覧を記録する
  (`docs/experiments/ab_reading/access_audit.md` の手順)
- 採点は別のスレッドで、先に固定した基準どおりに行う

## 6. この設計で分からないこと

- **入力パッケージに図形が入っていない。** だから記号を数える行と形から出す行は、
  どの順番でも埋まらないと考えている(それ自体を 3 節で測る)。
- 会社のルールの行は、ルールの中身が無いので埋まらない。
- **読む側を動かすには、このスレッドとは別のスレッドが要る。**
  同時に動かすスレッドは 2 本までという決まりがあるので、
  コーディネータに枠の調整を頼む。
