## 3. 何を作ったか

### 決め手(`estimating/decisive.py`)

指示の 5 つをそのまま種類にした。**証拠が無ければ名乗れない。**

| 決め手 | 名乗るのに要る証拠 |
|---|---|
| 観測 | 図面を読んだ値で、**ほかの 4 つがどれも無い**こと(「だけ」を守る) |
| 知識のルール | **どのルールID**か(1 つ以上) |
| 経路の一致 | **異なる経路が 2 つ以上**、かつ**独立しているかどうか**の記述 |
| 人の回答 | **どの問いへの回答**か |
| 要約資料 | **どの項目**から見つけたか |

**札ではなく証拠を持たせた。** 数量(`QuantityItem`)が持つのは証拠のほうで、
札は `decisive` が 1 か所で作る。**札を手で付けられる形にすると、証拠の無い札が混ざる。**

### 一致の数え方で気をつけたこと

- **同じ経路を 2 回数えて「一致」にしない。**
- **矛盾なく解けたときだけ「一致」と言う**(仲裁層の `solve_is_consistent` を読む)。
- **独立しているかどうかを書かないまま「一致した」と言わせない。**
  同じ PDF から出た 2 つは独立していない。**ここを落とすと、裏を取った数字に見えてしまう**
  (`docs/b_real_drawing_paths_report.md` の「合わせて 18/18」の教訓)。

### 取れなかった理由(4 種類 + 説明つきの「その他」)

- **記号が読めない / 面積が出せない** … 入口しか知らないので
  `estimating/from_intake.not_obtained_from_intake()` が作る。
- **ルールが無い / 現地確認が必要** … 当てはめの側(`MappingResult.not_obtained()`)。
- **「その他」は説明が無ければ作れない。** 束ねて中身が消えるのを防ぐ。

### 仲裁層の記録が畳むときに落ちていた

`FirewallDecision` は「どの読みが効いたか」「独立したデータ源が何個か」まで
持っているのに、**人が読む形(`TargetDecision`)に畳むときに落ちていた。**
見積の行から「複数の経路が一致したのか」を辿れなかったのはそのためである。
**判定には使わない。記録として残しただけ。**

## 4. 採点でどう使うか

`estimating/decisive.py` に集計の入口を置いた。**既存の指標は 1 つも消していない。**

- `counts_by_reason(lines)` … 決め手の種類別の件数
- `score_by_reason(hits, misses)` … **当たった行と外した行を理由別に集計**
  (当たり外れの判定は**この関数の外**でする。抽出と採点を分ける規則をここでも崩さない)
- `lines_without_reason(lines)` … **決め手の無い行を名指しする**(空欄を埋めない)
- `not_obtained_counts(items)` … 取れなかった理由別の件数

**1 行が 2 つの決め手を持つことがある**ので、種類別の合計は行数と一致しない。
行数と突き合わせるときは `lines_without_reason()` と併せて見る。
