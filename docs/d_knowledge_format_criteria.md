# 65周目の基準: **知識の表の形式が、集まった候補を無理なく受け取れるか**

**測る前にコミットする。結果を見てから基準は変えない。**

## 1. なぜこれを測るか

おーちゃんの優先順 2 は「**知識の表の形式(列の名前と意味)を先に確定させる**」である。
**Codex-B がその形式で中身を作るので、後から列を足すと作り直しになる。**
だから**先に、集まっている候補が入るかどうかを確かめる。**

## 2. 測る対象(**先に決めて動かさない**)

`docs/knowledge/candidates.md` の **A・A′・B′・B・C の全 25 項目**。
おーちゃんが名指しした 3 種類(会社のルール・波及のルール・軸ごとの問い)に当たる節である。
**「入りやすい項目だけ選ぶ」ことをしないため、節ごと全部を対象にする。**

| 節 | 何の候補か | 項目数 |
|---|---|---|
| A | 会社のルール(数え方) | 7 |
| A′ | 会社のルール(設備の数え方) | 5 |
| B′ | 波及のルール(内装改修の撤去) | 5 |
| B | 波及のルール | 3 |
| C | 軸ごとの問い | 5 |
| | **合計** | **25** |

## 3. 数える数字(**この周の数字は 1 つ**)

**M1: 25 項目のうち、形式の欄だけで表せた項目の数。**
「表せた」= **新しい列を足さずに、読み込みが通る 1 行になる**こと。

**先に線を引く。M1 が 20(8 割)以上なら、この形式で確定する。
下回ったら形式を作り直す。**表せなかった項目は**必ず名指しする。**

## 4. 対照(これが通らなければ結論を出さない)

**C1: 壊れた表を拒むこと。** 3 通りを入れて 3 通りとも読み込みが失敗すること。

1. 知らない列がある(黙って読み飛ばさない)
2. **出典が空**(出どころの無い知識を入れない)
3. 種類が知らない語

**C2: 同梱する見本が架空であること。** 実在の会社のルールも、実案件から作った表も
リポジトリに置かない(取り決め④)。見本の中身が架空だと**ファイル自身が宣言**していること。

## 5. この測定で分からないこと

- **候補の中身が正しいかは測らない。**入る形かどうかだけである。
  (候補は公共工事の基準からの引き写しで、住宅の改修にそのまま当てはまるとは限らない)
- **Codex-B が実際に埋められるかは測らない。**
- **読み込んだ知識が判定に効くかは測らない。**この周では**読み込むだけ**で、
  判定のしかたには一切つながない。
