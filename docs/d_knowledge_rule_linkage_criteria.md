# 知識を判定に繋ぐ(1本目): 採否の基準

**測る前に置く。**おーちゃんの K-11 の 1 番。

> `estimating/decisive.py` の `knowledge_rule_ids` に値を入れる側が 0 か所という件です。
> 規則か数量のどちらかに「どの知識のルールで数えたか」を渡す経路を作ってください。

## 0. どちらに持たせるか: **規則の側**

数量の側ではなく規則の側に持たせる。理由は 3 つ。

1. 知識の表の `数え方` と `波及` は「**どう数えるか**」の文である。数量を作るのは
   図面の読み取り(`estimating/from_intake.py`)で、そこに知識は要らない。
   **知識が効くのは、読めた数量を見積の行に当てはめるところである。**
2. 図面からは決まらない行(`estimating/standing_lines.py`)は、**知識だけで立つ行**である。
   P011 で 6 本とも外した 39 行のうち 6 行(仮設水道料・仮設電気料・小運搬費・荷上費・
   墨出し・竣工時清掃)がここに当たる。規則の側に持たせると、この 6 行が
   「知識のルールで出た行」として数えられる。
3. 数量の側には既に欄がある(`QuantityItem.knowledge_rule_ids`)。**規則の側に足せば、
   どちらからでも渡せるようになる。**片方だけ塞いだままにしない。

## 1. 何を測るか

| 記号 | 何か |
|---|---|
| N1 | **見積の行に届いた数**(本番経路・固定の合成数量・P011 v2 の 3 つで) |
| N2 | **自動確定の件数** |
| N3 | **決め手の種類別の件数**(とくに `知識のルール` が何件か) |

前後は同じ環境・同じ入力で測る。P011 は**匿名化 v2** で測り、報告にどちらの紙かを書く。
**出すのは件数と割合だけ。**室名・寸法・数量の値・事務所名は出力にも報告にも書かない。

## 2. 対照(1 つでも落ちたら数字を出さない)

- **C0**: それぞれの入力で行が 1 行以上出ること(0 行で割合を出さない)
- **C1**: 知識の表に無い ID を引いた規則は**断られる**こと
- **C2**: 引用を外すと `知識のルール` が **0 件に戻る**こと(壊し試験)
- **C3**: 既存の指標(行数・確定件数・基づきの内訳)が前後で**1 件も動かない**こと
- **C4**: `不採用` の知識は引用できないこと
- **C5**: 版 2 の規則ファイルに新しい欄を書いたら**断られる**こと
  (半分だけ効いた規則を作らない、という既存の約束を崩さない)

## 3. 採否

- **採用**: N2 が前後で **0 件のまま**、C0〜C5 が全部通り、N3 の `知識のルール` の件数が
  「引用を持つ規則が当たった行数」と**ちょうど一致**する
- **保留**: 対照が 1 つでも落ちる。または N3 が上の数と合わない
- **止めて報告**: **N2 が 1 件でも増えたら**、その場で止めておーちゃんに報告する
  (K-11 の条件。自動確定は 0 件のままでなければならない)

## 4. この周でやらないこと

- **判定のしかたを変えない。**階層・許容差・独立性の数え方・質問の選び方には触らない。
  決め手は**記録**であって判定ではない(`estimating/decisive.py` 4 節)。
- **採否(`adoption_status`)を書き換えない。**`候補` を `採用` に変えるのはおーちゃんだけ。
- 知識の中身(率・係数・どの工種にどれを当てるか)は書かない。ここは**経路だけ**である。

## 5. 予想(**当たっても外れても書く**)

- P011 v2 では、見本の規則が当たる行が少ないので、`知識のルール` の件数も小さいと見ている。
  **経路が通っていることと、行が埋まることは別である。**
- `候補` のままの知識を引いた行が出る。**`候補` と `採用` を混ぜて数えない**ように、
  報告では採否の状態ごとに分けて数える。
