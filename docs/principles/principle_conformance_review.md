## A. 意味の付いていない値を使っている(原則2)

原則2は「読み取った値には、必ず意味を付ける：それは何か、どこのものか、現況か計画か、目的にどう関係するか」
「意味が付けられない値は、数量に使わない」。**いま数量に付いているのは「それは何か」と、粗い「どこのもの」(ページ番号)だけ。**

1. **面積の記載に、現況か計画かも、どこの面積かも付いていない。**
   `intake/drawing_intake.py:943`(`_area_findings`)は、対象名を図面に印字されたラベルそのもの
   (`専有延床面積` / `施工床面積`)にしている。拾い方は `axes/image_axis/pdf_vector_symbols.py:302` の
   正規表現で、この2語しか拾わない。現況の面積なのか計画の面積なのかは、どこにも入らない。

2. **開き戸の件数に「どの部屋か」が無い。**
   `intake/drawing_intake.py:894`(`_door_arc_findings`)の対象名は `開き戸::ページN`。
   円弧ごとの座標は根拠(`provenance`)には残るが、値の意味としては「そのページに何件あったか」だけである。
   室の輪郭を取る実装が無いので、部屋に結びつけられない。現況/計画は、**人が宣言したときだけ**対象名に入る(`intake/drawing_intake.py:906-912`)。

3. **建具表の数量は、現況と計画を1つのレンジに混ぜている。**
   `intake/drawing_intake.py:677`(`_door_quantity_findings`)は、同じ建具番号がページによって違う数量だったとき、
   足さずにレンジにする。足さないのは正しいが、コード中のコメント自身が「既存と新設の建具表が両方ある」場合を
   想定している。**それは値の幅ではなく、意味の違いである。** 原則2の「意味が付けられない値は、数量に使わない」に
   照らすと、幅にして数量として出すのではなく、意味が決まらないものとして分けるべきところ。

4. **見積の行を決める規則が、現況か計画かを条件にできない。**
   `estimating/quantities.py:110`(`kind`)は対象名の最初の `::` より前しか見ない。
   `開き戸::現況::ページ1` は種類が `開き戸` で、`現況` は鍵の側に入るので、規則からは見えない。
   規則が条件にできる属性は `estimating/from_intake.py:27` の3つ(種別・幅・高さ)だけで、
   現況/計画は入っていない。**原則1(工事内容とは現況と計画の差分)を、見積の行の側から表現できない。**

## B. 縮尺の表記に依存している(原則3-1)

原則3-1の1行目は「図面に書かれた縮尺の表記は当てにしない」。

5. **基準点が無いページでは、表題欄の印字した縮尺だけで実寸を出している。**
   `intake/drawing_intake.py:725`(`_resolve_scale`)は、読みが1つしか無ければそれをそのまま採る
   (`_all_agree` は値が1つなら常に真)。その縮尺を使って `intake/drawing_intake.py:894` が
   建具の幅を mm に直し、開き戸を数える。**基準点を渡さない限り、実寸はすべて印字の縮尺に乗っている。**
   人が基準点を入れたページでは突き合わせが効くが、入れなかったページには何の歯止めも無い。

   **【2026-09-22 訂正】これは違反ではなくなった。** おーちゃんの定め直しにより、基準が効くのは
   「図面上の長さから数量を計算する処理だけ」で、基準点が無くても**止めない**。
   **やることは、縮尺の表記だけに頼って出した長さを「仮説に基づく」にすること**であって、
   計算をやめることではない。→ 判定が変わるので別の PR で扱う。

6. **「図面に書かれた寸法の数字と突き合わせて検算」が無い。**
   `intake/drawing_intake.py:830`(`_reference_dimension_findings`)が突き合わせる相手は、
   **同じ2点から計算した印字縮尺由来の長さだけ**である。図面上の寸法線の数字を読む経路は、
   リポジトリに1つも無い(`axes/image_axis/` にあるのは表・面積ラベル・縮尺表記の読み取りだけ)。
   したがって原則3-1の最後の1行(人のクリックや入力の誤りを寸法の数字で検算して警告する)は未実装。
   このことは `intake/start_kit.py:31` の但し書きにも書かれているとおりで、
   **2つの読みは2点の座標を共有しているので、座標の取り違えはこの突き合わせでは捕まらない。**

   **【2026-09-22 追記】この項目の重みが増した。** 「基準点が無くても、図面に書かれた寸法の
   数字から計算できるものは計算してよい」と決まったが、**その寸法の数字を読む経路が無い。**
   したがって基準点の検算ができないだけでなく、**基準点が無いページで計算できるものが実質無い。**
   寸法線の数字を位置つきで読む実装が、いま最も効く追加である。

7. **区画ごとの基準が持てない。**
   `intake/start_kit.py:185` は、縦・横それぞれ1ページに1組までしか受け付けない。
   ページ全体に同じ比を当てるので、原則3-1の「画像を区画に分けて、区画ごとに基準を持てる形にする
   (局所的な歪みへの対応)」は表現できない。

## C. 人の入力を無条件に正解としている(原則5・原則4)

原則5は「人が与えた情報も、図面の中身と突き合わせて矛盾を探す。人の入力を無条件の正解にせず、
単一の根拠では自動確定させない」。**後半(自動確定させない)は守れている。破れているのは前半(突き合わせる)。**

8. **面積の基準の指定を、そのまま採っている。**
   `intake/drawing_intake.py:1023-1024`。保存済みの回答とスタートキットの指定が食い違うかは見るが、
   **図面の中身とは突き合わせない。** 人が選んだほうの値が、そのまま `施工対象床面積` になる。

9. **人が宣言したページの種類が、抽出の範囲を無条件に決める。**
   `intake/drawing_intake.py:605`。宣言が「建具表」「仕上表」なら、そのページで開き戸を探さない。
   ページの種類を図面から自動で判定する経路は無い(`content_kind` はベクター/ラスター/空の区別だけ)ので、
   **宣言が誤っていても検出できず、そのページの建具は黙って0件になる。**
   これは原則4の条件3「図面の読み方を縛らない」にも正面から反する。

    **【2026-09-22 対応】直した。マージせず PR のまま待機している。**
    宣言でページを外す分岐を削除し、円弧は宣言に関わらず探す。宣言と食い違ったら
    読みを捨てずに `PendingDecision(kind="page_kind_disagreement")` に残し、
    その読みの由来を `assumed`(＝「仮説に基づく」)にして自動確定から外す。
    実装場所は `intake/drawing_intake.py` の `_door_arc_findings()`。
    設計は `docs/design_v8.md` 18 章、経緯は `docs/page_kind_weak_hint.md`。
    **既存テスト1件(`test_door_arcs_are_not_hunted_on_a_page_declared_as_a_table`)と
    食い違う。書き換えずに残してあり、おーちゃんの判断待ち。**

10. **人が宣言した現況/計画/解体が、突き合わせなしに対象名へ入る。**
    `intake/drawing_intake.py:906-912`。宣言の誤りは下流のすべてに効く。

11. **原則4「人が先に入力してよいのは基準点だけ」に対し、いま先に受け取っているのは4つ。**
    `intake/start_kit.py:173-181` が受け取るのは、基準点・ページの種類・現況と計画の対応・面積の選択。
    **基準点以外の3つは、原則4の3条件を満たしていない**(ページの種類は条件3を破り、
    面積の選択は条件2「AI では確実に推定できない」に当てはまらない可能性がある)。

    **【2026-09-22 訂正】3つのうち2つは解消し、1つだけ残る。**
    現況と計画の対応、面積の選択は、**未入力でも止まらない弱い手がかり**として扱えば筋が通る
    (目的も現況も「与えられていなくても処理は止めない」と定まった)。
    **残るのはページの種類である。** 人が「建具表」と宣言すると、そのページで開き戸を探すこと
    自体をやめる(9 を参照)。これは弱い手がかりではなく**図面の読み方を縛っている**ので、
    原則4の条件3にまだ反している。

    **【2026-09-22 対応】直した(9 を参照)。マージせず PR のまま待機している。**
    ページの種類も**弱い手がかり**になり、読み取りの範囲を決めなくなった。
    これで原則4に反して残っているものは無くなる(この PR がマージされた場合)。

**補足(反していない点):** 人の入力は `arbitration/method_policies.py:113` で未校正として登録されているので、
それだけを根拠に階層1(自動確定)へ上がることはない。ここは原則どおりに守られている。

## D. 確定と仮説の区別がない(原則5)

原則5は「何に基づくかを区別して出す：確定／推論に基づく／仮説に基づく／現地確認が必要」。

12. **4つの区別がどこにも無い。いまあるのは2値だけ。**
    `estimating/quantities.py:127`(`is_confirmed`)と `estimating/mapping.py:59`(`is_confirmed_quantity`)は
    真偽値で、「確定したか、していないか」しか表せない。
    「現地確認が必要」はリポジトリ全体で1件も出てこない(`grep` で0件)。

13. **仲裁層には由来があるのに、見積の行まで運ばれていない。**
    `arbitration/inference_orchestrator.py:400` と `axes/reading/protocol.py:75` には
    `read`(読んだ) / `derived`(計算した) / `assumed`(一般則で補った)の区別があり、
    `assumed` は階層1に上がらないよう守られている。ところが
    `estimating/from_intake.py:92-106` は `QuantityItem` を作るときに `derivation` を写していない。
    **仮説から来た数量と、図面から読んだ数量が、見積の行の上では見分けられない。**

14. **仮説の記録と、仮説が変わったときの連動が無い。**
    原則5の「仮説に基づく行は、どの仮説に依存しているかを記録し、仮説が変わったら連動して見直す」に
    当たる仕組みが無い。`provenance` は根拠を運ぶが、仮説そのものに識別子が無く、
    仮説を変えたときに影響する行を引く経路も無い。

15. **原則5の1行目とは逆に、いまは止める作りになっている。**
    `intake/drawing_intake.py:978`(`_apply_area_basis`)は、面積の基準が未回答だと
    `施工対象床面積` を出さない。安全側に倒した設計で、理由も docstring に書かれている。
    ただし原則5は「前提が揃うまで止めるのではなく、何に基づくかを区別して出す」である。

    **【2026-09-22 決着】止める作りそのものが取り消しになった。** おーちゃんの回答2と、
    位置づけの定め直しの5節による。**両方の値で「仮説に基づく」行を2本出し、どちらも自動確定
    させず、どの仮説に依存しているかを記録する。**

    **これに食い違う既存のテストが2件ある**(`tests/test_drawing_intake.py` と
    `tests/test_intake_start_kit.py` の「未回答なら `施工対象床面積` を出さない」)。
    **勝手に書き換えず、食い違いとして報告した。** 判定が変わる修正の PR の中で、新しい動きを
    固定するテストに置き換える。
