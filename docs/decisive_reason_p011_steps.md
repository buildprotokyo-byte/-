# P011 で「理由別の内訳」を出す手順(**PC 側 = Codex-A 向け**)

2026-09-23。66周目で、見積の行 1 つに**決め手**が付くようになった
(`docs/d_decisive_reason_report.md`)。**これが以後の基準になる**ので、
実案件でもう一度、理由別の内訳を出してほしい。

**クラウド側(Claude)は実図面で測らない。** ここにあるのは仕組みと手順だけである。

---

## 0. 先に守ること

- **実図面・見積明細・そこから作ったデータはコミットしない。** パスは引数で渡す。
- **出すのは件数と割合だけ。** 室名・寸法・数量の値・事務所名は出力にも報告にも書かない。
- **P011 には 2 つのファイルがある。** どちらで測ったかを報告に必ず書く。
  - 匿名化 v2(A3・34ページ・30ページに文字)… **こちらで測る**
  - 古いほう(A0・全ページスキャン・文字なし)… 開き戸の円弧の正解データはこちらの紙で
    作られている。**v2 とは別の紙なので、ベクターの経路をこの正解で採点しない。**

## 1. 測る

```bash
.venv/bin/python benchmarks/measure_decisive_reason.py <P011v2のパス>
```

合成案件の測定(対照つき)に加えて、`入力う_実図面` が付く。

## 2. 見る数字

| 記号 | 何か |
|---|---|
| M1 | 出た行のうち、**決め手が 1 つ以上付いている行の割合** |
| M2 | **決め手の種類別の件数**(観測 / 知識のルール / 経路の一致 / 人の回答 / 要約資料) |
| M3 | **取れなかった理由別の件数**(記号が読めない / 面積が出せない / ルールが無い / 現地確認が必要 / その他) |

**対照(C0〜C3)が 1 つでも通らなければ、数字を出さない。** 合成側で先に見る。

## 3. 合成案件での結果(比べる先)

- M1 = 1.00(本番経路 1 行中 1 行 / 固定の合成数量 3 行中 3 行)
- M2 = **観測 1 種類だけ**。残り 4 種類は**経路がまだ無い**
- M3 = 記号が読めない 1 件、ルールが無い 2 件

**実図面で M2 に「経路の一致」が出たら、そこが合成案件では測れていない場所である。**
出たときは、`agreeing_paths`(どの手法が一致したか)と `paths_independent`
(独立していたか)を**必ず両方**報告に書く。**独立していない一致を「裏を取った」と書かない。**

## 4. 報告に書くこと

1. **どちらの P011 か**(v2 か古いほうか)
2. 使ったコミット
3. M1・M2・M3 の数字(**件数と割合だけ**)
4. 対照の結果(C0〜C3)
5. **決め手が付かなかった行が何件で、なぜ付かなかったか**
   (`一般則で補った値` は決め手が空のまま残る。**埋めない。**)
6. うまくいかなかったこと。**結果を捏造しない。**

## 5. 決め手の意味(名乗るのに要る証拠)

| 決め手 | 証拠 |
|---|---|
| 観測 | 図面を読んだ値で、ほかの 4 つがどれも無い |
| 知識のルール | どのルールIDか |
| 経路の一致 | 異なる経路が 2 つ以上 + 独立しているかどうか |
| 人の回答 | どの問いへの回答か |
| 要約資料 | どの項目から見つけたか |

**証拠が足りない札は、仕組みが作らせない**(`estimating/decisive.py`)。
