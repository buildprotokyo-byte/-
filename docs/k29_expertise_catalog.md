# K-29 要素ごとに専門知識を選んで読む仕組み

2026-09-24。おーちゃんの指示(「ありとあらゆる知識を要素に分けて、この要素はこの知識で読む、
と指示を出せる仕組み」)に対する最初の形。

## 1. 何ができたか

| 部品 | 場所 | すること |
|---|---|---|
| (置き場所) | `knowledge/expertise/reader.py` | 判定の側(`axes/` など)から知識を読み込まない決まりを崩さないため、`knowledge/` の下に置いた |
| 要素と知識の対応表 | `knowledge/expertise/catalog.json` | 図面の要素 15 種類 × 知識 12 件 × 専門家 5 人。**出どころと、こちらの言葉で書いた要点だけ。**本文は写さない |
| 知識を選ぶ | `select_knowledge` | 要素を 1 つ渡すと、その要素に付いた知識と専門家を**全部**選ぶ(選り好みしない) |
| 前提の文 | `build_premise` | 選んだ専門家・知識・要点と、守ること 5 つ(図面の凡例・表・印字が一般の決まりより優先、使った知識と見た場所を必ず挙げる、数字を作らない、2 通りに取れたら質疑、読めないは間違いではない)。**前提の文はここ 1 か所でしか作らない** |
| 読ませる | `read_element` | 読み手が無ければ「読み手が未接続」と記録して**答えを作らない**。答えには必ず「知識から出した」印。**確定は常にしない** |
| 面積(最初の対象) | `room_area_request` | 室を長方形の足し引きで答えさせ、**面積の掛け算はこちらでやり直す。**合わなければ記録。基準が芯々(`docs/decision_area_basis.md`)でなければ記録 |
| 図面との突き合わせ | `check_against_drawing` | **ここ 1 か所だけ。**凡例の名前・印字された面積と食い違えば図面を採る |
| AI の読み手 | `AnthropicReader` | Claude を呼ぶ。鍵が無ければ作れない |

一覧は `python -m knowledge.expertise.reader --list`、前提の文は
`python -m knowledge.expertise.reader --element 室の面積` で見られる。

## 2. 知識の表(format_version 2)に乗せなかった理由

版 2 の `kind` は `数え方` / `波及` / `問い` の 3 つで、**「その要素をどう読むか」はどれにも当たらない。**
`kind` を足すと版 2 の表の形が変わり、「列を後から足すと作り直し」の決まりに触れる。
だから**別の目録にした**。ただし出どころの検査は知識の表と**同じもの**(`knowledge/table.py`
の `_parse_source`)を使う。拘束力の値(`法令`・`行政基準`・`業界指針`・`任意資料`…)も同じ一覧。

## 3. 正直に書いておくこと

- **要点は全 12 件とも `未照合`。**こちらが持っている一般の理解で書いた要点で、原文とはまだ
  照らし合わせていない。条番号・版も「未確認」と書いてある。**`照合済み` にするには
  原文を直接読み、確認日を書くことが要る**(書かずに `照合済み` にすると読み込みが断る)。
- **AI はこの環境からもリポジトリからも呼べない。**鍵(`ANTHROPIC_API_KEY`)が無い。
  通信は届く(鍵なしで 401 が返る)。部品(`anthropic`)は PyPI から入る。
- **本番の経路(`app.py`)には繋いでいない**(K-29 の注意)。

## 4. 測り方(場面ごと、1 場面ずつ)

面積の測定は検証ループが K-29 で進めている。このスレッドでは二重に測らない。
記号・配管・建具は、**1 場面ずつ**、測る前に基準をコミットしてから測る。
各場面で、答えごとに**どの知識を見に行ったか・どのページのどこの数字を使ったか・なぜその数字がそこに当たると判断したか**を
書かせる(`used_knowledge`・`drawing_evidence`・`reason`、面積は長方形ごとの `width_from`・`depth_from`)。
