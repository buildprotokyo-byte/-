## なぜこの題なのか

**いまの選び方は「効き」しか見ていない。**1 問で一番多くの未確定が閉じる問いを選ぶ。
だから「その値をそのまま教えてください」という問いが**最強**になる。

**コードを読むと、問いの形はもともと 1 種類しかない**(`killer_question/engine.Question`)。
**変数を 1 つ指して「この値は?」と聞く。**だから「直接聞くかどうか」で分類しても意味がない。
**分かれ目は、答えが返ってきたあとに検算されるかどうかである。**

**そこで、質を「嘘の答えを入れたときに気づくか」で測る。**

- **気づかれる問い**: 答えが他の読みや制約と突き合わされる。**間違えたら弾かれる。**
- **気づかれない問い**: 答えがそのまま値になる。**間違えたら、そのまま通る。**

おーちゃんの言う「洋室の面積を教えてください」は後者である。

## 測り方(**合成案件だけで測る。取り決め④**)

`benchmarks/run_killer_question_eval.py` と同じ合成のシナリオを使う。
**代役(正解から答えを返す仕掛け)で回す。人は要らない。**

1. **正しく答えたときの通し**を 1 回。出た問いを記録する。
2. 出た問いを 1 つずつ取り上げ、**その問いにだけ嘘の答えを入れて**同じ通しをやり直す。
3. **嘘が矛盾として出るか**(解けなくなる・食い違いとして残る・確定しない)を数える。

**嘘の作り方は先に決める。** どれも整数の変数なので **「正解 + 1」** を入れる。
**あわせて「正解 + 5」でも測る。**(幅で結果が変わるかを見るため。**線は +1 のほうで引く。**)

| 記号 | 何を測るか |
|---|---|
| **E0** | 正しく答えたときの問いの数と、解けたかどうか |
| **E1** | 嘘を入れて試した問いの数(= E0 の問いの数) |
| **E2** | **嘘が気づかれた問いの数**(+1 のとき) |
| **E3** | **嘘が気づかれなかった問いの数**(+1 のとき) |
| **E4** | E2・E3 を「+5」でも測った数 |

**出すのは件数と割合だけ。**

## 結論の形(**測る前に決める。結果を見てから変えない**)

- **E3 ÷ E1 ≧ 0.5** → **半分以上の問いは、嘘をついても誰も気づかない。**
  **おーちゃんの見立てが当たっている。**質の軸を足す設計を出す
  (**設計まで。実装は PR のまま待機**。判定のしかたに触るため)。
- **E3 = 0** → **全部の問いが検算される。**いまの選び方でも質は保たれている。
  **おーちゃんの心配は、この仕組みには当てはまらない**と報告する。
- **0 < E3 ÷ E1 < 0.5** → **割合を記録し、気づかれない問いがどの種類かを名指しする。**
  設計は出さず、次の周の題にする。

**「気づかれた」の定義も先に決める。** 次の**どれか 1 つでも**起きたら気づかれたとする。

1. 解こうとして**解けなくなる**(矛盾)
2. **食い違いとして人に回る**
3. その対象が**自動確定しなくなる**(正しく答えたときは確定していたのに)

## 対照

| 対照 | 中身 | 通る条件 |
|---|---|---|
| **1(誤検出が無いか)** | 正しい答えだけで通したとき | **矛盾が 1 件も出ない。**出るなら測定そのものが壊れている |
| **2** | 問いの数 | **1 問以上。**0 問なら測るものが無い |
| **3** | 反復 3 回(E3) | 3 回とも同じ |

**対照1・2 が通らなければ結論を出さない。**
