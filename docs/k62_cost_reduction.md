# K-62 1 回の費用を、評価用で 1/20・実運用で 1/10 にする

おーちゃんの指示(K-62、2026-10-01)。K-61 の 1 回 32〜37 ドル(文字数から出した概算)を、
**評価用は約 1.7 ドル以下、実運用は約 3.5 ドル以下**にする。**質は下げない。**

K-61 の 3 つの判断(同じ指示の頭):
1. 通読は分けて読ませる。
2. 32 ページのような表も仕上表の原本と数え、画面に「本来の仕上表ではない」と出す。
3. 読み直すページの選び方は今のまま(その回の通読の落ちで 33% 超)。

## 測る前の基準(2026-10-01、測る前にコミット)

### 毎周出す数字

- 1 回の費用と時間(段ごと)。
  - クラウドには鍵が無いので、ここで出すのは**目安**(画像は画素数から、文字は字数から)。
  - **API の使用量の記録(入力・出力・キャッシュの書き込みと読み出し)で測るのはパソコン側**。
    道具は一本道に入れ、手順書は `reports/K-62/` に置く。
- 落ち。1 回の通読のあとと、読み直したあと。
- 囮との差(拾えた − 囮)。
- 3 回のばらつき。項目の数、行の名前の一致、数量の一致、質問の一致。
- 自動確定の件数。

### 線(戻すかどうか)

1. **自動確定 0 件**。1 件でも出たらその場で止めて報告する。
2. **落ちが悪化しない**。読み直した後の落ちを、K-61 の同じ回と比べる(R1 16.11%・R2 21.23%・R3 17.28%)。
   - 1 回でもこれより大きければ「悪化」とし、その周の手段は採らずに戻す。
   - 拾えた − 囮(K-61: 162,587・163,560・170,683)は並べて書くが、線にはしない。
   - 不通過の例: R2 の読み直した後の落ちが 21.5% なら、その手段は採らない。
3. **未取得を 0 にしない**。数量が 0 の行が出ていないこと。
4. **質が下がる手段は採らない**。
   - 落ちのほかに、3 回で共通する内訳の鍵の数と、3 回とも同じ数量の行の数も見る。
   - 手段の前より大きく減れば(半分未満なら)質が下がったとみなし、落ちが通っていても採らない。
   - 揺れの直し(下の 4)はこの比べ方を変えるので、直しの前後は別に書く。

### 1 周で変えるのは 1 つ

- 手段 a〜f は 1 周に 1 つだけ当てる。比べる相手は、その直前に採った状態。
- 判断 1(通読を分ける)は手段の前に入れる。分けた状態の 3 回を新しい基準の回とし、それ自体も線 2 で K-61 と比べる。
  - 通らなければ報告し、判断はおーちゃんに返す(分けることは決まっているので戻さない)。
- 室名の揃え(4)は費用の作業と並べて進める。読みを変えない機械の処理なので、AI を呼び直さずに既にある 3 回へ当てて測る。

### 手段ごとの測り方(前もって決めておく)

- **a 文字の層で読ませる**: 読みを変える。クラウドで 3 回読ませ、落ちを測る。
- **b キャッシュ**: 読みを変えない。キャッシュに乗る分を、指示と画像の重なりから数えて費用を出す。本当に乗ったかはパソコン側の使用量の記録で見る。
- **c 軽いモデル**: 読みを変える。クラウドで軽いモデルの作業役に 3 回読ませ、落ちを測る。
- **d 位置は一覧に載る項目だけ**: 実運用の回の出力を変える。評価用の回は今のまま。実運用の回で項目と数量が評価用の回と同じだけ出るかで見る。
- **e 低解像度**: 読みを変える。対象のページだけ 3 回読ませ、落ちを測る。
- **f 即時でない処理方式**: 読みを変えない。使えるかと値引きの率を調べ、費用を出す。

## 結果

2026-10-01 に P011 匿名化 v4 で測った。クラウドには鍵が無いので、AI の段はすべて作業役に「待っている問い」を読ませて答えさせた。**費用は文字数と画素数から出した目安で、考える分(thinking)は入っていない。** 使用量の記録で測るのはパソコン側(手順書は共有フォルダ `reports/K-62/`)。時間も作業役の時間は API の時間ではないので、ここには出さない。

### 3. 手段ごとの前後

| 手段 | 測り方 | 結果 | 採否 |
|---|---|---|---|
| a 文字の層で読ませる | 3 回読ませた | 読み直した後の落ち R1 19.34%・R2 20.18%・R3 17.68%(基準の回より 3 回とも 1.3〜1.6 点悪い。R1・R3 は線を超えた)。費用は通読+読み直しで $0.6〜1.0 下がった | **採らない** |
| b キャッシュ | 指示と画像の重なりから数えた | 理解の段で凡例 2 枚を 34 回送り直している分が 1 回 $1.0〜1.2(約 3%)。ただし理解の指示にページ番号が入っていて前置きが毎回変わるので、今のままでは乗らない | 未採用(下の「戻って決めること」) |
| c 軽いモデル(整理と通読) | 3 回読ませた | 通読の落ち 32.4%・44.6%・43.3%。読み直した後 **R1 20.89%**(線 16.11% を超えた)・R2 15.71%・R3 14.84%。読み直すページが 13・22・21 回に増え、費用は $14.3〜18.3 で基準の回より $2〜6 しか下がらない | **採らない** |
| d 位置は一覧に載る項目だけ(実運用) | — | 実運用の回を測っていない | 未測定 |
| e 整理を低解像度で | 費用から判断 | 整理は 1 回 $0.26(0.7%)。半分にしても 0.4% | 採らない(効かない) |
| f まとめて送る(半額) | 口を入れた(`--batch`) | 評価用の回だけ。値引き 50%。鍵が無いので動かしていない | 入れた(パソコン側で確かめる) |

- **a が悪くなった中身**: 文字の層だけで読ませた 7 ページ(1〜5・17・32)の通読の落ちが 0.1〜7% から **74〜87%** に上がった。この数え方は線や罫も「図形」として数えるので、表の罫線を囲めない読み方は落ちとして数えられる。罫線が数量に効くかはこの測り方では分からないが、線は線なので戻した。
- **c で起きたこと**: 軽いモデルの作業役は、ページによって挙げる要素の数が大きく少なかった(R3 の 19〜21 ページで 129 個、重いモデルは 501 個)。読み直しを重いモデルで足すと、浮いた費用がほぼ消える。
- 作業の途中で、軽いモデルの作業役 3 つが「答えのファイルを新しく書く」ところで安全判定に止められた。同じ作業役をやり直さず、Write の道具で書くように指示した新しい作業役で通した。

### 4. 室名の揃え(4)

- AI を呼び直さずに既にある 3 回へ当てた。室名の書き方 51 種類 → 44 種類。3 回で共通する内訳の鍵 159 → 161。同じ室を別の室として問う質問の重なり 0 件。
- 共通する鍵がほとんど増えないのは、揺れの大きいところが室名ではなく工事の名前の側にあるため。

### 5. 着いた費用と時間

- **評価用**: 質を変えずに当てられたのは f(まとめて送る、半額)だけ。それを当てた見込みで、1 回およそ **$18**(基準の回の目安 $36 の半分、考える分は除く)。目標 $1.7 には届かない。
- **実運用**: 採った手段が無いので **基準の回の $35.9〜36.4 のまま**(目標 $3.5)。d を実運用で当てると読み直しの段(7〜29%)が要らなくなる見込みだが、測っていない。
- 時間は API で測っていない(作業役の時間は API の時間ではない)。パソコン側の手順書で測る。

### 6. 目標に届かない理由と、届きうる道(未測定)

1/20・1/10 は、a〜f の範囲では質を下げずには届かない。費用の大半は「読んだものを全部書き出す出力」と「理解の段での画像の送り直し」で、a〜f はどちらにも小さくしか当たらない。届きうる道は読みの形を変えるもので、どれも未測定:

1. 出力の形を詰める(要素を 1 行ずつの長い書き方から、短い配列にする)。通読・読み直しの出力と理解の入力がおよそ半分になる見込み($9〜12)。
2. 読む段と理解の段を 1 回にまとめる(理解の段の 34 回の送り直しが無くなる)。
3. 考える量を medium に下げる(今は high)。
4. 機械が文字の層から語と位置を先に渡し、AI は線と記号だけを読む。

### 7. 戻って最初に決めること 3 つ

1. **通読を分けた R1 が線を 1.76 点超えた。** 分けたまま進めてよいか(分けても費用は下がらない)。
2. **目標の 1/20・1/10 を、上の 6 の「読みの形を変える」道で追うか。** 追うなら 1 周に 1 つずつ、測る前に基準をコミットして測る。
3. **パソコン側で手順書の 2 本(使用量で費用を測る・機械の段をマザー PC で動かす)を流すか。** 考える分を含む本当の費用と、まとめて送る方式の値引きと時間は、ここでしか分からない。
