# K-62 1 回の費用を、評価用で 1/20・実運用で 1/10 にする

おーちゃんの指示(K-62、2026-10-01)。K-61 の 1 回 32〜37 ドル(文字数から出した概算)を、
**評価用は約 1.7 ドル以下、実運用は約 3.5 ドル以下**にする。**質は下げない。**

K-61 の 3 つの判断(同じ指示の頭):
1. 通読は分けて読ませる。
2. 32 ページのような表も仕上表の原本と数え、画面に「本来の仕上表ではない」と出す。
3. 読み直すページの選び方は今のまま(その回の通読の落ちで 33% 超)。

## 測る前の基準(2026-10-01、測る前にコミット)

### 毎周出す数字

- 1 回の費用と時間(段ごと)。
  - クラウドには鍵が無いので、ここで出すのは**目安**(画像は画素数から、文字は字数から)。
  - **API の使用量の記録(入力・出力・キャッシュの書き込みと読み出し)で測るのはパソコン側**。
    道具は一本道に入れ、手順書は `reports/K-62/` に置く。
- 落ち。1 回の通読のあとと、読み直したあと。
- 囮との差(拾えた − 囮)。
- 3 回のばらつき。項目の数、行の名前の一致、数量の一致、質問の一致。
- 自動確定の件数。

### 線(戻すかどうか)

1. **自動確定 0 件**。1 件でも出たらその場で止めて報告する。
2. **落ちが悪化しない**。読み直した後の落ちを、K-61 の同じ回と比べる(R1 16.11%・R2 21.23%・R3 17.28%)。
   - 1 回でもこれより大きければ「悪化」とし、その周の手段は採らずに戻す。
   - 拾えた − 囮(K-61: 162,587・163,560・170,683)は並べて書くが、線にはしない。
   - 不通過の例: R2 の読み直した後の落ちが 21.5% なら、その手段は採らない。
3. **未取得を 0 にしない**。数量が 0 の行が出ていないこと。
4. **質が下がる手段は採らない**。
   - 落ちのほかに、3 回で共通する内訳の鍵の数と、3 回とも同じ数量の行の数も見る。
   - 手段の前より大きく減れば(半分未満なら)質が下がったとみなし、落ちが通っていても採らない。
   - 揺れの直し(下の 4)はこの比べ方を変えるので、直しの前後は別に書く。

### 1 周で変えるのは 1 つ

- 手段 a〜f は 1 周に 1 つだけ当てる。比べる相手は、その直前に採った状態。
- 判断 1(通読を分ける)は手段の前に入れる。分けた状態の 3 回を新しい基準の回とし、それ自体も線 2 で K-61 と比べる。
  - 通らなければ報告し、判断はおーちゃんに返す(分けることは決まっているので戻さない)。
- 室名の揃え(4)は費用の作業と並べて進める。読みを変えない機械の処理なので、AI を呼び直さずに既にある 3 回へ当てて測る。

### 手段ごとの測り方(前もって決めておく)

- **a 文字の層で読ませる**: 読みを変える。クラウドで 3 回読ませ、落ちを測る。
- **b キャッシュ**: 読みを変えない。キャッシュに乗る分を、指示と画像の重なりから数えて費用を出す。本当に乗ったかはパソコン側の使用量の記録で見る。
- **c 軽いモデル**: 読みを変える。クラウドで軽いモデルの作業役に 3 回読ませ、落ちを測る。
- **d 位置は一覧に載る項目だけ**: 実運用の回の出力を変える。評価用の回は今のまま。実運用の回で項目と数量が評価用の回と同じだけ出るかで見る。
- **e 低解像度**: 読みを変える。対象のページだけ 3 回読ませ、落ちを測る。
- **f 即時でない処理方式**: 読みを変えない。使えるかと値引きの率を調べ、費用を出す。
