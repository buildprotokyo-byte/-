# 1 段目(認識)を測った — **図面の上にあるものの 3 分の 2 に、どの経路も触れていない**

基準は `docs/k21_stage_walkthrough_criteria.md`(追記 1 まで**すべて測る前にコミット済み**)。
道具は `benchmarks/measure_recognition_stage.py`。**実図面の中身はこの文書に書かない。**

## なぜこれを測ったか

おーちゃんの指摘。**「認識をしていなければ、読むも読まないもない。」**
これまでの「不明」「0 件」「落ちた」は、**認識で落ちたのか、読むで落ちたのかが混ざっていた**
→ `docs/k21_reading_stages.md`。

## 正解は人が作らない

ベクターの PDF は、**その紙に何がどこにあるかの台帳を自分で持っている。**
描画命令(線・矩形・曲線)の 1 本 1 本と、語の 1 つ 1 つが、位置つきで取れる。
**それを分母にする。**分子は「**いまの経路が触れた命令**」である。

## 結果(P011 匿名化 v2 の 1 ページ、縮尺 1/50、閉じた面 1 つぶんの範囲)

| | |
|---|---:|
| 範囲の中の**描画命令** | **1,573** |
| 範囲の中の**語** | 91 |
| ベクターの図形(円弧)の経路が触れた | 75 |
| 面の線分の経路が触れた | 467 |
| 文字の読み取りが拾った語 | 91(全部) |
| **どの経路も触れなかった描画命令** | **1,055(67.1%)** |
| その内訳 | **全部が曲線(ベジェ)** |

**先に決めた線は「触れていない割合が 6 割を超えたら 1 段目は落ちる」だった。落ちた。**

対照 D1(範囲を 50pt ずらす)でも 486 / 825 = 58.9% が触れられていない。
**範囲の取り方の問題ではない。**

### 表の升目は「触れた」に数えていない(**最初は数えて満点が出た**)

最初の実装は、罫線の表の外形に入っている命令を「触れた」に数えていた。
そうすると**表が 1 つ見つかっただけで、範囲の中の命令が全部「認識できた」ことになり、
触れていない命令 0 件という嘘の満点**が出た。升目で数え直しても 1,294 件が入ってしまう。

**升目の中に入っていることは、その命令を認識したことではない。**経路が出している要素は
「升目」であって、升目の中に描かれている線や曲線ではない。**数えはするが、触れたには入れない。**

## この数字の限界

- **「触れた」は「認識した」の上限である。**罫線を升目に取り込んだからといって、
  その線を「表の枠」として認識したとは限らない。**実際の認識はこの数字より低い。**
- **スキャンのページでは使えない。**描画命令が無いので常に 0 件になる。
- 測ったのは 1 ページの、1 つの面のまわりだけである。

## ここから言えること

**曲線(ベジェ)を見ている経路が、建具の円弧を探すものしか無い。**
1,055 件の取りこぼしは全部が曲線である。設備の記号・家具・什器・曲がった壁は、
**そこに在ることすら数えられていない。**

**「読めなかった」の多くは、読む前に落ちている。**
