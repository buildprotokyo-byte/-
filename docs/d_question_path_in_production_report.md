# 61周目の報告: **問いの経路は、本番経路から一度も呼ばれていない**

基準は `docs/d_question_path_in_production_criteria.md`(**測る前にコミット済み**)。
測り方は `benchmarks/measure_question_path_in_production.py`。

## 1. 結果

| 記号 | 何を数えたか | 合成案件 | 実図面 v2 | 予想 |
|---|---|---|---|---|
| C1(対照) | 問いの経路を使うベンチマークでの呼び出し回数 | **90** | — | 1 以上 |
| M1・M2 | **本番の入口からの `killer_question/` の呼び出し回数** | **0** | **0** | 0 |
| M3 | `independent_sources` を申告した変数の件数 | **0** | **0** | 0 |

**対照は通った**(同じ数え方が 90 回拾っている)。**だから 0 は「数え方が何も拾わない」ではない。**

## 2. 判定(基準の分岐のとおり)

> **M1 = 0 かつ M2 = 0 → 「PR #87 の 3 件は、本番経路では 1 件も効かない」と結論する。**

**そのとおりになった。**

- `KillerQuestionEngine` を作っているのは**テストとベンチマークだけ**である。
- `killer_question.firewall_bridge.add_target_to_joint_solver` も同じく、
  **本番から呼んでいる場所が 1 か所も無い。**
- したがって `Question.grade` も `AnsweredQuestion.basis` も
  `SessionResult.disagreements` も、**実案件では一度も作られない。**

**PR #87 に書いた但し書き(「いまの本番経路では全部 C になる」)は、
甘すぎた。**正しくは **「C にすらならない。問いが 1 つも出ない」** である。

## 3. 何が言えて、何が言えないか

- **言える**: 本番の入口 `read_drawing` を 2 通りの案件で走らせて、
  問いの経路には一度も入らなかった。
- **言えない**: 入口を作れば質が上がるかどうか。**入口が無いので測っていない。**
- 実図面は v2 の 1 冊だけ。**1 冊で出た 0 は、1 冊の話である。**
  ただし合成案件でも 0 なので、**図面の側の事情ではない。**

## 4. 次にすること(こちらでは決めない)

**入口を作るかどうかは判断待ちの札にする**(取り決め③・⑨)。
作る場合、置き場所は `read_drawing` の後(仲裁層の結果が出たところ)になる。
**48〜50 周の結論と合わせて読むと、入口を作っても自動確定は増えない。**
増えるのは**人に出せる問いの数**である。
