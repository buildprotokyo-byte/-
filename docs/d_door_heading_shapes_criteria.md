2026-09-23。**測る前に書いてコミットする。**

## 1. どこから続いているか

38周目で、建具表が実図面で 0 件になる落ちどころが**列の見出しの当て方**に確定した。
39周目で素直な直し方(**丸ごと含み一致**)を測り、**保留**になった
(`docs/b_door_heading_matching_report.md`)。

| | 内側で通った表 | 外側で通った表 | 誤爆÷当たり | 取り違え |
|---|---|---|---|---|
| いまのまま(完全一致) | 0 / 47 | 0 / 60 | — | 0 |
| 案1 丸ごと含み一致 | 1 / 47 | 1 / 60 | **1.000** | **7** |

**39周目が、次に測る案を 2 つ先に書いている。** この周はその 2 つを作る。

- **案2a 後方一致**: 升目の文字が言い換えで**終わる**ときだけ当てる。
  `有効幅`・`開口幅`・`内法高さ` は当たり、**`幅木`・`係数` は当たらない。**
- **案2b 区切ってから完全一致**: 升目の文字を空白と記号で割り、**どれか 1 つが
  言い換えとちょうど同じ**なら当てる。`巾 W` は当たり、**`幅木` は割れないので当たらない。**

**線も 39周目が先に引いている**(当たり 1 個以上・誤爆÷当たり < 0.5・取り違え 0)。
**結果を見てから線を変えない。**

## 2. この周で誰が何をするか

**実図面での測定は PC 側(Codex-A)。** クラウド側は**測れる形にするところまで**である。

- ベンチマーク `benchmarks/measure_door_heading_matching.py` に案2a・案2b を足す
  (**いまと同じく、緩め方はベンチマークの中だけ。実装には手を入れない。**)
- **合成の升目**で、当て方の形そのものを測る(下の M1)

## 3. 測る数字(**合成。語は過去の報告書から採る**)

**語をこの周で作らない。** 使うのは、過去の実測で名前が挙がった書き方だけである。

- **当ててほしい**(実測で名前が挙がった、または既存の別名表にある形):
  `巾 W` / `幅(W)` / `有効幅` / `開口幅` / `内法高さ` / `建具No.`
- **当ててほしくない**(39周目の報告書が名指しした紛らわしい語):
  `幅木` / `巾木` / `係数` / `全幅` / `床仕上`

| 記号 | 測るもの |
|---|---|
| M1 | 当ててほしい書き方のうち、当たった数(いまのまま / 案2a / 案2b) |
| M2 | 当ててほしくない書き方のうち、誤って当たった数(同じ 3 つ) |

## 4. 対照(**通らなければ結論を出さない**)

- **C1 いまのままでは当たらない**: `巾 W` が完全一致では当たらないこと
  (これが当たってしまうなら、落ちどころの見立てが違う)。
- **C2 誤爆が増えていない**: 案2a・案2b とも M2 = 0 であること。
- **C3 実装に触っていない**: `axes/image_axis/schedule_tables.py` の差分が 0 行。

## 5. 採否の線(**先に引く**)

- **C1〜C3 が通り、どちらかの案で M1 がいまのままより増え、M2 = 0** →
  **その案を実図面で測る候補として PC 側に渡す。実装には入れない。**
- **両案とも M1 が増えない** → **両方とも捨てる。** 見出しの形の問題ではない。
- **M2 > 0** → **その案は捨てる。** 誤爆を持ち込まない。
- **実装を入れるかどうかは、PC 側が実図面で 3 つの線を測ってから決める。**
  合成で増えたことは、実図面で増える理由にならない(27〜31周目の語彙と同じ)。

## 6. この周でしないこと

- `寸法` や `W×H` のような**まとまった寸法欄**を読むこと。
  **どちらの案でも当たらない。** 別の周の話である。
- 実装を変えること。**判定のしかた・階層の条件・許容差には触らない。**
- 実図面で測ること。
