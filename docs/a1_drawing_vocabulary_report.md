# 19周目 報告: 図面そのものの文字から語彙を作る(**採用**)

2026-09-23。基準は `docs/a1_drawing_vocabulary_criteria.md`(測る前にコミット済み、`bb3f8f8`)。

## 今回の対象

**語彙の出どころ。** 14〜18 周で、記号を数える行に届くかどうかは
**語彙だけで決まる**ことが分かっていた。その語彙は当て推量(15 周目)か
公開されている基準(16 周目)から来ていて、**どちらもその図面を見ていない。**

## 13 周目の結論を読み直した(これが今回の出発点)

13 周目のキラークエスチョンの答えは「**この図面から記号の名前は自動で取れない**」だった。
**しかし 13 周目が測っていたのは「形と名前の対応」である。**

**個数を数えるのは人である**(14 周目に決めた)。
**人が数えるなら、形と名前の対応は要らない。語彙だけあればよい。**

> **13 周目が失敗したのは対応づけであって、語を拾うことではなかった。**
> **語だけを拾う試みは、19 周目まで一度もしていなかった。**

## 試したこと

22 ページ(「凡例」の語があるページのうち図形がいちばん多い)の文字を、
**測る前に決めた機械的な規則**で語に切って全部拾った。

- 空白・記号・句読点・数字で切る
- 正規化して 2 文字未満・10 文字超・数字だけ・英字 1 文字は捨てる
- **出現回数では絞らない。残ったものを全部語彙にする**

**正解ファイルは一切見ないで作った。** 採点にだけ `trigger_terms` を使っている
(17・18 周目と同じ。`usage_policy` に沿う)。**拾った語はここに書かない。**

### 対照1 と 2 が、今回いちばん大事な 2 つである

- **対照1**: 33 ページの文字 105 語は、記号の行に **1 行しか届かず、正しく当たったのは 0**。
  それでいて**誤爆は本測定より高い**(0.375 対 0.333)。
  **「どのページの文字でもいい」ではない。22 ページの文字であることが効いている。**
- **対照2**: 34 ページ全部から 976 語を拾うと、届く行は **23 / 26** まで増える。
  **しかし誤爆が 0.875 になる。** 面積の行の 30 / 40、文字の行の 21 / 24 に当たってしまう。
  **届いた行を増やすだけなら簡単だが、それは「選べていない」のと同じである。**

## 判定と理由

**採用。**

採否の基準(8 節)を満たしている。

- R1 = 20 ≥ 19 ✓ / R2 ÷ R1 = 0.750 ≥ 0.737 ✓ / R3 = 2 ≤ 2 ✓
- **R4 = 0.333 < 0.365 ✓**(**ただし、ぎりぎりである**)
- 対照1 が本測定より低い ✓ / 対照3 の平均 2.00 < 7.5 ✓ / 対照4 一致 ✓

**言えること**

1. **その図面自身の文字が、いちばん良い語彙の出どころである。**
   当て推量(15 周目)・公開基準(16 周目)より、届く行も正しさも上だった。
2. **13 周目の結論は「形と名前の対応」についてだった。**
   **「この図面から記号の語彙は取れる」。** 6 周のあいだ、この区別に気づいていなかった。
3. **誤爆は知識の語彙の 2 倍ある**(0.333 対 0.167)。基準は満たしたが**ぎりぎり**で、
   **このまま語を増やす方向へ進むと、対照2(0.875)の側へ落ちる。**

## 次の周(20 周目)の対象

**「届いた行を増やす」方向はここで止める。** 対照2 が示したとおり、
増やすだけなら 23 / 26 まで行けるが、それは何にでも当たる語彙である。

20 周目は **2 つの語彙の交わり**を測る。**先に基準に書いてから測る。**

- 図面の文字(226 語)と知識の語彙(61 語)の**両方に出てくる語**だけを使う。
- 見立て: 届く行は少し減るが、**誤爆が大きく減る**はずである。
- **外れたらそのまま報告する。**
