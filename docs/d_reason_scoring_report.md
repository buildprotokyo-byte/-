# 67周目の報告: **出した行を正解に突き合わせ、当たり外れを理由別に数えられるようにした**

2026-09-23。基準は `docs/d_reason_scoring_criteria.md`(**測る前にコミット済み**)。
測定は `benchmarks/measure_reason_scoring.py`、数字は `docs/d_reason_scoring_result.json`。

**合成の正解と合成の図面だけで測った(取り決め④)。実案件は PC 側(Codex-A)。**

---

## 1. なぜ要ったか

66周目で行に決め手が付いた。**だが、採点そのものが行を見ていなかった。**
いまの採点(`benchmarks/run_golden_eval.py`)は、図面の文字に正解の
`trigger_terms` が出るかを見ているだけで、**当てはめが出した見積の行とは
一度も突き合わせていない。** だから「当たった行・外した行を理由別に」が出せない。

## 2. 結果

| 記号 | 数字 |
|---|---|
| M1 言い当てた項目数 ÷ 正解の項目数 | **1 / 8 = 0.125** |
| M2 当たった行の決め手別 | 観測 1 件(外した行 0 件) |
| M3 出せなかった項目数 | **7 件** |

対照は **3 つとも通った**。

- **C1 緩めていない**: 工事内容が 1 文字違う正解も、単位が違う正解も当たりにしない。
  単位の表記のゆれ(`㎡` と `m²`)だけは吸収する。
- **C2 壊し試験**: 突き合わせの鍵を壊すと、当たった行 1 → **0**、割合 0.125 → **0.0**。
- **C3 二重に数えていない**: 理由別の合計 1 + 決め手の無い行 0 = 行の総数 1。

**採否: 採用。** 判定のしかたを変えない追加なので、全件テストと CI が通ればマージする。

## 3. **正直に書いておくこと**

- **M1 = 0.125 は「仕組みが動いた」以上の意味を持たない。** 正解はこちらで
  合成して作ったもので、**合成の図面からは行が 1 行しか出ない。**
  基準にも先に「M1 の高さは採否に使わない」と書いてある。
- **外した行が 0 件なのは、そもそも出した行が 1 行しかないから**である。
  「間違った行を出さない仕組みができた」ではない。
- **実案件の M1 は PC 側(Codex-A)が出す。** こちらは口を作っただけ。

## 4. 何を作ったか(`estimating/scoring.py`)

- `score_lines(lines, golden_items)` … **行と正解だけ**を受け取る。読み取りも
  当てはめもしない。**抽出と採点を分ける構えを崩さない。**
- 突き合わせの鍵は **「正解に符号があれば符号」「無ければ(工事内容, 単位)の完全一致」**だけ。
  **部分一致も、似ている語で寄せることもしない。**
- **数量の値は見ない。** ここが言うのは「その行が出せたか」だけである。
  値の当たり外れと混ぜると、**「出たけれど値が違う」が見えなくなる。**
- `load_golden_items(path)` … 正解からは**名前・単位・符号しか読まない。**
  数量も単価もこの層に入れない(ゴールデンの運用規則)。
- 出る数え方: 言い当てた項目数 / 正解の項目数 / 出せなかった項目数 /
  当たった行 / 外した行 / **理由別** / **決め手の無い行**。
  **既存の指標は 1 つも消していない。**

## 5. 「外した行」の意味

**正解にあるのに出せなかった項目**と、**出したのに正解に無い行**は別物なので、別に数える。

- 出せなかった項目 → `missed_items`。理由は `not_obtained_counts()` の側で数える
  (記号が読めない / 面積が出せない / ルールが無い / 現地確認が必要)。
- 出したのに正解に無い行 → `extra_lines`。**これが「外した行」**で、決め手が付いているので
  **理由別に数えられる。「どの決め手が間違った行を出しやすいか」が見える。**
