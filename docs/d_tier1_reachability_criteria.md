## キラークエスチョン

> **いまの設計とこの図面で、自動確定(階層1)が 1 件でも出る道はあるのか。**
> **あるとしたら、最低限なにが変われば届くのか。**

**これは「どう直すか」ではなく「そもそも届くのか」を聞いている。**
届かないなら、**直す場所を探し続けること自体が間違い**になる。

## コードから読んだ、階層1の必要条件(**記録ではなくコードを読んだ**)

`arbitration/axis_quality_firewall.py:443-462`。

1. **`usable_sources` が 2 つ以上**。`usable_sources` の鍵は `independence_key`
   (= `source_fingerprint or source_id`、同ファイル 160-162)。
   **同じデータ源の複数手法は重複加算されない**(349-356)。
2. **ハード適格**であること。`calibrated=True` かつ `strength="strong"`。
   **登録簿(`arbitration/method_policies.py`)が上限**で、**引き上げは絶対にしない**(154-160)。
3. **z3 が矛盾しない**(`solve_result.status != "unsat"`)。
4. **中心値が離れていない**(`_centers_disagree`)。

**いま 4 手法すべてが `calibrated=False` である。** だから条件 2 で全部落ちる。
**では校正さえ済めば届くのか。それを測る。**

## 測るもの

実図面(匿名化 v2)に対して、**本番の入口** `intake.drawing_intake.read_drawing` を
3 通りで回す。**製品コードには 1 行も触らない。反実仮想はベンチマークの中だけ。**

| 記号 | 条件 |
|---|---|
| **G0** | いまのまま(スタートキット無し) |
| **G1** | **仮の人の入力**を 1 つ入れる(基準点 1 つ。**印字された縮尺とぴったり合う値**にする) |
| **G2** | G1 + **4 手法すべてを `calibrated=True` にした世界**(登録簿をその場で差し替える) |

**G1 の人の入力は本物ではない。** 図面に印字された縮尺から逆算して作った
**「人が完璧に入れた場合」**である。**これは最良の場合を測るためのもので、
この値が正しいと主張するものではない。**

| 記号 | 何を測るか |
|---|---|
| **Z1** | 仲裁層に届いた対象の数(G0 / G1 / G2) |
| **Z2** | **独立したデータ源(`independence_key`)の異なる値の数**(G0 / G1 / G2) |
| **Z3** | **階層1(自動確定)の対象の数**(G0 / G1 / G2) |
| **Z4** | 階層2・階層3の内訳(G0 / G1 / G2) |
| **Z5** | **2 つ以上の独立したデータ源が同じ対象を主張している対象の数**(校正と無関係の上限) |
| **Z6** | Z3 が 1 以上のとき、**どの対象が、どんな一致で通ったか** |

**出すのは件数と対象名の形だけ。図面に印字された文字・室名・数量は出さない。**

## 結論の形(**測る前に決める。結果を見てから変えない**)

- **Z5 = 0** → **校正は目標に効かない。壁は独立性である。**
  校正を何件済ませても階層1は 0 のままなので、**次に問うのは
  「2 つ目のデータ源を実際にどう入れるか」**になる。
- **Z5 ≧ 1 かつ Z3(G2) = 0** → **独立性はある。だが校正以外にも壁がある。**
  z3 の矛盾か中心値の検査か、**どちらが止めているかを名指しする。**
- **Z3(G2) ≧ 1** → **校正が本当の壁で、その大きさは Z3(G2) 件である。**
  **そのうえで Z6 を見る。** 通った一致が
  **「人が入れた値と印字された縮尺がぴったり合っただけ」**なら、
  **それは記憶が「危ない裏返し」として名指ししている形そのもの**なので、
  **改善ではなく危険として報告する。**

**Z3(G2) の件数を「改善の見込み」として報告してよいのは、Z6 がその形でないときだけ。**
