## 1. 作成したテストケース(6セット以上)と正解値

実在しない改修工事6件を自作した。企業名・個人名・住所は一切使っていない。
各セットは **概要ページ1枚 + 詳細ページ4枚** を核とし、詳細ページには
「詳細は別紙による」「図示による」のように、概要を見ないと解釈が決まらない記載を意図的に入れた。
さらに各セットに **おとりの数字**(工事対象外の部分まで含んだ合計値、別棟・別階の参考図、過去の工事の実績表)を混ぜた。

| セット | 内容 | 基準寸法 | 工事対象範囲 | 現況 | おとり |
|---|---|---|---|---|---|
| S1 | 分譲共同住宅 住戸内装改修 | 1グリッド=910mm | リビング+廊下のみ | 全面撤去のうえ張替 | 住戸全体の床面積 39.75 m2 |
| S2 | 事務所ビル 基準階 天井・照明改修 | 基準スパン 3,600mm | A・Bゾーンのみ | 既存天井は撤去せず直張り | 基準階 全ゾーン 427.68 m2 |
| S3 | 戸建て住宅 外壁塗装改修 | 軒高 6,400mm | 北面・東面のみ | 北面のみ全面剥離処理 | 4面の展開面積 209.66 m2 |
| S4 | 物販店舗 床張り替え | 内法(mm)表記 | 売場のみ | 置敷きのため下地補修なし | 店舗全体 324.00 m2 / 契約面積(壁芯) 320.00 m2 |
| S5 | 共同住宅 共用廊下 防水改修 | 基準スパン 3,200mm / 有効幅 1,500mm | 2〜5階のみ(1階ピロティ除外) | 撤去せず密着工法で被せる | 全階合計 192.00 m2 |
| S6 | 学校校舎 建具更新 | 符号表 W-1 1,800×2,000 ほか | 1階・2階のみ | 枠残しカバー工法 | 全校舎 建具面積 112.50 m2 |

各セットに設問を3問置いた。設問の狙いは3種類に分けてある。

- **scope**(各セットQ1、計6問): 工事対象範囲が分かれば解ける。おとりの合計値を使うと外れる。
- **condition**(各セットQ2、計6問): 現況が分かれば解ける。5セットで正解が 0(撤去しない/補修しない)。
- **extra_rule**(各セットQ3、計6問): **概要ページに書いてあるが、3つの根本要素のどれでもない数え方の決まり**が要る。
  例: S1「巾木は室内周長から出入口1箇所につき0.90mを控除」、S2「照明は天井改修面積10㎡につき1台・切り上げ」、
  S3「1箇所3.0㎡未満の開口は控除しない」、S4「外部出入口には見切り材を計上しない」、
  S5「立上りは手すり側のみ高さ0.30m」、S6「カバー工法は幅・高さからそれぞれ100mmを減じる」。
  この3種類目は、**2段階読みが何を落とすかを測るために置いた**。

正解値18個は資料を作った時点で確定し、`two_stage_reading_key.json` に書き出して、
**読み取りを1本も走らせる前に**コミット・プッシュした(commit 6534039)。以後この値は一切変えていない。

### 難易度
概要ページの「量」と「書き方」だけを変えた3段階を用意した。中身の数字・範囲・現況は3段階で同一である。

- **難易度1**: 5ページ(概要1 + 詳細4)。概要は番号付きの箇条書き。
- **難易度2**: 24ページ。詰め物ページ(共通仕様書・安全衛生・工程表など)と、別棟/別階/過去実績の数字で薄めた。**今回は未実施**(5節)。
- **難易度3**: 25ページ。難易度2の概要1ページを、**同じ中身の特記仕様書の散文2ページに書き換えた**もの。
  「基準寸法」「工事対象範囲」「現況」という見出し語は一つも出てこない。
  数字の中身が箇条書き版と同一であること、詳細ページ23枚が難易度2と同一であることはテストで固定した。

### ブラインド性
- 設問文を作る経路(`prompts`)は正解値に一切触れない。正解に触れるのは採点(`score`)だけで、こちらは凍結済み JSON を読む。
- 読み手には「指定した1ファイルだけを読み、検索はしない」と指示した。資料中に正解値は出てこない
  (詰め物ページに正解値が数として現れないことを、数字の境界を見る正規表現でテストにしてある)。

## 3. 曖昧な記載箇所での、両方式の解釈の違い

指示書が狙っていた「概要を見ないと解釈が決まらない箇所」は、**scope と condition の設問がそれにあたる**。
この2種類では、**方式Aも方式Bも全問正解で、差がつかなかった**(難易度1・3とも A 36/36、B 36/36。Aの棄権1件を除く)。

方式Aは、おとりを使ってしまうことを期待して置いたが、実際にはほぼ引っかからなかった。
読み手の作業ログを見ると、たとえばS5で「全階合計 192.00 m2 は 38.4×5階で、除外した1階ピロティを含むので使えない」と
明示的に退けている。S2では「427.68 は A+B+C+D の合計で、対象は A+B のみ」、S4では「契約面積 320.00 は壁芯で、
指示は内法」と、おとりの正体を言い当てていた。**1段階読みでも、離れたページの記述を結びつける作業は成立していた。**

差がついたのは、指示書が明示的には挙げていない3種類目、**extra_rule** である。具体的な外れ方は次のとおり(難易度1・方式B)。

| セット | 落ちた決まり | 方式Bの答え | 正解 | 方式A |
|---|---|---|---|---|
| S2 | 照明は 10㎡につき1台・切り上げ | null ×3 | 28 台 | 28 ×3 |
| S5 | 立上りは手すり側のみ 0.30m | null ×3 | 30.72 m2 | 30.72 ×3 |
| S3 | 3.0㎡未満の開口は控除しない | **94.532 ×3** | 100.332 m2 | 100.332 ×3 |
| S4 | 外部出入口に見切り材は計上しない | null ×1 / **21.00 ×2** | 18.00 m | 18.00 ×3 |
| S1 | 出入口1箇所につき 0.90m 控除 | null ×1 / 正解 ×2 | 20.06 m | 20.06 ×3 |
| S6 | カバー工法は各辺 −100mm | 正解 ×3 | 65.14 m2 | 65.14 ×3 |

**危ないのは棄権(null)ではなく、S3とS4の方である。** ここでは方式Bは黙らずに、
「開口はすべて控除する」「見切り材はすべての境界に回す」という**もっともらしい一般則**で穴を埋め、
自信を持って違う数字を出した。94.532 も 21.00 も、決まりを知らない人が計算すれば普通に出てくる値である。
**外れていることが、答えを見ただけでは分からない。**

## 4. 概要が確定できなかった場合の影響

指示書ステップ3の3番は「3要素が確定できなかったケースがあれば、その影響を報告せよ」だが、
**実測では『確定できなかった』と申告されたケースは1件も無かった。** 段階1の出力36本すべてで
`確定できなかった要素` が空配列だった(`docs/trial15_two_stage_reading_stage1.json`)。

それにもかかわらず、難易度1の段階2は13問外した。**この設問の作りでは、段階1の自己申告は損失を映さない。**
段階1は「3要素は全部取れた」と言い、実際3要素は取れていて、それでも下流が壊れている。
**「確定できたか」を段階1自身に聞く設計は、この失敗を検出できない。**

では何が起きたのかを、段階1の出力文に数え方の決まりが残っているかで調べた
(セットごとの語で判定: 巾木 / 照明 / 控除 / 見切 / 立上 / カバー)。

| 段階1の出力 | extra_rule の正答 |
|---|---|
| 決まりが残っていた | **20/21 (95.2%)** |
| 残っていなかった | **2/15 (13.3%)** |

**段階2の成否は、段階1がその決まりを書き写したかどうかでほぼ決まっている。**
難易度1と難易度3で成績が逆転したのも同じ理由である。段階1が決まりを引き継いだ割合は
難易度1で 5/18、難易度3で 16/18 だった。**散文の特記仕様書の方が、箇条書きより決まりを取りこぼさなかった。**
箇条書きでは3要素の見出しが立っているぶん、段階1が「見出しに当たるものだけ」を写して、
見出しの無い決まりを落としたように見える。

つまり損失は「概要が読めなかった」から起きたのではない。**「概要は読めたが、3要素という受け皿に載らない情報が、
受け渡しの時点で捨てられた」**から起きている。2段階読みの受け渡し様式が情報のふるいとして働いており、
**ふるいの目の大きさを決めているのが「3要素」という枠そのもの**である。

## 5. 制約・うまくいかなかった点

1. **方式Aが天井に張り付いた。これが今回いちばん大きな欠陥である。** 方式Aは 98.1% と 100.0%。
   伸びしろがほぼ無いので、**この実験は「2段階読みが精度を上げる」ことを検出できる作りになっていない。**
   測れたのは「下げる」方向だけである。**「効果が無かった」と読むのは言い過ぎで、正しくは
   「上がる証拠は得られず、代わりに下がる現象が出た」。**
   なお指標そのものは死んでいない(方式Bで実際に動いた)ので、「差を映せない指標だった」わけではない。
   上方向だけが測れていない。
2. **難易度2(24ページ・箇条書き概要)は未実施。** 設問文は生成済み。難易度1と3の間を埋める条件なので、
   「分量が増えただけでは何も変わらない」を確かめる対照として本来は要る。読み取りの回数を優先して落とした。
3. **難易度を足したのは、難易度1で天井を見たあとである。** 後出しで条件を足しているので、
   都合のいい条件を選んだのではないかという疑いは残る。これを抑えるため、
   **難易度3の結果を見たあとは条件を一切足していない**。また難易度3は概要の書き方を変えたもので、
   数字の中身が箇条書き版と同一であることはテストで固定した(両方式に等しくかかる変更である)。
   ただし**「書き方だけ」は厳密には正しくない**。散文にすると1ページが2ページになるので、
   概要の分量も一緒に増えている。分量と書き方のどちらが効いたかは分離できていない。
4. **方式Bに実装上の下駄を履かせている。** 方式Bには「どのページが概要か」を最初から教えている。
   実運用ではページの種別を判定する工程が要るが、本リポジトリに未実装である。
   **つまり方式Bは、本来必要な工程を人間が代行した状態で、それでも方式Aに負けている。**
5. **概要ページの位置を動かしていない。** 全条件で概要は資料の先頭にある。
   実際の図面では概要が途中に埋もれることがあり、その場合に順序が効く可能性は否定できない。未検証。
6. **3要素のうち「基準寸法」を単独で測っていない。** 設問は scope / condition / extra_rule の3種で、
   基準寸法は全問に共通の前提として効いている。**基準寸法だけが取れなかったときに何が起きるかは測れていない。**
7. **読み手はLLM(Claude Sonnet)であって、本リポジトリの実装ではない。**
   資料は図面画像ではなくテキストで、縮尺の読み取り・室の輪郭の取得といった
   実図面の本当のブロッカー(`docs/real_drawing_eval_report.md` 11-4節)は迂回している。
   ここで測ったのは「同じ読み手に、同じ情報を、違う順序と違う分割で渡したときの差」だけである。
8. **反復3回・6セット・条件あたり54問。** 難易度1のA(53/54)とB(41/54)の差は大きく偶然では説明しにくいが、
   難易度3のA(54/54)とB(53/54)の差1問には意味を置いていない。
9. **正解値の凍結は守った**が、その正解値を決めたのは資料を作ったのと同じ担当(Claude)である。
   資料の作り手と採点基準の作り手が分かれていない。

## 6. 結論

**「概要の3要素(基準寸法・範囲・現況)を先に確定してから詳細を読むと精度が上がる」という仮説は、この実測では支持されなかった。**

1. **精度は上がらなかった。** 難易度1で 98.1% → 75.9%、難易度3で 100.0% → 98.1%。両方とも2段階読みの方が低い。
   上がった条件は一つも無い。
2. **ただし「効果が無い」と断定はできない。** 方式Aが天井(98〜100%)に張り付いたので、
   **上がる方向を測る余地が最初から無かった**。この実験が示せたのは「下がる現象が実在する」ことまでである。
3. **3要素を先に確定すること自体は、害でも無駄でもない。** 方式A2(1段階のまま3要素を先に書き出す)は
   両難易度とも 54/54 で、方式Aと同等以上だった。**悪さをしているのは「3要素を書き出すこと」ではなく、
   「工程を分けて、詳細を読むときに概要を取り上げること」である。** この切り分けは方式A2を置いたから分かった。
4. **失われるのは、3要素に当てはまらない情報である。** scope と condition の設問は方式Bも全問正解した。
   落ちたのは数え方の決まり(控除・切り上げ・単位換算)だけで、段階1がそれを書き写したかどうかで
   段階2の成否がほぼ決まっていた(残っていれば 20/21、残っていなければ 2/15)。
5. **最も警戒すべきは、黙らずに間違えることである。** 決まりを落とした段階2は、棄権するとは限らず、
   一般的な慣行で穴を埋めて別の数字を自信を持って出した(S3 94.532、S4 21.00)。
   **出力を見ても外れていることが分からない。** 3段階確信度階層は「軸が黙ったこと」は拾えるが、
   「軸が自信を持って違う値を出したこと」は拾えないので、この失敗はそのまま通る。
   これは `docs/trial789_reproduction_report.md` 3-2節 で見つかった「重なる誤り」と同じ形の問題である。

### v8設計への反映についての提案(判断はおーちゃんに委ねる)

指示書は「効果があれば段階0.5として組み込む」としていたが、**この結果では、いま提案されている形での段階0.5の追加は勧められない。**
理由は上の3と4で、下がった原因が「工程を分けて概要を取り上げること」にあるからである。
代わりに、測れた範囲で言えることは次の2つに限られる。

- **もし段階0.5を入れるなら、概要を取り上げない形にする。** つまり方式A2の形(3要素を明示的に書き出させたうえで、
  資料は全部見せたまま数量に進む)。この形は今回の実測では方式A以上だった。ただし天井に当たっているので、
  「A2 の方が良い」とまでは言えず、言えるのは「A2 は害が無かった」までである。
- **受け渡しを「3要素」に固定する設計は、情報のふるいとして働く。** どの軸であれ、
  工程間の受け渡し様式を決めるときは、**その様式に載らない情報がどれだけあるかを先に測る必要がある**。
  今回はそれが設問の1/3(extra_rule 6問)を占めていた。

2. **方式Aの天井を壊す条件を作る**。おとりを強くするか、設問を増やすか、資料をさらに長くする。
   天井が下がって初めて「2段階読みが上げるか」を測れる。
3. **段階1の受け渡し様式を「3要素+数え方の決まり」に広げた方式B'を作り、方式Bと比べる。**
   4節の機構が正しければ、B' は B より上がるはずで、これは B の損失が「順序」ではなく
   「受け渡し様式」由来であることの直接の検証になる。
