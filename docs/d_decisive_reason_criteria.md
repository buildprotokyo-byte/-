# 66周目の基準: **見積の行 1 つを見て「何が決め手だったか」が分かるか**

2026-09-23。**測る前に書いてコミットする**(取り決め「計測の前に採否の判定基準を宣言する」)。

おーちゃんの指示(優先順1番):

> 今は「何行当たった」しか分からず、「なぜ当たったか」が分かりません。
> 以後のすべての判断がここに依存するので、技術を足すより先にこれを作ってください。

**64周目(PR #91)で入れたのは「どの規則・手法・軸・階層・処置で出たか」までで、
指示が求めている 5 つの区別は入っていない。** この周はその 5 つを行に持たせる。

---

## 1. 何を作るか(1 周で変えるのは 1 つ)

行 1 つに **「決め手」** を持たせる。指示の 5 つを区別できること。

| 決め手 | 何が要るか(**証拠が無ければ名乗れない**) |
|---|---|
| 観測だけで出た | 図面を読んだ値で、下の 4 つがどれも無いこと |
| 知識のルールが効いて出た | **どのルールIDか**(1 つ以上) |
| 複数の経路が一致して確度が上がった | **どの経路か(2 つ以上)** と、**独立しているかどうか** |
| 人の回答で確定した | **どの問いか**(問いの識別子) |
| 要約資料(メニュー)から探して見つかった | **どの項目か** |

取れなかったものも理由別に数えられること(記号が読めない / 面積が出せない /
ルールが無い / 現地確認が必要)。**「その他」は理由の説明が無ければ作れない。**

**判定のしかた・階層の条件・許容差・群合計・問いの選び方には触らない。**

## 2. 測る数字(固定の合成案件。実図面は PC 側)

固定の入力は 2 つ。どちらも**合成データのみ**(取り決め④)。

- **入力あ**: 本番経路。`tests/test_drawing_intake.py` の合成平面図を
  `read_drawing` → `quantities_from_intake` → `map_quantities`(同梱の見本規則)。
- **入力い**: 64周目と同じ固定の合成数量を `map_quantities` に通す。

| 記号 | 測るもの |
|---|---|
| M1 | 出た行のうち、**決め手が 1 つ以上付いている行の割合** |
| M2 | **5 種類のうち、本番経路が現に証拠を出せた種類の数**(0〜5)と種類別の件数 |
| M3 | 取れなかったものの**理由別の内訳**(件数) |

## 3. 対照(**通らなければ結論を出さない**)

- **C0 行が出るか**: 入力あ・いのそれぞれで行が 1 行以上出ること。
  **0 行の入力で M1 を出さない**(62周目に踏んだ失敗をくり返さない)。
- **C1 でたらめを断るか**: 証拠の欠けた決め手を作ろうとしたら必ず断られること。
  (ルールIDの無い「知識のルール」/ 経路が 1 本だけの「経路の一致」/
  問いの識別子の無い「人の回答」/ 知らない種類)
- **C2 欄が効いているか**: 決め手を作る関数を空を返すように壊すと M1 が 0 になること。
  **`rm -rf __pycache__` と `PYTHONDONTWRITEBYTECODE=1` を付けて測る。**
- **C3 既存の指標が動かないか**: 行数・確定件数・基づきの内訳が、変更の前後で 1 件も変わらないこと。

## 4. 採否の線(**先に引く**)

- **M1 = 1.00 かつ C0〜C3 が全部通る** → 採用。判定を変えない追加なので、
  全件テストと CI が通ればマージする。
- **M1 < 1.00** → **決め手の付かない行がどの種類かを名指しして報告する。**
  **空欄を既定値で埋めない。** 実装は出すが、マージは判断を仰ぐ。
- **C1 が通らない**(証拠の無い決め手が作れてしまう)→ **不採用。作り直す。**
- **C2 が通らない**(壊しても数字が動かない)→ **測れていない。結論を出さない。**
- **C3 が通らない** → **判定に触っている。取り下げる。**

**M2 は採否に使わない。** 5 種類のうちいくつ出せるかは、いまの本番経路の実力であって、
この周の出来ではない。**0 でも 5 でもそのまま記録する。**
**数字を上げるために、本番経路が出していない決め手を付けない。**
