# 63周目の基準: **人が「平面図」と宣言するかどうかで、出てくる数はどれだけ変わるか**

**測る前にコミットする。結果を見てから基準は変えない。**
62 周目は**対照の立て方を間違えて止まった**(`docs/d_second_case_intake_report.md`)。
**今回は対照を同じ経路の中で立てる。**

## 1. なぜこれを測るか

62 周目に止めたとき、こう見えた。

> **読み取りの関数が 90 件見つけられるところで、本番の入口は 5 件しか試していない。**

**これは不具合ではない。**入口は、縮尺が読めたページと人が「平面図」と宣言した
ページでしか円弧を試さないからである。**だが「宣言しなければどれだけ減るか」は
誰も測っていない。**人にどこまで入力を求めるかは、この数字が無いと決められない。

## 2. 測るもの

**同じ入口 `read_drawing` を、前提だけ変えて走らせる。**

| 組 | 渡す前提 |
|---|---|
| A | **何も渡さない**(62 周目と同じ) |
| B | **全ページを「平面図」と宣言する** |

これを **P011v2** と **2 件目の図面**の両方に当てて、次を数える。

| 記号 | 何を数えるか |
|---|---|
| M1 | 手法ごとの読めた件数(とくに `pdf_vector_door_arc`) |
| M2 | 階層ごとの件数 |
| M3 | 試せなかった手法があるページ数 |
| M4 | 建具表・仕上表の行数 |

## 3. 対照(これが通らなければ結論を出さない)

**C1: P011v2 の A 組が、62 周目と同じ数になること。**
すなわち `pdf_vector_door_arc` **5 件**、`pdf_text_area` **2 件**、
仕上表 **59 行**、試せなかった手法のあるページ **14 件**。

**同じ経路・同じ前提・同じファイルなので、ここは必ず一致する。**
一致しなければ測り方か実装が変わっているので、**結論を出さずに止める。**

## 4. 判定の分岐(先に決める)

- **B の円弧が A の 2 倍以上**
  → **「人が宣言するかどうかで、出てくる数が倍以上変わる」と結論する。**
  そのうえで、**宣言を既定でどう扱うかは判断待ちの札にする**(取り決め③・⑨)。
  **こちらでは既定を変えない。**
- **B の円弧が A と同じか、2 倍未満**
  → 宣言以外の何か(縮尺が読めない等)が塞いでいる。**それを名指しする。**
- **B で階層 1 が 1 件でも出たら**
  → **驚くべき結果。**何が届いたかを名指しし、写しでないことを確かめるまで
  「増えた」と呼ばない。

## 5. この測定で分からないこと

- **宣言が正しいかどうかは測らない。**全ページを平面図と宣言するのは
  **現実の入力ではなく、上限を見るための仮定**である。
  実際には平面図でないページも混じるので、**B は「宣言が完璧だったら」の数字**。
- 出た数量が**正しいか**は測らない。**正解が無い。**
- **図面の中身は報告にも記憶にも書かない。**
