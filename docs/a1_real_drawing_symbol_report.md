# 10周目: A-1(繰り返す図形から記号を数える)を実図面で測る — 測定と判定

作成: 2026-09-23。基準は `docs/a1_real_drawing_symbol_criteria.md`
(**測る前にコミットした。採否の基準は変えていない。**)

## 判定: **不採用**(この測り方・この使い方では)

**実図面では、群が出すぎるので「個数が合った」が証拠にならない。**

| | 的中 |
|---|---:|
| **本測定**(22・23・24 ページ、正解 66 行) | **0.652** |
| 対照3 記号の行が推奨していない 33 ページ | **0.682** |
| 対照3 記号の行が推奨していない 34 ページ | 0.500 |
| **対照4 でたらめな正解(1〜24 の乱数、100 回平均)** | **0.747** |

**本測定は、でたらめな正解と突き合わせたときより低い。**
電気の図面でないページのほうが高い。
つまり **0.652 という数字は、この手法が記号を数えられている証拠ではない。**

理由ははっきりしている。**正解の個数は 1〜24 の小さい整数で、
実図面では群が 674 個出る。** 1〜24 のどの整数も、674 個の中にはほぼ必ずある。
**合成図面で群が 6 個しか出なかったときは、同じ指標に意味があった。**
実図面で意味を失ったのであって、実装が壊れたのではない。

対照1(図形がほとんど無い 25・26 ページ)は合格(群 0 件)。
対照2(同じページを 3 回)も合格(3 回とも同じ)。

## 基準に書いた対照が 2 つとも壊れていた(測定中に作り直した)

**これがこの周でいちばん大事な記録である。**

| 基準に書いた対照 | 何が起きたか |
|---|---|
| 対照3「22 ページの群を 23 ページの正解と突き合わせる」 | **記号の行は 26 件とも 22〜26 ページを推奨している。** ページを入れ替えても突き合わせる正解の並びが同じなので、**本測定と必ず同じ数字になる**(実際 0.652 対 0.652) |
| 対照4「正解の個数を並べ替えて突き合わせる」 | 採点は多重集合として引き当てるので、**並べ替えても結果が 1 件も変わらない**(実際 0.652 対 0.682 は、並べ替えではなく採点の呼び方の違いによる) |

**どちらも「対照を回した」と書けてしまう形をしていた。**
一度は実際にその数字を出して「本測定と同じ」と読みかけた。
**対照が本測定と同じ数字を出したときは、まず対照を疑うこと。**

作り直した対照は、
③**記号の行が推奨していない図面ページ**(33・34 ページ、図形 13,618 個と 29 個)と、
④**でたらめな正解**(1〜24 の乱数を同じ件数、100 回)である。
**採否の基準(対照よりはっきり高いこと)は変えていない。**

## 凡例と突き合わせると群は 674 から 13 に減る

A-1 の合成図面での収穫は「**誤検出を止めているのは大きさの窓ではなく
凡例との突き合わせ**」だった。実図面でも同じことが起きる。

| | 群 |
|---|---:|
| 22・23・24 ページで出た群 | **674** |
| そのうち凡例と形が一致して名前が付いた群 | **13** |

**ただし、この 13 件を成績として出さない。**
この図面には**凡例だけのページが無い。**
凡例は電気の図面(22 ページ)の中に描かれている。
そこを「凡例のページ」として読ませると、
**図面の上で文字の右に図形が並んでいるだけの並びまで凡例として読む**
(296 件の「名前↔図形」が取れた。凡例の項目がそんなにあるはずがない)。
`pdf_repeated_symbols.py` の docstring が警告しているとおりの誤読である。

参考までに採点すると 8/66(0.121)で、これも**でたらめ対照と同じ**だった。

## 何が本当に足りないのか

**記号は数えられている。数えられていないのは「どれが何か」である。**

- 22 ページには図形が 37,675 個あり、群にまとめると 108 個になる。
  **記号の候補としては十分に出ている。**
- 足りないのは**名前**で、名前は凡例からしか来ない。
- **この案件の凡例は独立したページになっていない。**

だから次に要るのは、**検出の精度を上げることではなく、
「凡例の領域」を図面の中から切り出すこと**である。
図面の中の凡例は、
(1) 罫線の表になっていることが多い(この PDF は罫線の表が 34 ページで 107 個取れる)、
(2) 見出しに「凡例」「記号」と書いてある、
という 2 つの手がかりがある。**どちらも既に読める実装がある。**

## この測定で分からないこと(必ず書く)

- **名前で突き合わせていない。** 測ったのは個数の一致だけである。
  名前で突き合わせるには表記のゆれの手当てが要る(未着手)。
- **1 案件しか見ていない。**
- **見積の行が埋まるかは測っていない。**
- **「式」の 21 件には効かない**(この周は記号だけを見た)。
- **合成図面の成績は落ちていない**(実装を 1 行も変えていないため)。
  全件テスト **975 件パス**(1 件 skip、3 分 22 秒)。
- 図面の中身(記号の名前・位置・個数)はこの報告にも書いていない。

## 次の周

**凡例の領域を図面の中から切り出す。** 罫線の表の検出(既にある)を凡例に当て、
表の中の「名前↔図形」だけを凡例として読む。
これが効けば、群 674 → 名前付き十数件が**根拠のあるもの**になる。
効かなければ、電気の記号は**人に入れてもらう対象**に回る(9 周目と同じ結論になる)。

**キラークエスチョンは当てない。** この周は「数えられていない」ではなく
**「数えられているが名前が無い」**という、次にやることがはっきりした結果である。
鈍化ではない。
