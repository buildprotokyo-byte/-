# 図面に記入された寸法の数字を読む経路(2026-09-22 実装)

担当スレッド: 「寸法の数字を読む経路」。土台にしたコミット: `90fae24`(main)。
ブランチ `claude/read-dimension-text`。

この作業は、原則の一覧([principle_conformance_review.md](./principles/principle_conformance_review.md))
の **B-6「図面に書かれた寸法の数字と突き合わせて検算が無い」** に当たる。
一覧の追記が言うとおり、**おーちゃんの定め直しでこの項目の重みが増していた**
(「基準点が無くても、図面に書かれた寸法の数字から計算できるものは計算してよい」と
決まったが、その数字を読む手段が無かった)。

---

## 1. 着手前に、記録ではなくコードで確かめたこと

**寸法の数字を読む経路は、リポジトリに1つも無かった。** 一覧の記述と一致する。

| 読んだもの | 何を読んでいたか |
|---|---|
| `axes/image_axis/pdf_pages.py` | ページのラスター化と種別判定。`text` は持つが**誰も消費していない**(docstring にもそう書いてある) |
| `axes/image_axis/pdf_vector_symbols.py` | 表題欄の縮尺表記、面積のラベル2語、円弧の幾何 |
| `axes/image_axis/pdf_tables.py` / `schedule_tables.py` | 罫線の升目(建具表・内装仕上表)。**表の外の文字は見ない** |
| `intake/drawing_intake.py` の `_resolve_scale` | 読みは2つだけ(表題欄の印字・人が入れた基準点) |
| `intake/drawing_intake.py` の `_reference_dimension_findings` | 突き合わせる相手は**同じ2点から印字の縮尺で計算した長さだけ** |

**スキャン画像だけの問題ではなかった。** 文字データのあるベクターのページでも、
寸法線の数字は1件も読めていなかった。

## 2. 入れたもの

### 2-1. `axes/image_axis/pdf_dimensions.py`(新規)

`read_dimensions(pdf_path, page_index, *, phase, purpose_received)` が
そのページの寸法を返す。**数字と、それが指す2点の両方**がある。

対応の取り方は次の順である。

1. 行全体が数字(と単位)の文字だけを、位置と**書き方向**つきで拾う
   (`line["dir"]`)。`1/50`・`AW-1`・`GL+500`・`2FL` はここで落ちる。
2. 直線を集め、**両端に目印(寸法補助線・矢印・目印の線)がある区間**だけを
   寸法線の候補にする。目印とは「その線と同じ向きでない線が接している所」で、
   垂直な補助線でも 45 度の目印でも同じに拾える。連続した寸法
   (`910 | 1820 | 910`)は目印で区切った区間ごとに候補になる。
3. 数字の向きが線と平行で、線から離れすぎておらず、線に射影した位置が
   区間の中にあり、**区間の中央から大きくずれていない**ものを対応とみなす。
4. 長さの食い違う候補が2つ以上残ったら、**どちらも選ばずに落とす。**
5. **表の升目の中の数字と罫線は、候補から外す**(2-3 を参照)。

単位の決め方は、**表題欄の縮尺を一度も読まない。**

- 単位が書かれていればそれに従う(`mm` / `cm` / `m`、全角も)。
- 書かれていなければ、**建築図面として成り立つ縮尺になる側**に読む。
  `3640` を mm と読めば 1/50、m と読めば 1/50000 で、**1000 倍違う。**
  成り立つ縮尺の幅(`PLAUSIBLE_SCALE_MIN`=5 〜 `PLAUSIBLE_SCALE_MAX`=600)は
  **1000 倍より狭い**ので、両方が成り立つことは起こりえない
  (`test_the_plausible_scale_range_cannot_make_mm_and_m_both_valid` が固定)。
  どちらも成り立たない数字は落とす。
- **2桁以下の数字は落とす。** 通り芯の番号(`3`)と区別できない。

`page_scale_from_dimensions(page, *, tolerance)` がページの縮尺を返す。

- **`tolerance` に既定値を置いていない。** 許容差はこのリポジトリで1つに
  決めるべき値(v8 10章12項が未決)なので、2箇所目の基準値を作らない。
  入口が `CENTER_TOLERANCES["mm"]` 由来の値をそのまま渡す。
- **一致する読みが2件以上ないと返さない**(取り決めのルール3)。
- **平均は取らない。** 一致した読みのうち、平均にいちばん近い**実在の読み**の
  分母を採る。どの読みも主張していない数値を作らないため。
- 一致しなかった読みは `outlier_values_mm` に残す。捨てない。

### 2-2. `axes/reading/meaning.py`(既にあったものへの追加)

**意味の4欄そのものは、OCR のスレッドが先に main へ入れていた**
(`axes/reading/meaning.py`)。**同じものを2つ書いてしまったので、
こちらの版は捨てて main のものを使った。** 足したのは1つだけである。

`purpose_link` の印を2つに分けた。どちらも `is_complete` を False にする。

- `PURPOSE_UNESTABLISHED`(目的未確立) … 目的そのものが渡されていない(既存)
- `PURPOSE_RECEIVED_UNLINKED`(目的受領済み・結び付けは未実装) … **追加。**
  `Purpose` は渡されているが、その目的と個々の値を結び付ける経路が無い
  (原則3-2の二段階目が未実装)

目的の受け取り口(`Purpose`)は同じ日に main へ入ったので、**「受け皿が無い」と
「結び付けが無い」を分けて記録できるようになった。**
**方向性の自由記述を `purpose_link` に写していない。** 写すのは結び付けではない。
この点は下の「判断がほしいところ」1 に出してある。

### 2-3. 建具表の升目を寸法と読んでしまう不具合(実際に起きた)

最初の版は、**建具表のページで幅・高さ・数量の数字を升目の罫線と対応づけ、
升目の紙の上の長さを「その数字が指す長さ」として読んで、そのページの縮尺を
丸ごと誤っていた。** その結果、そのページの開き戸の抽出が止まった
(`tests/test_drawing_intake_schedules.py::test_the_door_arc_count_and_the_schedule_are_separate_targets`
が落ちて見つかった。想像ではなく実際の回帰である)。

直し方は、**既にある表の検出器に位置を聞き**(`pdf_tables.find_tables()`)、
その中の数字と罫線を寸法の候補から外す。表の数字は `schedule_tables` が読む。
罫線探索を自前で作り直していない。

### 2-4. 入口(`intake/drawing_intake.py`)への接続

1. **縮尺の読みが3つになった。** 表題欄の印字、人が入れた基準点、
   **図面に記入された寸法**。食い違えばどれも採らず、そのページを未確定にする。
   一致したときの優先は「人の入力 → 記入された寸法 → 印字」。
   **記入された寸法を印字より先にするのは**、印字が用紙の拡大縮小を保証しない
   のに対し、記入された寸法から求めた比は保証するためである(原則3-1の1行目)。
2. **人が入れた基準点の検算**(原則3-1の最後の1行)。人が指した2点を、
   記入された寸法から求めた縮尺で実寸に直した値を、同じ対象
   (`基準寸法::ページN::横`)の3つめの読みとして出す。加えて、人の入力と
   記入された寸法が食い違ったときは `PendingDecision` の種類を
   **`human_input_vs_dimension_disagreement` に分ける**。表題欄との食い違いは
   「印刷のときに拡大縮小されたかもしれない」だが、寸法との食い違いは
   「指した2点か入れた長さが違うかもしれない」で、人に伝える中身が違う。
3. **記入された寸法そのものを数量として出す**(`寸法::ページN::向き::(x,y)-(x,y)`)。
   意味の4欄と根拠(ページ番号・座標・元の文字列・単位の決め方)を付ける。
   対象名は**連番にしない**(読める寸法が1件増えると他の名前がずれる)。
4. `PageOutcome` に `dimension_readings` と `dimension_scale` を残す。
   読まなかった数字の件数も `notes` に残す。

`DrawingFinding.meaning` は **`None` を許してある**。既存の読み(面積・開き戸・
建具表)は「修正のついでに順に入れる」という 2026-09-22 の判断に従い、
一斉移行はしていない。**`None` は「意味が無い」ではなく「まだ付けていない」**である。

`rm -rf __pycache__` と `PYTHONDONTWRITEBYTECODE=1` を毎回かけて実施した。

**やってみて分かった2つを、そのまま書いておく。**

- 2 と 5 は、**最初の壊し方では落ちなかった。** 2 は「目印が2つ無ければ捨てる」の

  ループが担っていた)、5 は一致した読みの分母がどれもぴったり同じだったため
  平均と実在の値が一致していた。**5 はテストが判別できていなかったので、
  許容差の中でわずかにずれた読みを1件足してテストを直した。**
- 8 は登録簿だけでは落ちない。入口が証拠に `"calibrated": False` を書いて

## 6. 拾えないもの(0件は「寸法が無い」ではない)

- **スキャンしただけのページ。** 文字が画像なので1件も読めない。
  **実案件 P011 は34ページ全部スキャンなので、この案件では1件も読めない。**
  スキャン図面の文字読み取り(OCR)は別スレッドの作業である。
- 文字が寸法線に平行に入っていない図面。
- **寸法線を横切る線があるページ。** 横切りを両端の目印と区別できないので、
  測る区間が短く取られることがある。**この誤りは1件では気づけない。**
  ページ内の突き合わせで外れとして出ることを当てにしている。
- 表の外にある、罫線で囲まれた注記の中の数字(表として検出されれば外れる)。
- 2桁以下の寸法。

**合成 PDF でしか確かめていないので、実図面での誤り率は未知である。**

## 7. Codex 側で測るべき項目

1. **数字と寸法線の対応の適合率・再現率**を、文字データのある実図面で。
   とくに「寸法線を横切る線」がどれだけあるか、そのとき区間がどれだけ短く
   取られるか。
2. **単位が書かれていない数字の取り違え**。成り立つ縮尺の幅(5〜600)で
   落ちる図面(詳細図・配置図)がどれだけあるか。
3. **ページの縮尺の一致率**。記入された寸法から出した比が、表題欄の印字と
   どれだけ一致するか。**食い違ったとき、どちらが正しかったか**まで見る
   (P011 では印字が実効と違っていた)。
4. **人が指す2点の位置の誤差**(既に挙がっている項目)。この検算が
   ±5% の許容差で意味を持つかは、そこで決まる。
5. **実行時間**。寸法が多いページでは、寸法ごとに1つの対象ができるので、
   仲裁層への要求がページあたり数十件になる。34ページ規模での時間を測る。

## 8. 判断がほしいところ

1. **意味の4欄を必須にすると、`purpose_link` が誰も埋められない。**
   目的の受け皿(`Purpose`)は入ったが、**目的と個々の値を結び付ける経路が
   無い**(原則3-2の二段階目が未実装)。いまは「目的未確立」「目的受領済み・
   結び付けは未実装」の印を置き、`Meaning.is_complete` を False にして
   **数量は出している。**
   これは原則2の2行目「意味が付けられない値は、数量に使わない」を緩めている。
   **推奨: いまのまま(印を置いて出す)。** 厳格にすると、目的の二段階目が
   入るまでこの経路から出る数量が0件になり、原則5「前提が揃うまで止めるのでは
   なく、何に基づくかを区別して出す」と正面からぶつかる。
2. **`phase` が「不明」のときも `is_complete` を False にしている。**
   人がページの種類を宣言していないページでは全部の寸法がこうなる。
   「不明」を意味が付いていない扱いにするかは、数え方の問題として決めてほしい。
   **推奨: いまのまま。** どれが本当に意味の付いた値かを数えられるほうが後で効く。
3. **表題欄の印字だけに頼って出した長さを「仮説に基づく」にする**
   (おーちゃんの追補)。**この PR には入れていない。** 既存の由来
   (`derivation`)の付け方を変えるので、原則の一覧も「判定が変わるので別の PR で
   扱う」としている。入れる場所は `_door_arc_findings` と
   `_reference_dimension_findings` の `pdf_text_scale` の2箇所である。
4. **記入された寸法を、数量として出し続けるか。** いまは1本ごとに1つの対象に
   なるので、寸法の多いページでは対象が数十件になる。見積の行には当たらない
   (規則が `寸法` を条件にしていない)ので害は無いが、量が多い。
   **推奨: 出し続ける。** 読めた値を出さないのは、この作業が直した「読んでいるのに
   誰も消費しない」形に戻ることになる。
