# 62周目の基準: **2件目の図面を、いまの読み取りに通すと何が出るか**

**測る前にコミットする。結果を見てから基準は変えない。**

## 1. なぜこれを測るか

2026-09-23 に 2 件目の案件(図面と原価表)が届いた。
**1 件でしか測っていない数字は、その 1 件の話でしかない**
(`docs/a1_one_case_killer_question_report.md`)。
**まず、いまの本番の入口に通して何が出るかを見る。直すのはその後である。**

## 2. 測るもの

本番の入口 `intake.drawing_intake.read_drawing` を **2 件目の図面**に当てて数える。

| 記号 | 何を数えるか | 予想 |
|---|---|---|
| M1 | 読み取りが出した数量の件数(手法ごと) | 円弧は出る。文字を使う手法は **0** |
| M2 | 階層ごとの件数(階層1 / 2 / 3) | **階層1は0件** |
| M3 | 試せなかった手法があるページ数 | 1 以上 |
| M4 | 建具表・仕上表の行数 | **0**(文字が画像のため) |

## 3. 対照(これが通らなければ結論を出さない)

**C1: 同じ測り方を P011v2 に当てて、既知の数字が再現すること。**
具体的には**開き戸の円弧が 90 件**(35 周目・55 周目と同じ)。

再現しなければ、**測り方が変わってしまっている**ということなので、
2 件目の数字も信用できない。**その場合は結論を出さずに止める。**

## 4. 判定の分岐(先に決める)

- **M4 = 0 かつ M1 の円弧 > 0**
  → **「この案件は形は読めるが文字が読めない」と結論する。**
  次にやるのは OCR を通す経路(PR #85 で入った 2 つ一致の既定が初めて効く)。
- **M4 > 0**
  → 予想が外れ。文字が画像だという見立てが間違っていたことになるので、
  `/mnt/project-files/.notes/inputs.md` の記述を訂正する。
- **M2 の階層1 > 0**
  → **驚くべき結果。**何がそこへ届いたかを名指しし、
  写しではないことを確かめるまで「増えた」と呼ばない。

## 5. この測定で分からないこと

- **原価表との突き合わせは測らない。**(対応付けの経路がまだ無い)
- 出た数量が**正しいか**は測らない。**正解が無い。**
  出るか出ないかだけの話である。
- **図面の中身は報告にも記憶にも書かない。**件数と手法の名前だけを出す。
