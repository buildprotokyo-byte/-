# K-24 報告: 上限を理由に置き換え、表題欄と図面リストの食い違いを出す

- K-23 の台帳(`axes/image_axis/candidate_ledger.py`)の続き。結果 `docs/k24_candidate_ledger_result.json`(件数と真偽だけ)。
- **判定・本番の入口には繋いでいない**(K-23 と同じ)。

## 1. 上限

上限を線・閉領域・小輪郭とも 10,000 にした(K-23 は 1,800・300・600)。上限は安全弁として残し、当たったらページに記録する。

| P011 匿名化v2 | K-23 の上限 | K-24 の上限 |
|---|---:|---:|
| 上限に当たったページ | 16 | **0** |
| 小輪郭を台帳に残した数 | 12,614 | **59,277(全部)** |
| 1 回の処理 | 9.2 秒 | 9.8〜9.9 秒 |
| 台帳の大きさ(JSON) | 1.9MB | 5.0MB |

v1(スキャン)も上限に当たるページは 16 → 0(12.0 秒 → 11.8〜12.2 秒、3.5MB → 3.9MB)。
別プロセスで 3 回処理して、68 ページとも件数と指紋が同じだった。キャッシュは 2 回目 34/34 ページで使い回し。

**捨てるのは理由で。**理由ごとの数をページに残す(`PageLedger.dropped`)。

| 理由(匿名化v2、34 ページの合計) | 数 |
|---|---:|
| 小さすぎる(点の汚れ。外接矩形の長いほうが 0〜1,000 の単位で 1 未満 ≒ 1.2pt) | 96,816 |
| 短すぎる線(長さ 10 未満) | 42,754 |
| 座標まで同じ線の重複 | 1,487 |
| 面積が小さすぎる閉領域(100 未満) | 811 |
| 線の塊の外形(線として持っている) | 35 |
| 上限を超えた | 0 |

**点の汚れが 9 万 7 千件ある。**中身は見ていない(ハッチングの点や記号の中の点が入っている可能性がある)。
「小さすぎる」の区切りは K-23 でこちらが決めた値で、実図面で合わせていない。「罫線と重なっている」のような理由はまだ作っていない(意味を当てることになるので、この段では入れていない)。

## 2. 回転(凡例の処理)

K-20 の凡例の処理(`claude/k20-legend-lookup` の枝、#124 と #125)をコードで確かめた。

- **対照表を作る処理は、回転を前提に書かれている。**6・22 ページは 270 度回転していて、文字が 90 度倒れて入る。対照表の道具は回転前の座標のまま「1 行 = 同じ x の縦並び」として読む作りで、升目の画像を切る道具は `find_tables` が回転後の座標を返すことを踏まえて切っている。**回転を直していないせいで凡例を読み切れなかった、ということは無かった。**
- **ただし照合する処理の側に 1 つずれがある。**表題欄を除く線引き(`TITLE_BLOCK_X = 75`、x が 75pt より左を捨てる)が**回転前の座標**で書かれている。これは 6・22 ページ(回転している凡例のページ)では表題欄に当たるが、**回転していない残りのページでは表題欄ではなく図面の左端の帯**を捨てている。
  - 回転していないページで、表題欄(表示の向きで下端の帯)の文字 **695 語が照合の対象に入っている**。そのうち名前が付いたものは 0 語。「事務所名・個人名が入るので数にも入れない」という約束は、このページ群では守られていない(文字は数えられているだけで、外には出ていない)。
  - 左端の帯の **177 語が捨てられている**。そのうち 2 語は対照表と一致する。
  - 表示の向きの下端の帯で表題欄を除くように直すと、**名前が付く件数は 135 → 137**。捏造は 0 のまま。
- この部品は検証ループのスレッドのものなので、**こちらでは直していない。**直し方(表題欄の線引きを表示の向きの座標にする)はそのスレッドに回す。

## 3. 表題欄と図面リストの食い違い

図面リストのページを自動で探し(図番の形をした語と名称が 5 行以上並ぶページ)、各ページの表題欄と突き合わせる。**どちらが正しいかは決めない。両方の値を並べてページに残す**(`PageLedger.title_conflicts`)。

| 食い違いの種類 | 匿名化v2 のページ | 品質ゲート |
|---|---|---|
| 名称の語が違う | **6** | needs_review(「表題欄と図面リストが食い違う」) |
| 名称の表記だけが違う(「・」や括弧) | 9・12・15 | 記録するが、それだけでは needs_review にしない |
| 図番の表記だけが違う(「-」と「ー」) | 22 | 同上 |
| 表題欄の図番が図面リストに無い | 0 | needs_review |
| 図面リストの枚目と、その図番が載っているページが違う | 0 | needs_review |

図面リストは 24 行読めて、24 行とも枚目と名称が付いた。**語が違う食い違いは全ページで 6 ページの 1 件だけだった。**
図番が無いページ(27〜30 など)は突き合わせられない。「食い違いが無い」とは書かない。

## 5. 凡例の照合をもう一度測る(台帳の前と後)

**台帳の図形が、名前が付く件数(135)に効く経路は今のところ無い。**135 件は、図面の文字と対照表の文字の完全一致で付いた名前で、図形を見ていない。照合の処理は台帳を読み込んでいない。だから台帳の前と後で **135 → 135、捏造 0 → 0、図形だけの 19 件は 0 → 0**(変わりようがない)。

代わりに、**経路の手前**(4 段のうち 1 段目「認識」)を測った。22 ページの凡例の「記号」の升目の中に、台帳の候補が 1 つ以上あるか。

| 升目の行 | 行数 | K-23 の上限 | K-24 の上限 |
|---|---:|---:|---:|
| 文字がある行(群A) | 61 | 47 | 51 |
| **図形だけの行(群B)** | **19** | **9** | **15** |
| 決まらない行(群C) | 6 | 3 | 6 |

- 図形だけの 19 件のうち、**台帳が見本の図形を持っているのは 9 → 15 件**に増えた。上限で捨てていたのが原因だった。
- 残り 4 件は、升目の中に収まる候補が無い(升目をまたぐ線はある)。原因は調べていない。
- **これは「名前が付いた」ではない。**凡例の見本の形を台帳が持っているというだけで、図面のどこに同じ形があるかを探す部品は無い。K-20 で形の重なりを試したときは「どの記号か」を見分けられなかった(対照 C6)。

測り方の道具は枝をまたぐ(升目の位置は `claude/k21-expert-reading` の `name_rows`)ので本線には入れていない。スクリプトは共有フォルダの `reports/K-24_凡例の升目と台帳.py`。
