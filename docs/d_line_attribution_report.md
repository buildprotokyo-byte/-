# 64周目の報告: **見積の行 1 つを見れば、何が効いたか分かるようにした**

基準は `docs/d_line_attribution_criteria.md`(**測る前にコミット済み**)。
測り方は `benchmarks/measure_line_attribution.py`。
**合成の数量と同梱の合成の見本規則だけで測った**(実案件での測定は Codex-A)。

## 1. 数字(**この周の数字は 1 つ**)

**行だけを取り出したときに「何が効いたか」を辿れる割合: 0.0 → 1.0**

| 欄 | 足す前 | 足したあと |
|---|---|---|
| 規則 `rule_id` | 0.0 | **1.0** |
| 手法 `method_id` | 0.0 | **1.0** |
| 軸 `axis_id` | 0.0 | **1.0** |
| 階層 `tier` | 0.0 | **1.0** |
| 処置 `action` | 0.0 | **1.0** |

(合成の数量 2 件から行 3 本)

## 2. 対照

| | 結果 |
|---|---|
| **C1**: 行の基づきの内訳が、足す前と 1 件も変わらないこと | **通過**(足す前・足したあととも「推論に基づく 3 件」) |
| **C2**: 欄をわざと空にしたら割合が 0 に戻ること | **通過**(5 欄とも 0.0) |

**C1 は、足す前のコードを `git show` で取り出してそのまま読み込んで比べている。**
記憶や印象ではなく、同じ案件を 2 つのコードに通した結果である。

## 3. 何を変えたか(**1 つだけ**)

`MappedLine` に 5 つの欄を足し、`as_dict()` に出した。値は
**その行を作った規則と、元になった数量**からそのまま運ぶ。
**作り直していない。**

これまで規則・手法・軸・階層は**木の形でしか無かった**
(`MappingResult` → `QuantityMapping` → `RuleOutcome` → `MappedLine`)。
**行だけを取り出す経路**(`settled_lines()`・`as_dict()`)を通ると全部落ちる。
**報告や見積に出るのはその形である。**

## 4. 測れていないこと

- **行が正しいかは測っていない。**辿れるかどうかだけである。
- **人が読んで分かるかは測っていない。**欄があることと伝わることは別である。
- **実案件では測っていない。**Codex-A の担当である。
- 金額・規則の中身・判定のしかたには触っていない。
  **自動確定の件数は 0 件のまま**(合成でも実案件でも)。
