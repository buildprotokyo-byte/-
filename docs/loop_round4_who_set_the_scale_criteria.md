# 周4の基準: 縮尺の基準を「誰が入れたか」を記録する

作成: 2026年9月25日。**測る前にコミットする。**

## おーちゃんの設計

> **周4 基準線を AI が決める。必ず「AI が基準を入れた」と記録すること。
> 人が入れたものと混ぜない。**

K-34 でも決まっている:

> **縮尺の基準となる長さは、本来は人が決める作業である。**
> この案件では人の入力が空のままなので、機械が印字と記入寸法で代わりに出している。

## 先に数えたこと(**コードを読んでから着手する**)

1. **人が入れたことになっている証拠は、本当に人の入力からしか出ないか。**
   → `METHOD_HUMAN_REFERENCE_POINT` を出しているのは `intake/drawing_intake.py` の
   1 か所だけで、**人の入力(`reference_points`)からしか出ない。混ざっていない。**
2. **誰が入れたかは、必ず残っているか。**
   → `ReferencePoint.entered_by` は**既定値が空文字で、空のままでも通る。**
   リポジトリで作っている 13 か所のうち 3 か所が渡していない(どれもテスト)。
   **止める仕組みは無い。**
3. **機械が出した縮尺には、「機械が出した」という記録があるか。**
   → `DimensionScale.provenance()` にも、表題欄から読む側にも、
   **「誰が(何が)入れたか」の欄が無い。**「未校正の手法である」とは書いてあるが、
   **人が入れたのか機械が出したのかは書いていない。**

## この周でやること

**記録を足すだけ。判定は 1 ミリも動かさない。**

1. **`ReferencePoint` は、誰が入れたかが空なら断る。**
   このリポジトリには既に**「出どころが無ければ断る」**という決まりがある
   (`knowledge/table.py` 2)。同じ考え方をそろえる。
2. **機械が出した縮尺の根拠に、「機械が出した」と書く欄を足す。**
   人の名前が入りうる欄と**別の名前の欄**にして、取り違えられないようにする。
3. **機械の欄に人を書けないことを、テストで固定する。**

## 測ること

### 線1(この周の採否)

**変更の前と後で、判定の出力が 1 か所も変わらないこと。**

- 合成の見本で、**足した欄を除いた全部の欄**を突き合わせる。
- **1 か所でも変われば、この周は失敗である。**記録のつもりで判定を動かしたことになる。
- **全件テストが通ること。**

### 線2: 空のまま通る道が残っていないこと

**誰が入れたかが空の `ReferencePoint` を作れないことを、失敗するテストで先に示す。**

### 線3: **この欄を読む場所は、いまのところ 0 か所である**

**それを報告にはっきり書く。**
`基準寸法` の独立性の但し書きが **provenance に残るだけで判定を 1 ミリも
動かしていなかった**件(K-02)と同じ形になりうる。

- **読む場所を作るのは、この周ではない。**
- **だが「0 か所である」と書かずに足すと、同じ轍を踏む。**

### 線4: 危ない裏返しに触れていないこと

`human_reference_point` と `pdf_text_scale` を校正済みにした瞬間、
**人が 1 回入れた値と印字の一致だけで階層1(自動確定)に届いてしまう。**

- **`calibrated` の値には触らない**(K-29)。
- **手法の一覧(`DEFAULT_METHOD_POLICIES`)を書き換えない。**
- 触れていないことを、変更の差分で示す。

## 書かないこと

- **自動確定は 0 件のままにする**(K-29)。
- **記録が増えたことを成果としない**(K-33)。
- **判定に触る材料が増えるので、PR のまま判断待ちに載せる**(K-06)。
