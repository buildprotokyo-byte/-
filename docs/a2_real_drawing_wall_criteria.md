# 6周目: 実図面の壁は 1 本線か 2 本線か — 測る前に決めた採否の基準

作成: 2026-09-23。**測定を始める前にこの文書をコミットする。**
結果を見てから基準を変えない(変える必要が出たら、変更と理由とコミットを残す)。
前提: `docs/decision_area_basis.md`(面積は芯々)、
`docs/a2_center_line_area_report.md`(合成図面では 7/7 で誤差 0.000)。

## なぜ測るのか

芯々の面積は、**壁が 2 本線で描いてあるときにしか図形から出せない。**
1 本線の図面には厚みがどこにも無い。
だから「合成図面で 7/7」という結果が実案件で何を意味するかは、
**実図面の壁がどう描かれているか**で決まる。
1 本線が大半なら、この実装で埋まる面積の行はごく一部にとどまる。

**この測定は実装の良し悪しを測るものではない。** 実装が実案件に届くかどうかを測る。

## 何を測るのか

対象は P011 の匿名化v2(27MB・A3・34ページ)。
**中身(室名・寸法・数量)は報告書にもリポジトリにも書かない。** 件数だけを書く。

| 指標 | 定義 | 分母 |
|---|---|---|
| 輪郭が取れた室 | `find_room_outlines` が返した面 | ページごと |
| 芯々を出せた室 | `area_basis == "壁芯"` になった面 | 輪郭が取れた室 |
| 出せなかった理由 | 「厚みが読めない辺」の本数の分布 | 芯々にならなかった室 |
| 長い線の相棒 | 長い直線のうち、平行で重なる相棒が近くにある本数 | 長い直線の本数 |

「長い線の相棒」は、室の輪郭が取れなくても**壁の描き方だけ**を見るための指標である。
室の輪郭が 0 件でも、この数字は出る。

## 先に決めておく採否の基準

この周の問いは「芯々の実装は実案件に届くか」である。

- **届く**: 輪郭が取れたページで、**芯々を出せた室が半分以上**。
  → 実装をそのまま進める。
- **壁の描き方で届かない**: 室は取れるが芯々が 0 件に近く、
  理由が「厚みが読めない辺がある」。
  → **壁の厚みを会社のルールとして決めてもらう必要がある。判断待ちに上げる。**
- **そもそも室が取れない**: 輪郭が 0 件。
  → 芯々以前の問題なので、6 周目の対象を輪郭の取り方に切り替える。

**どの結果でも実装を合成図面に合わせて調整しない。** 合成図面に合わせて窓を締めるのは
段階 A でテンプレートを合成図面の作図関数から作ったのと同じ誤りになる。

## 必ず回す負の対照(これを回さずに数字を報告しない)

1. **図面でないページ**(表紙・仕様書・写真のページ、図形が 30 未満のページ)。
   期待: 輪郭は 0 件。出るなら、出ている面は室ではない。
2. **同じページを 2 回読む。** 期待: 同じ件数。違えば非決定性がある。
3. **縮尺を 2 倍にして読む。** 期待: 芯々を出せた室の**数は変わらない**
   (面積は変わる)。数が変わるなら、判定が縮尺に引きずられている。

## この測定で分からないこと(報告に必ず書く)

- **1 案件しか見ていない。** P011 の描き方が業界の標準とは限らない。
  **1 案件の結果を「実図面はこうだ」と書かない。**
- 面積の**正しさ**は測れない。正解の面積が案件ごとに無い。
  測れるのは「芯々を出せたかどうか」だけである。
- ページの種類(平面図か否か)を図面から判定する手段が無いので、
  **図形の多いページをまとめて読む。** 平面図でないページが混ざる。
- 見積の行が埋まるかは測っていない。
