# トライアルB 多方向からのアプローチ — 測る前に決めた採否の基準

作成: 2026-09-23。**測定を始める前にこの文書をコミットする。**
結果を見てから基準を変えない(変える必要が出たら、変更と理由とコミットを残す)。

## 何を測るのか

同じ案件を、別々の向きから解いて、最後に突き合わせる。
突き合わせ役は `arbitration/multi_path_reconciler.py`。
**突き合わせ役は値を選ばない。** 一致・食い違い・片方にしか無いもの、の 3 つに
仕分けて、それぞれに独立したデータ源がいくつあるかを付けて返すだけ。

測るのは次の 4 つ。**合成図面の上での測定であって、実図面での成績ではない。**

| 指標 | 定義 | 分母 |
|---|---|---|
| 単独の経路の再現 | その経路 1 つだけで見つかった行 | 正解の行の数 |
| 合わせた再現 | どれか 1 つでも見つけた行(和集合) | 正解の行の数 |
| 誤った一致 | 2 経路が一致したが、値が正解から外れていた行 | 一致した行の数 |
| 取りこぼした食い違い | 値が食い違っているのに一致と判定した行 | 正解が食い違っている行の数 |

## 先に決めておく採否の基準

この周で確かめたいのは「経路を足すと埋まる行が増えるのか、それとも
同じ行を別の言い方で数え直しているだけなのか」である。

- **採用**: 合わせた再現が、**いちばん良い単独の経路の再現より大きい**。
  かつ**誤った一致が 0 件**、**取りこぼした食い違いが 0 件**。
- **保留**: 合わせた再現は上がるが、誤った一致か取りこぼした食い違いが 1 件以上出る。
  この場合、突き合わせは「候補を広げる」までで、根拠を強めるのには使えない。
- **不採用**: 合わせた再現が、いちばん良い単独の経路と同じかそれ以下。
  経路を足しても新しい行は埋まっていないことになる。

**どの結果でも、この層は数量を自動で確定させない。** 独立したデータ源が 2 つ
そろっても、どの手法も未校正なので、確定させるかどうかは仲裁層が決める。

## 必ず回す負の対照(これを回さずに数字を報告しない)

1. **同じ PDF を 2 つの手法で読んで一致させる。**
   期待: 一致にはなるが、独立したデータ源は 1 つ、`strengthened()` は 0 件。
   **ここで独立が 2 と出るなら、一致の数え方が壊れている。**
2. **わざと違う値を持たせた 2 経路。**
   期待: 食い違いになり、`agreed_range` が None(どちらも選ばない)。
3. **1 つの経路だけが出した行。**
   期待: 捨てられずに「片方にしか無いもの」として残る。
4. **経路を 1 つだけにして突き合わせる。**
   期待: 全件が「片方にしか無いもの」。一致は 0 件。
   一致が出るなら、同じ経路の複数件を別経路と数えている。

## 回数

条件ごとに 3 回走らせる。**3 回で分かるのは大きさと、ばらつくかどうかだけ。**
3 回とも同じ件数にならない場合は、非決定性の原因を先に潰す。

## この測定で分からないこと(報告に必ず書く)

- **実図面での成績は測れない。** 実図面 PDF はこの作業環境に無い。
- 経路のうち「上から(人の入力)」と「後ろから(見積の書式)」は、
  **この測定では合成した入力**である。実際に人が入れた値でも、実際の
  見積書式でもない。だから「人の入力があれば独立が 2 になる」は
  **仕組みとして通ることの確認であって、実案件での確認ではない。**
- 見積の金額は出していない。埋まるのは行と数量までである。
- 経路どうしを見せないで走らせる決まり(5 節)は、この測定では
  **経路が別々の関数で、互いの出力を引数に取らない**ことで満たしている。
  読む側が言語モデルになる場合は、この保証は別に要る。
