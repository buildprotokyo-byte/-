# 内壁面積が出なかったわけ — **天井高は図面に印字されている。読む口が無かった**

K-22 (d)。おーちゃんの指示「**6 ページの凡例の 14 項目のうち、c(天井高・室名・床高の並び)
から読んでください。内壁面積が出なかった原因がそこにあります。**」に答える。

**実図面の数値・室名はこの文書に書かない。**読み取った中身は共有フォルダに置く。

## 1. 凡例 c が何を決めているか(6 ページ「凡-1 意匠図凡例」)

**c.天井高・室名・床高**

- **3 段の枠**を室の中に置き、**枠内に記入する。**上から **天井高 / 室名 / 床高**。
- 凡例は例まで載せている(天井高さ ⇒ 4 桁の数、室名 ⇒ 部屋の名、床高 ⇒ 基準からの差)。
- 使う図面は **既存平面図・既存撤去図・改装平面図**の 3 つ。
- 但し書きが 1 つある。**スケルトンリフォームの場合は BM(ベンチマーク)を必ず表記し、
  FL=BM+○○ とする。原則、掃出窓下枠上端を BM とする。**

**つまり、天井高は「人が入れるもの」ではなく、図面が刷っているものである。**

## 2. この図面は c のとおりには描いていない

3 段の枠は、平面図のページからは**見つからない**(罫線の表として 3 行 1 列のものが 0 件)。
代わりに、**`CH=` で始まる注記**が平面図に置かれている。**5 ページに合わせて 71 か所**で、
改装平面図のページと既存平面図のページはそれぞれ 8 か所ずつ、残りは別の 3 ページにある。

**凡例が宣言した書き方と、図面が実際に使っている書き方が違う。**
K-20 で見つけた「凡例が宣言していない略字を本文で使っている」と**同じことが、
天井高でも起きている。**

## 3. なぜ内壁面積が出なかったか(**コードを読んで確かめた**)

| どこ | いま何をしているか |
|---|---|
| `intake/room_dimensions.py` | 天井高を**人の入力からしか受け取らない**(「人が室ごとに入れる」と冒頭に書いてある)。`ceiling_height_mm` が無ければ**壁の数量を出さない** |
| `axes/image_axis/printed_dimensions.py` | 裸の整数を**寸法の候補**として拾う。`CH=` の数も拾えてはいる |
| どこにも無い | **拾った数を「その室の天井高」に結び付ける経路** |

**天井高は紙の上にあり、数としては拾えている。ところが「これは天井高だ」と言う口がどこにも無い。**
だから `ceiling_height_mm` は常に人の入力待ちになり、人が入れなければ内壁面積は出ない。

**「読めなかった」のではなく「読む口が無かった」。**これは 1 段目(認識)ではなく
**3 段目(理解)の欠落**である → `docs/k21_reading_stages.md`。

## 4. 足すとどうなるか(**足す前に、おーちゃんの判断が要る**)

`CH=` を読んで室に結び付ければ、内壁面積の道は開く。**ただし、開けてよいかは別の話である。**

- **天井高に 2 つ目のデータ源ができる。**人の入力(スタートキット)と、図面の印字である。
  階層 1 は独立したデータ源 2 つを要求するので、**この 2 つが揃うと自動確定に届きうる。**
- ところが `docs/tier1_reachability_summary.md` に書いたとおり、**書き写した値だけが
  階層 1 へ通る**という欠陥がある。人が図面の `CH=` を見て同じ数を入れたら、
  **独立した 2 つの証言ではないのに一致として通ってしまう。**
- **だから、読む口を足すことと、それを独立した 2 つ目として数えることは、分けて決める。**
  この周では**読む口も足していない。**判断待ちに出す。
