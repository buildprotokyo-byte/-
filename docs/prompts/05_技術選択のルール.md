# 技術選択のルール(精度が上がらない所に、何を当てるか)v1

これは、実行中のAIではなく、**開発する側(Claude Code、Codex、おーちゃん)**が使うルールです。精度が上がらない所が見つかったとき、各業界で確立された技術の中から何を当てるかを、思いつきではなく手順で決めるためのものです。

全体の決まりはマスタープロンプト(統合版)に従います。どんな技術を入れても、第1章の原則(根拠の位置、単一の根拠で確定しない、分からないものを埋めない)は変えません。

---

## 1. 大原則
1. **診断が先、技術は後。** どこで、どんな種類の誤りが、どれだけ起きているかを測ってから技術を選ぶ。「流行っているから」「強そうだから」で選ばない
2. **測れない改善は入れない。** 固定の正解データと固定の採点基準で、入れる前と後を比べる。下がる変更、他を悪くする変更は入れない
3. **原則を壊す技術は、そのままでは使わない。** 根拠の位置を示せない出力(中身の見えない判定など)は、事実として扱わず、候補を出す道具としてだけ使う
4. **軽いものから試す。** 手順やルールの見直し → 知識の表の追加 → 決まった計算で確かめられる技術 → 学習するモデル、の順に検討する
5. **独立性を増やす技術を優先する。** 同じ画像を別の方法で読むより、別の情報源・別の手段で確かめられる技術の方が、確定の根拠を強くする

## 2. 手順

### 手順1 精度が上がらない所を特定する
異常検知AIの記録と、抜き取り検査・正解データとの照合から、次を特定する。
- どの役割か(認識/理解/最適解/異常検知)
- どの階層か(大/中/小)、どの班・どの要素の種類か
- どの誤りの種類か(下の分類)
- どれだけの件数と金額に影響しているか

### 手順2 誤りを分類する
| 誤りの種類 | 例 |
|---|---|
| 読めない | スキャンのかすれ、手書き、重なり |
| 読み違い | 数字の取り違え、単位の取り違え |
| 対応づけの誤り | 寸法の数字と寸法線、記号と表の行 |
| 構造の復元の誤り | 表の崩れ、部屋の輪郭、壁の連続 |
| 意味の取り違い | 既存と新設、撤去と改修 |
| 漏れ | 読み落とし、波及の漏れ、工種の漏れ |
| 作り話 | 根拠の無い項目 |
| 組み立ての誤り | ルールの適用、換算、丸め |
| 前提・ルールの欠け | 会社のルールや案件の前提が無い |
| 同じ誤りの一致 | 2つの根拠が同じ誤った値 |
| 速度・費用 | 計算が終わらない、費用がかかりすぎる |

### 手順3 原因の仮説を立てる
「なぜその誤りが起きるか」を、なぜを繰り返して掘り下げる(なぜなぜ分析)。原因を、入力(図面の質)、手段(方法の限界)、知識(ルールの欠け)、構造(役割の境目・受け渡し)のどれかに寄せて考える。原因が分からないまま技術を選ばない。

### 手順4 技術の候補を挙げる
下の対応表から、誤りの種類と原因に合う候補を2〜3個挙げる。それぞれについて、次を書く。
- 何を解決するはずか
- 原則との相性(根拠の位置を出せるか、独立した根拠になるか)
- 手間と費用(作業環境で動くか、時間はどれくらいか)
- 失敗したときに何が悪くなり得るか

### 手順5 小さく試して、測る
- 固定の正解データの一部で試す。入れる前と後の差を、件数と分母つきで出す
- 対象の誤りが減ったかだけでなく、他の指標が悪くなっていないかを必ず確かめる
- 数回の結果で偶然かどうかを断定しない。差の大きさと一貫性で判断する

### 手順6 採用・不採用を記録する
採用しても、しなくても、何を試し、どうなったかを記録する。不採用の記録は、同じ技術を何度も試す無駄を防ぐ。

## 3. 誤りの種類と、当てる技術の候補
ここに挙げるのは出発点の候補です。有効かどうかは、必ず手順5で測って決めます。

### 読めない・読み違い(認識)
- 画像の前処理:傾きの補正、二値化、ノイズ除去、解像度の引き上げ
- 文字データのあるPDFからの直接の取り出し(読み取りより確実な場合が多い)
- 数字・記号に特化した読み取りと、読みの確かさの出力
- 単位の桁の検算(同じ図面の他の寸法との比較)
- 注意:複数の読み取りエンジンの一致は、同じ画像を読んでいる以上、独立した根拠にならない

### 対応づけ・構造の復元の誤り(認識)
- 図形の幾何規則(寸法線の端点、引出線の向き、数字の配置)による対応づけ
- 表の構造の認識(罫線の検出、セル結合の推定)
- 線・壁の検出(直線の検出、形態の処理)と、部屋の領域の分割(閉じた領域の抽出、多角形化)
- 記号の検出(型の照合、物体検出)
- CADやBIMのデータが手に入る場合は、画像より優先して使う
- 基準点による補正:ページ全体の射影の補正、区画ごとの補正(写真測量の考え方)

### 意味の取り違い・漏れ(理解)
- 知識の表と規則による推論(波及のルール、軸ごとの問いの一覧)
- 建物の部材・工事の分類体系(BIMの分類、内訳書の標準書式、工種の分類)による用語の揃え
- 公開されている基準・施工要領からの根拠の検索と引用
- 施工順序に並べての抜け漏れ確認(工程の型)
- 故障モードと影響の分析(FMEA)の考え方で、工事ごとの「起こりがちな漏れ」を事前に一覧化する

### 作り話(全役割)
- 出力の形で、位置と根拠の欄を必須にする(欄が空なら受け付けない)
- 根拠の欄が本当に元の図面を指しているかの自動照合
- 仕組みでミスを防ぐ(ポカヨケ)の考え方:誤りが起きにくい入力と出力の形にする

### 組み立ての誤り・前提の欠け(最適解)
- 制約充足・SAT/SMT(部分と全体、群の合計の矛盾の検出)
- 整数計画・最適化(割付、枚数の最適化)
- 会社のルールの表と、案件の前提の入力の形の整備
- 過去の実績からの統計的な推定(人工、単価、ロス率)。ただし推定は仮定(C)として扱う

### 同じ誤りの一致・独立性の不足(異常検知)
- 別の情報源による確かめ(表 ↔ 図 ↔ 別の図、寸法 ↔ 基準点 ↔ 合計)
- 根拠の由来の記録(どの画像、どの手段、どのAIの土台か)と、独立性の自動判定
- 抜き取り検査(統計的な抜き取りの考え方で、検査の件数と合格の基準を決める)

### 仮説の選択と、何を聞くか(最適解)
- 確率的な推論(複数の仮説の確からしさの更新)
- 情報の価値の考え方(答えが分かると下流がどれだけ確定するか)による質問の選定
- 人が答えやすい選択肢の設計と、操作回数・時間の計測

### 速度・費用
- 問題を独立した部分に分けて解く(全体を毎回解き直さない)
- 計算の途中結果の再利用
- 重い処理を、軽い処理で候補を絞った後にだけ行う
- 重い計測は、作業環境ではなく計測用の環境で行う

## 4. やってはいけないこと
- 測らずに技術を入れる
- 1つの指標だけ上がったことで採用する(他の指標の悪化を見る)
- 原則を緩めて精度の数字を上げる(例:単一の根拠で確定を許して「確定件数」を増やす)
- 正解データを見ながら、正解に合うように調整する(採点の基準は先に固定する)
- 同じ誤りに、測らずに次々と技術を重ねる

## 5. 出力の形(技術選択の記録)
- 対象:役割、階層、誤りの種類、件数と金額
- 原因の仮説と、その確かめ方
- 候補の技術(2〜3個)と、それぞれの原則との相性、手間、危険
- 試した方法と、前後の比較(件数と分母つき)
- 判断(採用/不採用/保留)と理由
- 次に試すこと
