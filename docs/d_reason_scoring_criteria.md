# 67周目の基準: **出した行を正解に突き合わせ、当たり外れを理由別に数える**

2026-09-23。**測る前に書いてコミットする。**

66周目で行に決め手が付いた。**だが、採点そのものがまだ行を見ていない。**
いまの採点(`benchmarks/run_golden_eval.py`)は、図面の文字に正解の
`trigger_terms` が出るかを見ているだけで、**当てはめが出した見積の行とは
突き合わせていない。** だから「当たった行・外した行を理由別に」が出せない。

この周で作るのは、**出した行と正解の項目を突き合わせる口**である。

---

## 1. 守ること(**緩めない**)

- **抽出と採点を分ける。** 突き合わせる関数は、**行と正解だけ**を引数に取る。
  読み取り側が正解を見ない構えを崩さない(ゴールデンの `usage_policy`)。
- **対応づけを緩めない。** 突き合わせの鍵は次の順で、**部分一致や近い語で寄せない。**
  1. 正解に `code` があれば `code` が一致すること
  2. 無ければ(工事内容, 単位)が**正規化して完全一致**すること
- **数量の値は見ない。** この周で数えるのは「その行が出せたかどうか」だけ。
  値の当たり外れは別の指標で、混ぜると「出たけれど値が違う」が見えなくなる。
- **既存の指標を残す。** 全体の言い当て数と分母は今までどおり出す。

## 2. 測る数字(**固定の合成の正解**。実案件は PC 側)

| 記号 | 測るもの |
|---|---|
| M1 | 言い当てた項目数 ÷ 正解の項目数(**既存と同じ数え方**) |
| M2 | **当たった行の決め手別の件数** |
| M3 | **外した(正解にあるのに出せなかった)項目数と、取れなかった理由別の件数** |

## 3. 対照(**通らなければ結論を出さない**)

- **C1 緩めていないか**: 工事内容が 1 文字違う正解を当たりにしないこと。
  単位だけ違う正解も当たりにしないこと。
- **C2 壊し試験**: 突き合わせの鍵を壊すと M1 が 0 になること。
  **`rm -rf __pycache__` と `PYTHONDONTWRITEBYTECODE=1` を付ける。**
- **C3 数が合うか**: **理由別の合計 + 決め手の無い行 = 当たった行の総数**。
  ここがずれていたら、どこかで二重に数えている。

## 4. 採否の線(**先に引く**)

- **C1〜C3 が全部通る** → 採用。判定を変えない追加なので、全件テストと CI が
  通ればマージする。
- **C1 が通らない**(緩い突き合わせで当たりが増える)→ **不採用。作り直す。**
- **C3 が通らない** → **数え方が壊れている。数字を出さない。**
- **M1 の高さは採否に使わない。** 合成の正解を自分で作るので、**M1 は「仕組みが
  動いた」以上の意味を持たない。** 実案件の M1 は PC 側が出す。

## 5. この周でしないこと

- 実案件の正解ファイルをリポジトリに置くこと。**合成の正解を作る。**
- 数量の値の当たり外れを混ぜること。
- 突き合わせに「似ている語」を使うこと。
