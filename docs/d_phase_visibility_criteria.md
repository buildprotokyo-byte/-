# 基準: **現況と計画を、対象の名前ではなく意味の欄で分けたとき、何が変わるか**

**測る前にコミットする。結果を見てから基準は変えない**(取り決め、恒常ルール)。

対象の変更は `docs/principles/scope_of_work_diff.md` 9 節の 2 番と 3 番、
すなわち**建具表の数量を `phase` ごとに分ける**のと、
**`phase` を対象名から `Meaning.phase` へ移す**の 2 つである。
どちらも**既存の判定のしかたを変える**ので、**測ってから聞く**
(おーちゃん、2026-09-23「変わらないことを測って示してから、私に聞いてください」)。

## 1. なぜ測るか

この 2 つは**仲裁層から見た対象の同一性を変える。**
対象名が変われば、同じ対象としてまとめられていた読みが別々になり、
別々だった読みが同じになる。**「実案件では何も変わらないから」で自分で決めない。**
変わらないことと変わることを、数えて分けて出す。

## 2. 測るもの

**同じ入口 `read_drawing` を、前提だけ変えて 2 組走らせる。**
図面は**合成のベクター PDF**(`benchmarks/measure_phase_visibility.py` の中で組み立てる)。
実図面は使わない。

| 組 | 渡す前提 |
|---|---|
| A | **ページの宣言を渡さない** |
| B | **1 枚目を「現況」、2 枚目を「計画」と宣言する**(建具表も同じ 2 枚) |

数えるもの。

| 記号 | 何を数えるか |
|---|---|
| M1 | 読みの対象名と値の全部(`target` → `value_range`) |
| M2 | `meaning` を持つ読みの件数 / 読みの総数 |
| M3 | `meaning.phase` の内訳 |
| M4 | `QuantityItem` が `meaning` を持つ件数 / 総数 |
| M5 | 階層ごとの件数(`decisions`) |
| M6 | 建具表の数量の対象名と値 |

## 3. 対照(これが通らなければ結論を出さない)

**C1: A 組の M1 が、直す前と 1 件も違わないこと。**
ページの宣言が無ければ現況も計画も名乗れないので、**対象名も値も変わりようがない。**
1 件でも変わったら、直しが宣言の有無と関係ないところに及んでいる。
**結論を出さずに止めて、何が変わったかを名指しする。**

**C2: A 組・B 組とも M5 の階層 1 が 0 件のままであること。**
この変更は読みの分け方を変えるだけで、**新しいデータ源を作らない。**
階層 1 が 1 件でも増えたら、**対象を分けたせいで独立の数え方が狂った**ということなので、
増えた対象を名指しして止める(`docs/tier1_reachability_summary.md` の裏返し)。

## 4. 判定の分岐(先に決める)

- **C1 と C2 が通り、B 組で建具表の数量が現況と計画に分かれ、`meaning` が
  `QuantityItem` まで届いている**
  → **直しは効いている。** ただし**マージはしない。** PR のまま置いて、
  前後の数字を添えておーちゃんに聞く(承認の条件②)。
- **C1 が通らない**
  → 実装が広すぎる。**変わった対象を名指しして差し戻す。**
- **C2 が通らない**
  → **驚くべき結果。** 何が階層 1 に届いたかを名指しし、
  写し(`docs/tier1_reachability_summary.md` の「書き写した値だけが通る」)でないことを
  確かめるまで「増えた」と呼ばない。
- **B 組で分かれない**
  → 宣言が読みまで届いていない。**しきいの調整で誤魔化さず、どこで落ちたかを名指しする。**

## 5. この測定で分からないこと

- **出た数量が正しいかは測らない。合成図面なので「正解」は作図の側が決めた数である。**
  実図面での効きは Codex 側の測定に回す(役割分担、2026-09-23)。
- **差分(工事内容)そのものは、まだ作っていないので測れない。**
  この 2 つは差分の層が立つための前提であって、差分の精度の話ではない。
- **規則が `phase` を条件にできるようになったかは、この測定では見ない。**
  規則ファイルの版を上げたことは `tests/` の側で固定する。
