# Claude Codeへの引き継ぎプロンプト

## 背景

建設会社(ビルドプロ)の図面自動読み取り・自動積算AIを内製で開発するプロジェクトです。これまで、Claude(チャット)とChatGPT Codexを使い、設計の議論とトライアル(概念実証)を10回繰り返し、設計思想と統合ロジックの骨格が固まっています。ここから先は、実際にコードベースとして構築するフェーズに入ります。

添付する以下2つのファイルに、これまでの経緯がすべてまとまっています。作業を始める前に、必ず両方を読み込んでください。

- `自動積算AI_統合設計書v8.md`(現在の設計アーキテクチャ:層構造、軸カタログ、統合ロジック、キラークエスチョンエンジン)
- `開発引き継ぎ資料_2026-09-20時点.md`(トライアル1〜10の結果サマリー、未解決課題、次の優先順位)

## この設計の核心(要約)

1. 図面認識を1つの巨大なAIモデルに任せず、役割ごとに分解する(知覚層・絶対ルール層・施工慣習層・統合層等)
2. 各軸(画像・文章・絶対ルール・整合性・過去実績・空間認識等)は、**「大元のデータ源が独立しているか」**で独立性を判定する。技術系統が違うだけでは不十分
3. 軸は「強い軸」(実測校正済み・十分なサンプル)と「弱い軸」に分け、**ハードな絞り込みには強い軸のみを使う**
4. 確信度は二値ではなく3段階(自動確定/仮採用+抜き取り監査/要確認)で扱う
5. 確信度が低い要素群には、依存関係(「合計=内訳の和」等)を使い、**最も影響力の大きい1点だけを人に確認する「キラークエスチョンエンジン」**を適用する(ただし、独立した合算には適用しない)
6. 連続量(長さ・面積)は完全一致ではなく、許容誤差内での判定に切り替える

## 依頼したいこと(まずはここから)

以下の順番で進めてください。各ステップの完了時点で、簡単な進捗報告をお願いします。

### ステップ1:リポジトリの初期セットアップ

- Pythonプロジェクトとして初期化してください(これまでのトライアルはPython・NumPy・Pillow・OpenCV相当の処理を前提にしています)
- ディレクトリ構成の案を提示してください(例:`axes/`各軸の実装、`arbitration/`統合ロジック、`killer_question/`質問選定エンジン、`tests/`トライアルの再現、等)
- 提示後、私の確認を待ってから次に進んでください

### ステップ2:軸(Axis)の抽象化をコードとして実装する

- 各軸が共通で持つべきインターフェースを設計してください(入力:対象要素、出力:候補値のレンジ+根拠+確信度ステータス〈confident/low_confidence/abstained〉)
- まずは、これまでトライアルで使ってきた軸のうち、実装が容易なもの(絶対ルール軸、整合性軸)から着手してください

### ステップ3:3段階確信度階層と、強い軸/弱い軸の分離ロジックを実装する

- 設計書の「3-3. 3段階確信度階層」の判定ロジックをそのままコード化してください
- 弱い軸をハードな積集合の計算から除外し、参考情報として別枠で保持する仕組みを実装してください

### ステップ4:キラークエスチョンエンジンを実装する

- 設計書の「4-2. 影響度スコアの算出方法」の手順(候補値ごとに仮確定→下流の候補削減数を計算→平均→最高スコアの要素を選定→反復)をコード化してください
- 「合計=内訳の和」のような依存関係を定義できる、シンプルな依存グラフの表現方法も設計してください

### ステップ5:これまでのトライアルを、再現可能なテストとして組み込む

- トライアル7・8・9(キラークエスチョンエンジンの検証)を、`tests/`配下で再現できるようにしてください
- これにより、今後の設計変更が過去のトライアル結果を壊していないかを、毎回自動で確認できるようにします

## 進め方についての希望

- 一度にすべて実装せず、ステップごとに区切って進めてください
- 実装上の判断に迷う点(例:依存グラフの表現方法、確信度の閾値の初期値)があれば、独自に決めてよい場合は理由とともに決定し、設計思想に関わる重要な判断は都度確認してください
- コードには、どのトライアルのどの知見を反映した実装かがわかるよう、コメントを残してください
