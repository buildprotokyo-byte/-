# 周1「まとまりで読む」の基準(**測る前にコミットする**)

10 時間ループ(おーちゃん、2026-09-24 夜)の周1。
**この文書は測定の前にコミットする。結果を見てから基準を変えない。**

## おーちゃんが決めたこと(この周の出どころ)

> 「何かある」と「それが何か」は、同時にしか決まりません。
> ドアの周りには、線と数字と記号が固まっている。「W850」は、ドアの線とセットで
> 見なければ開口寸法だと分からない。丸の中の「WD-5」は、それ単独では意味を持たず、
> **建具表という別の資料に行って初めて何か分かる。**
> いまは線1本、文字1個、記号1個を別々に拾っています。
> **それでは W850 が何の寸法か永久に分かりません。**
> **近くにある線・数字・記号を一つのまとまりとして扱い、まとまりごとに意味を決める。**

測ること(原文):まとまりが何件できたか / そのうち意味が決まったのが何件か /
**バラバラに拾ったときと比べて、意味が決まった件数が増えたか。**

## 1. 測る紙

**P011 匿名化 v2 の 8 ページ目。**選び方は先に決めた機械的な条件で、
**中身を見て選んでいない:**

- 表題欄の縮尺の表記が読めるページのうち、
- **文字の断片がいちばん多く**(354 語)、
- 描画命令が 1 万本を超え(15,207 本)、
- **建具の記号と寸法の両方がある**ページ。

**縮尺に依存しないことの確かめ**には、**9 ページ目**(表題欄 1/30)を使う。

**この紙の中身(室名・寸法・記号の名前)は、報告にもリポジトリにも書かない。**

## 2. 比べる 2 つのやり方

| | 何をするか |
|---|---|
| **前(バラバラ)** | いまの本番の経路と同じく、**文字は文字だけ、線は線だけ**で拾う。文字の断片 1 つずつに、単独で意味を当てにいく |
| **後(まとまり)** | **近くにある文字と線と記号を 1 つのまとまり**にして、**まとまりごとに**意味を当てにいく |

**どちらも同じ分母で数える。**分母は**そのページの文字の断片の総数**
(`page.get_text("words")` が返す数)。

## 3. 「意味が決まった」の決め方(**先に固定する**)

文字の断片が、次の 4 つのどれかに、**この冊自身で裏が取れる形**で当たったときだけ数える。

| 種類 | 裏の取り方(**図面が自分で書いているもの**) |
|---|---|
| **寸法** | その数字が、**近くの寸法線の紙の上の長さ × 縮尺**と ±5% で一致する |
| **建具の記号** | その文字列が、**この冊の建具表のページの升目の中**にも出てくる |
| **室名** | その文字列が、**この冊の仕上表のページの升目の中**にも出てくる |
| **通り芯の符号** | 円の内側にあり、その円が**直線の端**に付いている |

**裏の取れない当て方は 1 件も数えない。**「たぶん寸法だろう」は 0 件として扱う。

**建具表・仕上表の側は、見出しを当てに行かない。**升目の中身を総当たりで見る。
(見出しの完全一致で当てる今の実装は、実図面で 0 件になることが分かっている
→ `jidou-sekisan-door-schedule-zero`。ここでその欠陥を持ち込まない)

## 4. まとまりの作り方(**縮尺に依存させない**)

- まとまりの単位は **文字の高さ**。「◯ポイント以内」のような紙の上の長さで持たない
- 文字の断片 A と B は、**間が A と B の文字の高さの平均の N 倍以内**なら同じまとまり
- 線と記号は、**その文字の高さの N 倍以内**にあれば同じまとまりに入れる
- **N は 1 つだけ決めて、両方のページで同じ値を使う。**ページごとに変えない

## 5. 先に決める線

| 線 | 中身 |
|---|---|
| **線1** | **まとまりで読むと、裏の取れた件数がバラバラのときより増える。**増えなければ**不採用**で、まとまりにする実装は入れない |
| **線2** | **縮尺に依存しない。**1/50 のページと 1/30 のページで**同じ N** を使い、文字の断片あたりのまとまりの数の差が **±20% 以内**に収まる |
| **線3** | **1 つのまとまりに違う種類の意味を 2 つ当てない。**当たったらそのまとまりは「決まらない」にする。**2 つ当たった件数も数えて出す** |
| **線4** | **まとまりの件数が増えても、裏の取れた件数が増えていなければ「効いた」と書かない**(おーちゃんの繰り返しの決まり) |

## 6. やらないこと

- **本番の経路には繋がない。**`app.py` と `intake/` は触らない(K-29 のまま)
- **自動確定は 0 件のままにする。**この周は数量を 1 件も確定させない
- **正解ファイル(見積の答え)は使わない。**裏はこの冊の中だけで取る
- **実図面から作ったデータをコミットしない。**試験は合成データで書く

## 追記1(**測る前にコミットする**): まとまりのしきい N を先に決める

**N = 2.0。**文字と文字、文字と線の間が**文字の高さの 2.0 倍以内**なら同じまとまりにする。

**この値は結果を見ずに決めた。**根拠は、製図では寸法の数字を寸法線のすぐ上に
文字の高さ 1 つぶんほど空けて書くのが普通であること(`docs/drafting_rules_reference.md`)。
**1.0 では線に届かず、3.0 では隣の寸法まで拾う**という見込みで、その間を取った。

**1/50 のページと 1/30 のページで、同じ 2.0 を使う。ページごとに変えない。**
**結果を見て 2.0 を動かさない。**動かすなら、動かす前に理由を書いてコミットし、
**動かす前の数字も報告に残す。**

## 追記2: いまの本番の経路の数字も並べて出す

基準の 2 節では「前」を**文字 1 つずつに単独で意味を当てにいくやり方**と決めた。
**これに加えて、いまの本番の経路(`read_dimensions`)がこのページで何件読めているかも、
同じ分母で並べて出す。**やり方を増やすだけで、線の判定は 2 節のままにする。

(理由: 単独のやり方では、寸法と通り芯は**作りからして 0 件**になる。
線1 が形だけ通ってしまうので、**本番の数字を並べないと意味のある比較にならない。**)
