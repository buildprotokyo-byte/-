## 1. 結論

**合否の基準 A1〜A5 はすべて合格。**

| | 前 | 後 |
|---|---|---|
| 測った群 | 127(名前つき10 + 格子117) | 同じ |
| 吸収と判定された群 | 15 | 15(**変わらない**) |
| 群合計から立った問い | 0(入口が無い) | **15**(吸収された15群に1問ずつ) |
| 吸収が無い群(112群)に立った問い | 0 | **0** |
| 陰性対照(誤りを仕込んでいない13群)に立った問い | 0 | **0** |
| unsat の群(17群)に立った問い | 0 | **0**(群全体を人へ回す安全装置はそのまま、17群とも10要素全部) |
| 階層・監査の割り当てが変わった群 | — | **0 / 127** |
| 既存の `next_question()` が吸収された群に立てた問い | 0 / 15 | 0 / 15(触っていない) |

**選ばれた要素が、仕込んだ誤りの要素だったか**

| 誤りの場所 | (c) の問い | 誤りの要素に当たった | 正しい値で答えた後 |
|---|---|---|---|
| 停止した要素の読みがずれた | 6 | **6 / 6** | 6群とも sat・吸収が消えた(群が閉じた) |
| 階層1の要素(強い2軸が同じ誤値) | 9 | **0 / 9** | 9群とも unsat → 群全体が人へ回った |

階層1に誤りがある場合、選ばれるのは誤りの要素ではなく、吸収している停止した
要素である。**これは予想どおりで、群合計の性質から来る。** 階層1の要素は強い2軸が
一致していて読みの範囲が幅0なので、「読みの範囲の答え」では群の残差を動かせない。
群合計は「階層1のどれが誤りか」を言えない(設計書4-1節)。

そのかわり、停止した要素に1問聞けば、答えが

- 押し出された値なら → 吸収は説明がつく(停止した要素の読みが誤っていた)
- それ以外なら → 群合計が矛盾し、**既存の安全装置が群全体を人へ回す**

のどちらかになり、**「隠れた吸収」の状態は1問で終わる。** 測った15群では、
正しい値で答えた後に「まだ吸収されている」群は **0**、候補の外の答え(食い違い)も **0**。

## 2. 何を足したか

- `arbitration/group_total.py` の `group_total_absorption_excess()` … **群の残差**。
  停止した要素が、群合計のせいで自分の読みの中心 ± `CENTER_TOLERANCES` の窓の外へ
  押し出された量の合計。`check_group_total` の「吸収された」と同じ窓・同じ比べ方で、
  0 より大きいことが「吸収された」と同じ意味になる。unsat なら `None`
- `killer_question/engine.py` の `KillerQuestionEngine.group_total_question(constraint)`
  - 吸収が無い群・unsat の群には `None`
  - 群の要素ごとに、**その要素自身の読みの範囲**(`detection_range`)の候補値を
    1つずつ仮に置き(複製した solver に `m == v` を置いて確認済みにする。
    `answer()` と同じ扱い)、残差が減った量を測る。**置いた結果 unsat になれば、
    残差を全部動かしたと数える**(隠れていた矛盾が表に出て、群が止まるため)
  - 候補値ごとの減り量の平均を効きとし、効きが0の要素は外す
  - 残りから、既存の `next_question()` と同じ規則で1つ選ぶ(検算できる階級を先に →
    効きの大きい順 → 同点は誤り率の低い軸 → 名前順)。候補値が多すぎる要素
    (256超)と、食い違いを人に回した要素は外す
  - 返すのは `Question` 1つ(`selected_by="group_residual"`)。**solver も階層も変えない。**
    答えの反映は通常の `answer()` / `run()`
- **(a) はそのまま。** 吸収された群の階層1を階層2へ落とす `targets_requiring_audit`
  は、(c) の前後で127群すべて一致した

候補値を群合計で絞った範囲から取らないのは、**群合計そのものが疑われているから**
である。群合計で絞ると、停止した要素は押し出された値1つ(例: 5)しか候補に残らず、
正しい答え(3)は候補の外になる。

## 5. **測って分かった、(a) の側の穴(この PR では直していない)**

(c) は「吸収と判定された群」にしか問いを立てない。その判定((a) の
`check_group_total`)は**停止した要素ごとに**、解の範囲が自分の窓から外れたかを見る。
**停止した要素が2つ以上あると、群としては合計が合わないのに、どの要素も
単独では窓の中に留まれる**ので、吸収と判定されない。

格子で、階層1に ±2・±3 の誤りを仕込んだ群:

| 停止した要素の数 | 群 | unsat | 吸収と判定 | **sat・吸収なし(誤りが素通り)** |
|---|---|---|---|---|
| 1 | 12 | 6 | 6 | **0** |
| 2 | 12 | 2 | 0 | **10** |
| 3 | 12 | 0 | 0 | **12** |

(±1 は許容差の中なので、停止の数に関わらず別に数える。18群のうち unsat 0・吸収 0。)

**停止が2つ以上の群では、±2 以上の誤りでも24群中22群が素通りした。** 設計書7-2節に
「4-1節の区間演算は使わなかった。同じ判定を solver の解から読める。判定の結果は試作と
一致する」とあるが、**試作の表は停止1つの群だけ**で、停止が複数の場合は一致しない。
設計書4-1節の式(残差を停止要素の中心の合計 ± 許容差×停止数と比べる)なら、
たとえば停止2つ・誤差3は捕まえられるはずである(**これは測っていない**)。

**直すと「吸収」の判定、つまり (a) の降格の範囲が変わる**ので、この PR には入れていない。
直すかどうかはおーちゃんの判断が要る。
