## 1. 何が 0 か所だったか

`estimating/decisive.py` には決め手の 1 つとして `知識のルール` があり、その証拠として
`knowledge_rule_ids` の欄がある。数量(`estimating/quantities.py`)にも同じ欄がある。
**しかし値を入れるコードが 0 か所だった。** そのため本番経路から `知識のルール` は
一度も出ていない(`docs/reports/2026-09-23_K-09_全体まとめ.md` 2 節)。[測った]

## 2. どちらに持たせたか: **規則の側**

理由は基準の 0 節に書いたとおり 3 つ。要点は「知識は数量を作るのではなく、
**読めた数量を行に当てはめるところで効く**」ことと、「**図面からは決まらない行は
知識だけで立つ行**なので、規則の側に置くとそこも数えられる」こと。

**数量の側の欄は残してある。** 片方だけ塞ぐと、人の入力から渡す経路を作るときにまた
書き換えになる。`estimating/mapping.py` は**両方を合わせて**決め手を作る。

## 3. 向きを固定した(判定の側は知識の表を読まない)

- 規則は ID を**文字列のまま**運ぶだけで、`estimating/` は `knowledge/` を import しない。
- 引用が本物かどうかは `knowledge/linkage.py` が調べる。こちらは `knowledge/` の側なので、
  規則も表も読める。
- 採否(`採用` / `候補` / `不採用`)は `knowledge/table.py` に足した**読むだけの窓**
  (`is_adopted` など)を通して読む。**列の名前を口にするコードは読み込みだけ**という
  既存の約束(K-04 6 番)を、読み手が増えても崩さない。**書き換える口は増やしていない。**[測った]

## 4. 断るようにしたこと

| 何を | なぜ |
|---|---|
| 知識の表に無い ID を引いた規則 | 指し先の無い引用は、証拠の無い札と同じ |
| `不採用` の知識の引用 | おーちゃんが落とした知識で行を立てない |
| 空の引用・重複した引用 | 「書いたのに効かない」がいちばん危ない |
| 版 2 以下のファイルに書いた引用 | 半分だけ効いた規則を作らない(既存の約束) |
| `候補` の引用 | **断らない。ただし採用済みと分けて数える** |

確認日が空欄(不明)の知識を引いていたら、止めずに**名指しする**(#110 の
「確認日が空欄なら採用に進めない」に合わせた形)。

## 6. **いちばん大事な読み方**: 行は増えていない。札が移っただけである

上の表で `知識のルール` が 0 → 3(入力あ)・0 → 6(入力い)に増えたが、
**見積の行は 1 行も増えていない。** 当てはめた行の決め手は `観測` から
`知識のルール` へ**移った**(`観測` は「ほかの 4 つがどれも無いときだけ名乗れる」という
既存の決まりのため)。増えているのは**ルールだけで立つ行**の側で、
そこは今まで決め手が空だった 9 行のうち 2 行に札が付いた。

つまりこの周が作ったのは「**何で数えたかを言えるようになった**」ことだけである。
**精度は測っていない。** 引用した知識が正しいかどうか、その知識で行が埋まるかどうかは
別の問題で、この周では 1 つも確かめていない。[動いた]

**この周はその 39 行に 1 行も届いていない。** 届かせるには知識の中身(どの工種をどう数えるか)が
要るので、そこはおーちゃんの採否待ちである(K-11 の 2 番の表)。

## 8. 測れていないこと(数字を引用する前に必ず読むこと)

- **引用した知識が正しいかは測っていない。** 見本が引いているのは公共建築数量積算基準からの
  **候補 5 件で、どれも `候補` のまま・確認日は空欄**である(採否はおーちゃんが決める)。
- **知識の中身は 1 つも実装していない。** 率・係数・どの工種にどれを当てるかは入っていない。
  ここは**経路だけ**である。
- **行が埋まるかどうかは測っていない。** 引用を足しても、規則が当たらない数量は今までどおり
  当たらない。P011 で行が増えなかったのはそのためである。
- 実案件の規則(会社の積算ルール)はリポジトリに無い。見本は**架空**である。
