# 42周目 結果: くっつけても届かない(ただし測り方に穴がある)

基準は `docs/b_door_table_fragments_criteria.md`(コミット `44d45ec`、**測る前**にコミット済み)。
測定は `benchmarks/measure_door_table_fragments.py`。対象は匿名化 v2(内側 47 表 / 外側 60 表)。

**出したのは件数と割合だけ。** 図面の文字は 1 文字も無い。

## 結果

**くっつけ自体は効いている。** 内側の表は **47 → 25**(SLACK 0〜6)、**47 → 20**(SLACK 12)に減った。
**つまり接している表は現にある。**

| SLACK | 塊(内側) | K0 当たり | K1 当たり | K2a 当たり | K2b 当たり |
|---|---|---|---|---|---|
| 0 pt | 25 | 0 | **1** | 0 | 0 |
| 2 pt | 25 | 0 | **1** | 0 | 0 |
| 6 pt | 25 | 0 | **1** | 0 | 0 |
| 12 pt | 20 | 0 | **1** | 0 | 0 |

**16 通り(SLACK 4 × 当て方 4)すべてで、当たりは 0 か 1。** 線は 2 以上。

K1 の誤爆比は 4 通りとも **1.000**、取り違えは 6〜7。**くっつけても形は変わらない。**

**P6 を見ると、くっつけて `幅` の当たりがむしろ減っている**(12 → 6 → 4)。
塊にすると見出しの探索範囲(上から 3 行)に入る升目が変わるためで、**増える向きには働いていない。**

## 判定

> **どの `SLACK` でも P2 ≦ 1** → **割れているのでもない。ここで建具表の追跡をいったん止め、
> 判断待ちとしておーちゃんに出す。**

**基準の字面どおり、この周の判定はそれである。そして止める。**

## **ただし、この測り方には穴がある(自分で見つけたので書く)**

**くっつけた塊でも、見出しを探すのは「上から 3 行」のままである。**

塊は元の表の行を上から並べたものなので、**2 つ目以降の破片の行は 4 行目より下に来る。**
つまり**破片 A に建具番号、破片 B に幅と高さがあっても、B の行が窓から外れていれば
くっつけた意味が無い。** 現に `幅` の当たりは**くっつけるほど減っている。**

**だからこの周の結論は「割れていないと確かめた」ではなく、
「くっつけるだけでは届かなかった」である。** 強さが違うので、そう書く。

**穴をふさぐ測り方は 1 つで、しかも安い。**

> **上から 3 行ではなく、塊の**全部の行**から見出しを探す。**

これは実装として正しい読み方ではない(下のほうの行を見出しと言い張ることになる)が、
**「この升目の集まりから建具表が取り出せるか」の上限としては正しい。**
**上限で届かなければ、どんな正しい読み方でも届かない。**

## 次の周(43): 上限を測る

**窓を外して、行・列の両方の向きで、4 通りの当て方を当てる。**
基準を先に書いてコミットする。**線は 39〜42 周目と同じ 3 つ。**

- **上限で届く** → 穴は窓(上から 3 行)。**直す場所が名指しできる。**
- **上限でも届かない** → **この図面の升目からは、この語彙で建具表は取り出せない。**
  6 つでなく 7 つ試して 7 つとも違ったことになり、**判断待ちの根拠が固くなる。**

## おーちゃんへ出す判断待ち(**この周で 1 件増える。5 → 6 件**)

**建具表の読み取りをこれ以上追うかどうか。**

いまの状態を正直に書くと、こうなる。

- **建具表はこの図面にある**(`建具` の語が 10 ページ、その全部に罫線の表)。
- **6 つ疑って 6 つとも違った**(表が無い / 文字が無い / 語が足りない / 当て方の形 /
  見出しが列にある / 表が割れている)。
- **効き方は大きい。** 開き戸は円弧で拾えるが、**引戸・折戸は図形から原理的に拾えない。**
  この経路が折れているあいだ、**実図面の新設建具はどの経路でも拾えない。**
- **1 案件しか無い。** この図面に合わせ込んだ直し方をしても、それが正しいか確かめられない。
