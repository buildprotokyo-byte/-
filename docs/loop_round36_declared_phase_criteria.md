## 1. 前の周との違い(おーちゃんの設計②「1周で変えるのは1つだけ」)

| | 周35 | 周36 |
| --- | --- | --- |
| 技術 | 粒度ごとの手間と粗さ | **渡す前と後で数える**(周28 と同じやり方) |
| 出典 | 人の入力(**仮定しただけ**) | **人の入力(実際に渡す)** |
| 専門 | 積算 | 同じ |

**周35 の自己批判に答える周である。**
周35 は「出典 3 つ目は名ばかり。人の入力は仮定しただけで 1 件も受け取っていない」と書いた。
**ここで実際に受け取る。**

## 2. 測る前に読んだこと(取り決め①)

- **`benchmarks/measure_declaration_effect.py`(63 周目)は `phase` を 1 度も渡していない。**
  渡しているのはページの種類(`kind`)だけである。**位相を実図面で渡した周はまだ無い。**
- **合成図面では測ってある**(`docs/d_phase_visibility_report.md`)。その報告の 5 節が
  自分でこう書いている——「**実図面でどうなるかは測っていない。**」
- `PageDeclaration.phase` に入れてよい値は `現況` `計画` `解体` `不明` の 4 つ
  (`intake/start_kit.py`)。**`不明` は「決まっていない」という記録。**

## 3. **この周が測るのは配管であって、正しさではない**(先に大きく書く)

**渡す位相の値は、こちらが作ったものである。おーちゃんが決めた値ではない。**

しかも**周32 で、ページに 1 つ位相を宣言する形はこの図面と粒度が合っていないと分かっている**
(語が在る 20 ページのうち 13 ページは 2 種類以上が同居)。
**だから、仮に配管が通っても、入る値は正しくない。**

**この周で言えるのは「人が入れた位相が、数量まで運ばれるか」までである。**
**「位相が正しく付く」とは書かない。**

**それでも測る理由は 2 つ。**

1. **設計④の出典 3 本目を、名ばかりでなく本当に当てるため。**
2. **裏返しの危険を実図面で確かめるため。** 人が 1 回入れた値で自動確定が起きないか。
   これは K-29(自動確定は 0 件のままにする)そのものである。

## 4. 測るもの

図面は **P011 の匿名化 v2**(34 ページ、A3)。**v1 ではない。**

### 渡す宣言

**34 ページすべてに宣言を作る。** 種類は `その他`、位相は**ページ番号で機械的に振る**
(奇数ページ=`現況`、偶数ページ=`計画`)。

**この振り方に意味は無い。** 意味のある振り方を作ると、**こちらが図面を読んで決めた値**に
なってしまい、「人の入力」ではなくなる。
**配管を測るのが目的なので、値は機械的でよい。**
**報告には「値に意味は無い」と必ず書く。**

## 5. 線(合格・不通過の数字を先に書く)

### 線1 — **配管は通るか**

位相が `不明` 以外に決まっている数量の件数。

- 渡す前(対照): **0 件**であること。周31・周35 で 0 件と分かっている。
- 渡した後: **合格 = 座標を持つ数量の 90% 以上**。

### 線2 — **対照**

**宣言を渡さない側で、数量の件数と対象名が 1 つも変わらないこと。**

- **合格 = 渡す前と後で、数量の総件数が同じ。**
- 変われば、宣言が位相以外のものまで動かしていることになる。
  `docs/d_phase_visibility_report.md` の C1 と同じ確認である。

### 線3 — **裏返しの危険**(いちばん大事)

- **合格 = 自動確定した数量が、渡す前も後も 0 件。**
- **0 でなければ、その場で止めて報告する。**
  人が 1 回入れた値だけで確定が起きるのは、`jidou-sekisan-tier1-unreachable` に
  書いてある「危ない裏返し」そのものである。

### 線4 — **規則は当たるようになるか**

現況を条件にした規則(**合成の見本。実案件には使わない**)を当てる。

- 渡す前: **0 件**(条件に `不明` は書けないので当たりようがない)。
- 渡した後: **合格 = 1 件以上当たる。**
- **ただし当てはめで確定した行は 0 件のままであること**(線3 と同じ理由)。

## 6. 測らないこと(先に宣言する)

- **位相の値が正しいかは測らない。**(3 節のとおり。値はこちらが機械的に作ったもの。)
- 実案件で見積が何行出るか、金額、数量の値、対象名。
- **`app.py` と `intake/` は 1 行も変えない**(K-29)。渡すのは実行時の引数だけ。
- コードは直さない(取り決め②)。

## 7. この測り方で分からないこと(先に書く)

- **配管が通っても、この図面では正しい値は入らない**(周32 の 13/20 ページ)。
- **座標を持たない数量(161 件)については、割合の分母に入れない。**
  件数は報告に書く。
