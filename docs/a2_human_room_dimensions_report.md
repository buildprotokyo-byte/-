## 壊し試験

**12 通りすべてで試験が落ちることを確認した**(テスト 28 件)。
`rm -rf __pycache__` と `PYTHONDONTWRITEBYTECODE=1` を毎回かけている。

天井高が無くても壁を出す/刻みで表せない値を丸める/小さすぎる寸法を通す/
0 と負の寸法を通す/天井高を既定値で埋める/縦か横の片方だけで面積を出す/

**3 通りは最初の試験では見逃した。** 理由はどれも同じで、
**別の関門が先に効いて壊れたところに届かなかった**ためである
(0 と負は「小さすぎる」の関門に、既定の天井高は変換側の関門に隠れた。
出どころは定数どうしを比べていたので、定数を書き換えると両側が動いた)。
7 周目の「開口を越えない止め札が試験に映らない」と同じ形である。
**関門を直に呼ぶ試験と、定数ではなく文字列そのものを見る試験を足して直した。**

## 黙って確定しないこと

`human_room_dimensions` を `arbitration/method_policies.py` に
**`calibrated=False` / 上限 `weak`** で登録した。理由は 4 つ書いてある。

そのうち**いちばん重いのは 4 つ目**である。
人の入力は**図面とは別のデータ源**なので、ここを校正済みにすると、
**人が 1 回入れた値と図面の印字が合っただけで階層1(自動確定)に届く。**
`human_reference_point` と `pdf_text_scale` で前に確認した裏返しの危険と同じ形で、
**独立性が足りないのではなく、独立性が揃ってしまうことが危ない。**

根拠(`provenance`)には、床面積・周長・内壁面積が
**同じ人が同じ時に入れた 3 つの数字から計算したもので、
3 つの独立した証言ではない**ことを必ず残している。

## 次の周

この周で**入口から見積の行までがつながった**ので、次に効くのは 2 つある。

1. **床面積から出る 14 件と、壁から出る 8 件を、実際の工種に結びつける規則を作る。**
   ただし**規則の中身は会社のルール**なので、自走の範囲は**形と動作の確認まで**である。
   (マスタープロンプト 2 章 A-3 の但し書きと同じ。)
2. **残る 50 件(記号を数える 26・文字がそのまま 24)に移る。**
   0 章の診断では、記号(コンセント・スイッチ・配線・TEL)が 0 件のままである。
   金額の効き方で言えばこちらのほうが大きい可能性がある。

**キラークエスチョンは今回は当てない。** 8 周目で当てたばかりで、
その答えのとおりに動いたら数字が動いた(0.000 → 22 件の射程)。
**鈍化していないときに当てる問いではない。**
次に当てるのは、上の 1 か 2 で数字が動かなくなったときである。

## 判断待ち

1. **室の寸法を人に入れてもらう形でよいか。** 室ごとに縦・横・天井高の 3 つである。
   面積 1 つでは ㎡ 22 件のうち 8 件が埋まらない。
2. **寸法は芯々で入れてもらうのか、内法で入れてもらうのか。**
   面積を芯々で数えることは決まったが、**人がどちらで測るかは決まっていない。**
   いまは申告してもらう形にして、申告が無ければ「不明」として理由に出している。
3. **開口(建具)の面積を内壁から引くか。** いまは引いていない。
   引くなら建具の数量と突き合わせる経路が要る。
