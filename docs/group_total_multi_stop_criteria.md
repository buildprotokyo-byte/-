# 停止した要素が2つ以上ある群の「素通り」— 測り方と基準(**測る前に書いてコミットする**)

2026-09-23。K-07 の6番「止まった要素が2つ以上あると素通りする件、測ってから聞いてください。
今は直さなくて結構です。」

- 測る対象のコード: `arbitration/group_total.py` の `check_group_total()`(#101 でマージ済みの本体)
- 測るスクリプト: `benchmarks/measure_group_total_multi_stop.py`(このあと書く)
- 数字の出力: `docs/group_total_multi_stop_result.json`

**判定のコードは変えない。** 直し方の候補は1つだけ、測るスクリプトの中にだけ置いて、
同じ群で並べて測る。**合成データだけで測る。** 実図面・実見積は使わない。

## 0. 何が問題か(コードを読んで確かめたこと)

`check_group_total()` は、群合計を含めて `use_detection_ranges=True` で解いたあと、
**停止した要素(`requires_confirmation=True`)を1つずつ**見て、その要素の解の範囲が
自分の読みの中心 ± `CENTER_TOLERANCES`(個数は ±1)の窓から**全部外れたとき**だけ
「吸収された」(`absorbing_targets`)とする。

停止した要素が2つ以上あると、群としては合計が合わないのに、**それぞれの要素の解の
範囲は、他の停止要素が動けるぶん広くなり、自分の窓と重なったままになる**。
すると sat・吸収なしになり、群は止まらず、階層1の要素も監査に落ちない(素通り)。

#101 の格子では、階層1に ±2・±3 の誤りを仕込んだ群のうち、停止2つで 10/12、
停止3つで 12/12 が素通りした(`docs/group_total_question_report.md` 5節)。

## 1. 格子(合成)

作り方は #101(`benchmarks/measure_group_total_question.py`)の部品をそのまま使う。
本番と同じ組み方(`AxisQualityFirewall.assess()` → `killer_question/firewall_bridge.py`
→ `ConsistencySolver`)で10要素を登録し、`GroupTotalConstraint`(単位 `count`)を立てる。

- 10要素、正解 `[3, 4, 2, 5, 3, 4, 2, 3, 4, 3]`(合計33。#101 と同じ)
- 停止する要素の数 **k ∈ {0, 1, 2, 3, 4}**。`door_0`, `door_5`, `door_9`, `door_7` の
  先頭から k 個(#101 の3つに `door_7` を足した)
- 停止した要素の読みの半幅 **w ∈ {1, 2, 3}**。読みは(正解 − w, 正解 + w)、
  強い軸1つ(校正済み)+ 弱い軸1つ(#101 と同じ)。k = 0 のときは w は意味が無いので
  1通りだけ測る
- 仕込む誤り
  - **なし**(陰性対照)
  - **階層1**: `door_3`(正解5)の強い2軸が、正解 + d で一致。
    **d ∈ {±1, ±2, ±3, ±4, ±5}**(#101 は `door_1` で ±3 まで。k = 4 のとき
    群の許容幅 4 を超える誤りを入れるため、正解の大きい `door_3` に移して ±5 まで広げた)
  - **停止した要素**: `door_0` の読みの中心が 正解 + d にずれる(d ∈ {±1, ±2, ±3}、
    半幅はそのまま、下限は0で切る。#101 と同じ)。k ≥ 1 のときだけ

群の数: k = 0 が 1 × (1 + 10) = 11、k = 1〜4 が 4 × 3 × (1 + 10 + 6) = 204、**合計 215 群**。

**前提の確かめ**: 停止した要素が階層3、それ以外が階層1になったことを群ごとに確かめる。
ならなかった群は数から外し、件数と理由を結果に書く。

乱数は使わない(格子は全部の組み合わせを1回ずつ)。

## 2. 「素通り」の定義

群の判定は3つのどれかになる。

| 判定 | 意味 |
|---|---|
| unsat | 群を止める。群の全要素が人へ回る(安全装置) |
| sat・吸収あり | 群の階層1の要素を階層2(仮採用+抜き取り監査)へ落とす((a))。(c) の1問もここに立つ |
| sat・吸収なし | 何も起きない。階層1の要素は自動確定のまま |

**素通り** = 階層1の要素に **|d| ≥ 2**(1要素の許容差 ±1 を超える)の誤りを仕込んだのに、
判定が **sat・吸収なし** になった群。群合計は合わないのに、吸収とも判定されず、
人にも回らない。

素通りは、誤りの大きさで2つに分けて数える。

- **群の許容幅の外**(|d| > k。個数の許容差1 × 停止要素数): 停止した要素の窓を
  全部足しても説明がつかない誤り。**群として見れば見えるはずのもの**
- **群の許容幅の中**(2 ≤ |d| ≤ k): 停止した要素がそれぞれ窓の中で少しずつ動けば
  説明がついてしまう誤り。**群合計の区間演算でも原理的に見えない**(死角。
  停止1つの ±1 と同じ性質が、停止の数だけ広がる)

|d| = 1 は1要素の許容差の中なので素通りに数えず、別に件数だけ出す。

停止した要素に誤りを仕込んだ群は、その要素がもともと人へ回っているので素通りには
数えない。判定がどう分かれるかと、階層1の(正しい)要素が監査に落ちた数を出す。

## 3. 直し方の候補(1つだけ。スクリプトの中にだけ置く)

設計書 `docs/group_total_masking_design.md` 4-1節に書いてあった式を、そのまま使う。

    停止していない要素の検出用の範囲の合計   [Σlow_fixed, Σhigh_fixed]
    停止した要素が担うべき合計(残差)       R = [T − Σhigh_fixed, T − Σlow_fixed]
    停止した要素の窓の合計                  [Σ(中心 − 許容差), Σ(中心 + 許容差)]
    R と窓の合計が交わらなければ「吸収された」

中心と許容差は `check_group_total()` と同じもの(`_center_window()`、`Fraction` で厳密)。

**候補の判定 = いまの判定(要素ごと)が吸収なら吸収、そうでなくても群が sat で
上の式が交わらなければ吸収。** いまの判定を置き換えず、足すだけにする(いまの判定が
拾っているものを落とさないため)。unsat の群には触らない。
吸収となった群の `targets_requiring_audit` は、いまのコードと同じく
「停止していない要素のうち `firewall_tier` が 1 のもの」とする。

## 4. 候補が「提案に値する」ための条件(**数字を見る前に決める**)

全部を満たしたときだけ「提案に値する」と書く。1つでも外れたら「提案しない」と書き、
どれが外れたかを書く。

| # | 条件 | 合格の条件 |
|---|---|---|
| B1 | 停止が0・1の群は何も変えない | k = 0, 1 の全群で、吸収の有無と `targets_requiring_audit` が いま と**完全に一致** |
| B2 | 陰性対照に新しい吸収を出さない | 誤りを仕込んでいない群(全 k)で、候補だけが吸収とする群が **0**。(c) の問いは吸収された群にちょうど1問立つので(#101 の A2・A3)、**新しい問いも 0** と同じ意味 |
| B3 | いまの判定を落とさない | いま unsat の群は候補でも unsat、いま吸収ありの群は候補でも吸収あり。**全群** |
| B4 | 群の許容幅の外の素通りを無くす | 階層1の誤りが \|d\| > k で sat の群のうち、候補で素通りのまま の群が **0** |

## 5. 合否ではなく、数字で出すもの(予想を先に書く)

| # | 何を | 予想 |
|---|---|---|
| R1 | 素通りの件数(いま と 候補)、k × \|d\| 別 | いま: k ≥ 2 で \|d\| ≥ 2 の多くが素通り。候補: 群の許容幅の外は 0、中は残る |
| R2 | 吸収の判定、つまり階層1の監査への割り当てが変わる群の数(誤りの場所別) | 階層1の誤り・停止した要素の誤りで増える。陰性対照は 0 |
| R3 | 候補でも残る素通り(群の許容幅の中、2 ≤ \|d\| ≤ k) | k が大きいほど増える。k = 4 では \|d\| = 2〜4 がすべて残る |
| R4 | 停止した要素の誤りで、正しい階層1の要素が新たに監査に落ちる群の数 | k ≥ 2・\|d\| ≥ 2 で出る(k = 1 では いま も同じ動き) |
| R5 | いまの判定の unsat / 吸収 / 素通り の内訳(k × \|d\| 別) | #101 の格子の数字(停止2つで 10/12、3つで 12/12)と同じ傾向 |

## 6. 測らないもの・限界

- **実案件。** `check_group_total()` を呼ぶのは、テストと `benchmarks/` と
  `KillerQuestionEngine.group_total_question()` だけで、`group_total_question()` を
  呼ぶのもテストと `benchmarks/` だけ(コードを読んで確かめる。報告に書く)。
  したがって**実案件で何件素通りしているかは、この測定では分からない**
- 単位が個数以外(連続量、許容差 ±5%)の群
- 階層1の誤りが2要素以上にまたがる群(打ち消し合う誤りは、どんな合計の検査でも見えない)
- 候補を使ったときの (c) の問いそのもの。`group_total_question()` は内部で
  いまの `check_group_total()` を呼ぶので、エンジンを変えずには測れない。B2 のとおり
  「吸収 = 1問」の関係から件数だけを言う
- 判定のコードの修正。**直すかどうかは おーちゃんの判断**
