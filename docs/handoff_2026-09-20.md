# 図面自動読み取りAI 開発 引き継ぎ資料(2026年9月20日時点)

次回の開発再開時に、この資料だけで状況を把握し、スムーズに続きから着手できることを目的にまとめています。

---

## 1. プロジェクトの目的

建設図面(線・数字・記号・手書き)を自動で正確に読み取り、自動積算に活用できる精度のAIを、外部サービスに頼らず内製で構築する。目指すのは「精度100%」ではなく、「業務で使える許容範囲に、限りなく安全に収束させる」こと。

---

## 2. 現在の設計思想(核となる5原則)

1. **役割限定 × 絶対ルールによる問題空間の縮小**:AIに全部を1人で理解させず、狭い役割ごとに絶対ルールを当てはめる
2. **確定的フィルター層と確率的判断層の分離**:前者(公理・法律)は何層重ねても誤差が蓄積しないが、後者(施工慣習)は重ねるほど誤差が複利で効く
3. **異なる失敗理由を持つ複数アプローチの組み合わせ(ブースティング理論)**:ただし技術系統の違いだけでは独立性は保証されない。**「大元のデータ源が同じかどうか」で独立性を判定する**のが正しい基準
4. **ゴールは精度100%ではなく「許容範囲内への収束」**:連続量(長さ・面積)では特に、完全一致ではなく許容誤差内での判定に切り替える
5. **精度を上げることと、人手コストを下げることは別の目的であり、分けて設計・評価する**

---

## 3. 現在の設計アーキテクチャ(v8時点)

### 3-1. 全体の層構造

```
Layer 0: 資料の目的分類層(図面/仕様書/仕上げ表/イメージ写真/過去事例を区別)
Layer 1: 知覚層(画像を複数アプローチで読む。軸内で統合してから軸間照合へ)
Layer 2: 絶対ルール層(幾何学的公理・建築基準法)
Layer 3: 順序推論層(空間包含順序・工程順序)
Layer 4: 施工慣習層(過去実績からの逆推論。恒久的に補助専用)
Layer 5: 条件layer(工期・特殊条件による補正。人の感覚を起点に、データとして蓄積)
Layer 6: 統合・アービトレーション層(軸内統合→軸間の立体照合→多軸レンジ収束)
Layer 7: エスカレーション層(3段階確信度階層+キラークエスチョンエンジン)
Layer 8: 人間補正層(条件補正の管理画面)
Layer 9: フィードバックループ(継続学習・事後検証)
```

### 3-2. 軸カタログ(大元データ源による整理)

| 軸 | 独立性 | ステータス |
|---|---|---|
| 画像軸 | 基準 | 検証済み。単体では劣化に弱い |
| 文章軸 | 画像から独立 | 検証済み。誤り率は低いがゼロではない |
| 絶対ルール軸 | 条件付き(材料が画像由来なら非独立) | 材料の出どころを都度確認する運用 |
| 整合性軸 | 条件付き(同上) | 同上 |
| 過去実績軸 | 画像から独立 | **恒久的に補助専用**(他の軸の答えを排除する権限を持たせない) |
| 空間認識軸 | 一部条件付き(平面図を共有) | 有効性は確認済みだが、現実的な劣化を伴う再検証が未了 |
| 目的逆算軸 | 画像から独立 | 単純な上限/下限補正では実用不足。撤去/残置/新設の内訳分解が必要 |
| 現地・現物確認軸 | 画像から独立 | 未実装。実案件パイロット時に検討 |
| 業界一般統計軸 | 画像から独立 | 未実装。信頼できる統計源の選定が前提 |

### 3-3. 統合ロジックの最終形

1. **軸内統合**:同じ情報源(例:1枚の画像)の複数手法は、まず1つの軸としてまとめる
2. **軸間の立体照合**:大元データ源が独立した軸同士だけを、初めて別方向の確認として扱う
3. **多軸レンジ収束**:各軸は単一値ではなく「あり得る範囲+根拠」を出し、**強い軸(実測校正済み・十分なサンプル・分布内)のみでハードな積集合を計算**する。弱い軸は参考情報にとどめる
4. **3段階確信度階層**:
   - 階層1(自動確定):強い軸が2つ以上、独立に一致(連続量では許容誤差内での一致)
   - 階層2(仮採用+抜き取り監査):強い軸1つ+弱い軸が同方向を支持
   - 階層3(要確認):それ以外
5. **キラークエスチョンエンジン**:依存関係(「合計=内訳の和」等)がある要素群について、1問確認すれば他の要素が芋づる式に決まる質問を優先的に選び、必要な分だけ繰り返す。**依存関係が明確な場合にのみ適用し、独立した合算(配管の区間長など)には無理に適用しない**

## 4. トライアル1〜10の結果サマリー

| # | 検証内容 | 結果・教訓 |
|---|---|---|
| 1 | 複数の無料積算AI/研究デモの単純統合 | カテゴリ表記の不一致、全不一致時のルール欠如が判明。正規化とエスカレーションを追加 |
| 2 | 正解既知の要素で技術系統の異なる3手法を統合 | 技術系統が違っても、同じ画像という同一情報源では失敗が相関し、単純多数決が単体最良手法(83.3%)を下回った(33.3%) |
| 3 | 画像軸×文章軸の独立2軸照合 | 軸内統合と軸間照合を分離する設計思想の原型ができた |
| 4 | 多軸レンジの積集合(交点収束) | 質の低い軸(サンプル2件の過去実績軸)が正解を誤って排除。強い/弱い軸の区別が必要と判明 |
| 5 | 強い/弱い軸の分離ロジックの適用 | 正解含有率75%→100%に改善したが、単一値自動確定が5件→0件に。安全性と自動化のトレードオフが判明 |
| 6 | 空間認識軸(複数投影図)+3段階確信度階層 | 自動化率33.3%→83.3%に回復。ただし投影図が理想化されすぎており、効果は楽観的な上限の可能性 |
| 7 | キラークエスチョンエンジン(理想条件) | 19要素を理論下限と一致する6問で解決。質問順の選び方に明確な価値があることを実証 |
| 8 | キラークエスチョン+誤り混入(現実条件) | 階層なしでは精度100%→78.9%に悪化。3段階階層とセットで100%に回復(コストは6問→8問) |
| 9 | データ源(誤り率)考慮の質問選定 | 精度ではなく監査コストを44%削減。ただし統計的検証(複数シード)が必要な単発結果。**【2026-09-21 追記】この44%は根拠としての引用を停止した。本リポジトリではルールがバグで未発火であり、修復後も未検証。v8 4-3節ルール2・10章20項** |
| 10 | 異なる数量パターン(長さ・面積・タイプ別個数)での汎用性検証 | v8設計は汎用的に機能。ただしキラークエスチョンは「依存関係がある問題」限定で効く。連続量は許容誤差ベースの判定に切り替える必要 |

## 7. 次回、着手すべき優先順位(テストマトリクス方針)

条件(対象・規模・回数・深さ)は、1回のトライアルで1軸だけ変えるのが原則です。

1. **トライアル11の結果を確認する**(最優先。結果待ち中)
2. 空間認識軸を、投影図にも現実的な劣化を加えた条件で再検証する
3. 目的逆算軸を、撤去/残置/新設の内訳に分解して再設計する
4. 格子に整列していない、傾き・曲線を含む、より現実的な図面で、トライアル10の改善率が再現するかを検証する
5. タイプ分類の内訳の取り違えを検出する、合計制約以外の独立した監査手法を設計する
6. テストマトリクスの「規模」(数十〜百要素規模)、「深さ」(3階層以上の依存関係)の軸を順に検証する
7. **最後に、「そもそも、この案件にルール・軸の前提が当てはまるか」を確認する、そもそも論の質問(ルール診断型のキラークエスチョン)を検証する**(意図的に最後に回している課題)
