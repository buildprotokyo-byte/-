# K-30 ②線の太さ — 報告

作成: 2026年9月24日。基準は `docs/k30_line_width_criteria.md`(**測る前にコミット済み**、
`8fdc851`)。**結果を見てから線を動かしていない。**
道具は `benchmarks/measure_k30_line_width.py`(件数と割合と太さの値だけを出す)。

## 先に結論

| 線 | 中身 | 決めた値 | 測った値 | |
|---|---|---:|---:|---|
| 線 A | 枠が取れたページのうち、太さの山が 2 つ以上あるページ | 8 割 | **20 / 24 = 83.3%** | **○** |
| 線 B | 太い山の線のほうが、細い山より輪になる割合が高い | 高いこと | **測れていない** | **—** |

**線 A は成り立った。この図面は太さで描き分けている。**
**線 B は、成り立たなかったのではなく、測れていない**(下の 2 節)。

## 1. いまの台帳が捨てているものは、PDF の中にある

**`get_drawings()` は線の太さを返している。**いまの台帳
(`axes/image_axis/candidate_ledger.py`)は、向きと長さだけを記録して**太さを捨てている。**

| | 件数 |
|---|---:|
| 34 ページの線(l・re・qu・c)の総数 | 311,168 |
| **太さが記録されていない線** | **17,939(5.8%)** |

**太さが取れないページがあるのではなく、取れるのに記録していない。**
構えの 5 番でいう **②決まりはあるが実装が無い**である。

## 2. 線 B は測れていない(**③実装はあるが動かなかった**)

輪になっているかを数える部品が、**直線(`l`)と矩形(`re`)しか辿っていない。**
**曲線(`c`)を辿っていない。**

そして**いちばん太い山は、ほとんどのページで曲線でできていた。**
その結果、20 ページのうち **18 ページで「太い山の輪」が 0 / 0** になった。
集計に出た数字(太い山 60.3% / 細い山 71.0%)は、**残り 2 ページの 63 本だけで作られている。**

**だから「太い線は輪になりにくい」とは書かない。数えていないだけである。**

## 3. 山の数え方が緩かった(**成り立った側の但し書き**)

基準に「太さを昇順に並べ、隣との比が 1.5 倍以上のところで切る」と先に書いた。
**この数え方は、太さの種類だけを見て本数を見ない。**だから

- **1 本しかない太さが、1 つの山として数えられる**(平面図のページで実際に起きている。
  山ごとの本数が `[13905, 185, 1, 721]` のような形になる)
- **いちばん太い山といちばん細い山の比が 68.75 倍**になるページが多い。
  **JIS の 1:2:4 とはまるで違う。**いちばん太い山は極太線ではなく、別のもの
  (塗りや曲線)である可能性が高い。

**線 A の「○」は、この緩い数え方での「○」である。**
**「この図面は JIS の 1:2:4 で描き分けている」とは書けない。**
言えるのは「**太さの値が 1 種類ではない**」までである。

## 4. ここで測るのをやめた理由(おーちゃんの 14:57・14:59)

**おーちゃんから、個別の決まりを 1 つずつ測って覚える形そのものを止められた。**

> 表題は線の外側にあるとか内側にあるとか、そういうふうに覚えてしまうと、
> 例外が出た時にそれを弾いてしまいますから、そういう個別のルールではなく、
> **基本的に図面の読み方っていうものが最優先されるべきです。**

**この報告も、その形に片足を突っ込んでいた。**「この案件の太さの分布はこうだった」を
積み上げても、**何を見ればよいかは決まらない。**

**残すのは次の 1 点だけである。**

> **線の太さは PDF に入っているのに、台帳が捨てている。**
> **平面図は床から 1〜1.5m で切った断面なので、切られている壁・柱・建具枠は太く、
> 切られていない家具・設備・寸法線は細い。だから室の輪郭を取るなら太い線だけを見る。**
> **いまは全部の線を同じに扱っているので、そもそも見分けられない。**

**次は `docs/reading_stance.md` の 0 節(読む順番)から入る。**
