# K-26 1番・4番: 台帳が「小さすぎる点」として捨てた 96,816 件の中身

作成: 2026年9月24日。対象は P011 匿名化v2(34 ページ)。
道具は `benchmarks/measure_ledger_specks.py`、数は `docs/k26_ledger_specks_result.json`。
**出しているのは件数・ページ番号・大きさだけ。**目で見るために切り出した画像は
図面そのものなので、リポジトリには入れていない。1 回だけ走らせた(台帳は K-23 で
3 回とも同じ数と確かめてある)。

## 先に結論

**捨てた点の 59%(56,724 件)は、1 本ずつは点でも、端点でつなぐと記号の輪や
曲線になる部品だった。**この図面は円や曲線を**細かい直線に割って、1 本ずつ
別の図形として**描いている。台帳は図形を 1 本ずつ大きさで判定するので、
**円を作っている部品を全部「点の汚れ」として捨てていた。**
つなぐと 672 個の形になり、どれも小輪郭の大きさ(20 単位以下)である。

**凡例の図形だけの 19 行のうち、台帳の候補が升目に 1 つも無かった 4 行
(K-24 で原因を調べていなかった行)は、4 行ともこれが原因だった。**
4 行とも、捨てた点をつなぐと升目の中に形ができる。

**区切りの値を変えても直らない。**半分にしても捨てる数は 8% しか減らない。
捨てた点の 84% は大きさが 0.2 単位未満で、区切りの値の問題ではなく、
**「1 本のパス = 1 つの候補」と数える単位の問題**である。

### 目で見たもの

- **区切りのすぐ下(捨てた側)の 10 件**: 19〜21 ページの**文字の画の一部**。
  この 3 ページは文字のデータが無く、文字が線で描かれている。その短い画が捨てられている。
- **区切りのすぐ上(残した側)の 10 件**: 7・8・23・24・33 ページの**記号の中の小さな曲線**
  (放射状の線がある丸い記号の一部)。
- **種類ごとに 5 件ずつ(無作為、種 20260924)**:
  大きさ 0 の点は点線・破線の端や、点の模様の中。短い線は破線の途中や記号の中心・線の交点。
  つないでも区切り未満のものは記号の中の小さな部分と、**点線の点**。
  つなぐと形になるものは**破線の曲線の一部**と器具の細部。
- **汚れは 1 件も無かった。**この 34 ページで点を捨てたのはベクターのページだけで、
  スキャンの 18 ページの捨てた点は 0 件である。ベクターの図面に紙の汚れは無い。
- **ハッチングの点**: 見た範囲には無かった(ハッチングは長い線で描かれていて、点ではない)。

## 4. K-20 の形の照合が落ちた原因か(K-26 5番)

**違う。**K-20 の形の重なり(`benchmarks/measure_legend_shape_overlap.py`)は、
ページを画素に描いて墨のある所で比べていた。**台帳を読んでおらず、点を捨てる処理を
通っていない。**円の部品を捨てていたことは、あの照合が落ちた原因ではない。

## 次にやれること(やっていない)

**捨てる前に、端点が同じ細かい図形をつないで 1 つの候補にする。**つないだ数は
捨てる理由と同じように記録する(「つないだ」)。そのあとで大きさを判定する。
これで円の部品は小輪郭として台帳に入る(この図面で 672 個)。
**名前が付く件数は変わらない**(照合は今も台帳を読んでいない。K-24)。

### 一本通す作業から台帳を呼ぶとき(#126・#128 の形)

```python
from axes.image_axis.candidate_ledger import build_ledger, LedgerCache

ledger = build_ledger(pdf_path)                 # 全ページ。pages=[0, 5] で一部だけ
ledger = build_ledger(pdf_path, cache=LedgerCache(dir))  # ページごとのキャッシュ(SHA-256)
ledger.gate_summary()                            # {"passed": .., "needs_review": .., "blocked": ..}
for page in ledger.pages:                        # PageLedger
    page.gate.status, page.gate.reasons          # passed / needs_review / blocked と理由
    page.title                                   # 表題欄(名称・図番・縮尺・改訂日。読めなければ None)
    page.title_conflicts                         # 表題欄と図面リストの食い違い(両方の値)
    page.lines, page.regions, page.small         # 線・閉領域・小輪郭(0〜1000、意味は当てていない)
    page.counts, page.dropped                    # 見つけた数・残した数・上限、捨てた理由ごとの数
```

- **候補の数は数量ではない**(K-23)。台帳は本番の経路にも判定にも繋いでいない
  (`tests/test_candidate_ledger.py` に、本番のコードが読み込んでいないことを確かめる試験がある)。
- **円や曲線を細かい線に割って描いた図面では、その部品が台帳に入っていない**(この報告の 1 節)。
