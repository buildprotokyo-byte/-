# 61周目の基準: **問いの経路は、本番経路から呼ばれているか**

**測る前にコミットする。結果を見てから基準は変えない。**

## 1. なぜこれを測るか

60 周目までで、問いの選び方・答えの扱いを 3 件変えた(PR #87)。
**だが「変えた」ことと「本番で効く」ことは別である**
(取り決め①、落とし穴「実装済みの記録を信じない。本番経路から呼ばれているかまで確認する」)。

PR #87 の本文には **「いまの本番経路では全部 C になる」** と書いた。
**これはコードを読んだだけの見立てで、実測していない。**
**自分の書いた但し書きを、自分で測る。**

## 2. 測るもの

本番の入口(`intake.drawing_intake.read_drawing` と、そこから呼ばれる
`arbitration.inference_orchestrator`)を、合成案件と実図面 v2 で 1 回ずつ走らせ、
**呼び出しを数える。**

| 記号 | 何を数えるか | 予想 |
|---|---|---|
| M1 | `KillerQuestionEngine` の生成・`next_question`・`run` の呼び出し回数 | **0** |
| M2 | `killer_question.firewall_bridge.add_target_to_joint_solver` の呼び出し回数 | **0** |
| M3 | `independent_sources` に 0 以外が渡った `add_variable` の件数 | **0** |

**数え方は呼び出しの記録(トレース)であって、コードを読んだ印象ではない。**

## 3. 対照(これが通らなければ結論を出さない)

**C1: 同じ数え方で、問いの経路を現に使っているベンチマーク
(`benchmarks/run_killer_question_eval.py` の星形シナリオ)を走らせ、
M1 が 1 以上になること。**

C1 が 0 なら、**数え方が何も拾えない仕掛けになっている**ということなので、
**本測定の 0 は意味を持たない。その場合は結論を出さずに止める**
(59 周目と同じ扱い)。

## 4. 判定の分岐(先に決める)

- **M1 = 0 かつ M2 = 0**(かつ C1 通過)
  → **「PR #87 の 3 件は、本番経路では 1 件も効かない」と結論する。**
  PR の但し書きは実測で裏づけられたことになる。
  **入口を作るかどうかは、こちらでは決めない。判断待ちの札にする**(取り決め③・⑨)。
- **M1 > 0**
  → **予想が外れ。** どこから呼ばれているかを名指しし、
  そこで階級(A/B/C)がどう付くかを続けて測る。
- **M3 > 0**
  → **予想が外れ。** どの対象が申告しているかを名指しし、PR の但し書きを訂正する。

## 5. この測定で分からないこと

- **入口を作ったときに問いの質が上がるか**は測らない(入口が無いため)。
- **実図面は v2 の 1 冊だけ。** 1 冊で出た数は 1 冊の話である。
- 実図面のパスは引数で渡す。**図面の中身は報告にも記憶にも書かない。**
