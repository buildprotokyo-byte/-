## **原因 — 名前が食い違っている。人が何を入れても入らない**

**コードを読んで確かめた。**

| | 名前 |
|---|---|
| `app.py` の `FINISH_PART_QUANTITY` が**巾木のために探す** | **`周長`** |
| `estimating/from_room_dimensions.py` が**実際に作る** | **`室の周長`**(`KIND_PERIMETER`) |

**引き当ては永久に外れる。**

実際に動かして確かめた。人の寸法 1 室から作られる対象は
`床面積::…` / **`室の周長::…`** / `内壁面積::…` の 3 つで、
**`周長::…` は 1 つも作られない。**

**床・壁・天井の 3 つは名前が合っている**(`床面積` / `内壁面積`)。
**食い違っているのは巾木だけである。**

### **作る側の `gaps` では、この食い違いは拾えない**

`from_room_dimensions` は「**入っていない欄を既定値で埋めない。なぜ作らなかったかを
`gaps` に並べる**」と約束しており、**その約束は守られている。**
**ただし今回、作る側は 3 種類とも作れている。だから `gaps` は空である。**

**落ちているのは作る側ではなく、探す側の名前である。**
**「作れなかった理由を残す」仕掛けでは、この種の食い違いは原理的に拾えない。**
